# 🌙 dream: a SOME block nested in a SOME block collapses the outer retry to one attempt

kind: fix · owner: ehmpathy/test-fns · caught 2026-10-06, in the route for #71

## .the cue that fired

peer review i005 (enroll-impl-behavior-intent, point 3) traced the context stack.

## .the gap, precisely

```js
given.repeatably({ attempts: 3, criteria: 'SOME' })('outer', () => {
  when.repeatably({ attempts: 3, criteria: 'SOME' })('inner', () => {
    then('it holds', () => { ... });
  });
});
```

- each `then` captures `getCurrentRepeatableContext()` at registration; the inner block's
  `setCurrentRepeatableContext` shadows the outer state
- so a failure marks only the inner state's `thisAttemptFailed`
- the outer `afterAll` (`setAttemptTracked` → `setAttemptPassed`) sees no failure and marks the
  outer block passed after attempt 1
- ⇒ outer attempts 2..N always skip. outer `attempts: 3` behaves as `attempts: 1`
- no false green: the inner block's final attempt still reds the file

## .the shape of the fix

carry a stack of SOME states rather than one current state. on a test failure, mark
`thisAttemptFailed` on every SOME state in the stack, so each outer `afterAll` sees it. clamp
with an acceptance case: inner fails on all 3 of outer attempt 1, passes on outer attempt 2 →
file green, 2 outer attempts driven.

## .why it is not done in this round

safe: no — it changes how often consumer bodies run under any nest of repeatable blocks.
clean: no — the context stack is read by every repeatable block and `usePrep`. prior to #71 on
`main`, and out of the wish's scope (fulcrum F17).
