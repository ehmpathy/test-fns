# 🌙 dream: a timed-out jest attempt's ghost can leak a snapshot mismatch into the next attempt

kind: fix · owner: ehmpathy/test-fns · caught 2026-10-06, in the route for #71

## .the cue that fired

peer review i007 (enroll-impl-arch-defects, nitpick) traced the overrun race against the
suppressed-tally rollback.

## .the gap, precisely

- under SOME, `getOneAttemptOutcome` races the body against the budget; on overrun it returns,
  and the body runs on (js cannot cancel a promise)
- on jest, a `toMatchSnapshot()` mismatch does not throw; it appends to the file-global
  `snapshotState` suppressed list
- if the ghost body's matcher fires while the NEXT attempt is in flight, its append lands
  after that attempt's `tallyBefore`, so `getAllSuppressedErrorsSince` counts it as the next
  attempt's own mismatch — a clean attempt can be withheld
- if it fires after the block ends, it adds to jest's end-of-file `Snapshots: N failed` with no
  attempt to own it

needs: jest, SOME, an overrun that lands before the body's own matcher call. no test builds it.

## .the shape of the fix

tag each attempt's matcher calls with an attempt token (e.g. snapshot of `currentTestName` at
call time, already pointed at the stripped name per attempt — compare against a per-attempt
nonce stored on `expect.getState()`), and drop any suppressed entry whose token is not the
current attempt's. or: after an overrun, mark the attempt's token dead, and filter appends
whose stack/test name carries it. a cancellable body is the root fix and js has none.

## .why it is not done in this round

safe: no — a filter over jest's suppressed list changes which mismatches fail a file.
clean: no — it needs a per-call attribution jest does not expose. the timeout ghost is already
named in the readme ("keep a retried body idempotent"); this sharpens it. fulcrum F26.
