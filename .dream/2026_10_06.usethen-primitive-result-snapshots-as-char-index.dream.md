# 🌙 dream: a `useThen` that returns a primitive should fail loud, not snapshot a char-indexed object

kind: fix · owner: ehmpathy/test-fns · caught 2026-10-06, in the route for #71

## .the cue that fired

the 5.3 verification walkthrough wrote a plain-js consumer whose `useThen` returned a string. the
baseline snapshot came out as `{ "0": "w", "1": "a", … }`, and a mismatch diff read char by char.

## .the gap, precisely

- `useThen` is typed `<T extends Record<string, any>>`, so a typescript consumer cannot return a
  primitive. a plain-js consumer (or one with `any`) can, and no error tells them
- `createUseThenProxy` returns `new Proxy(drawer, …)` and fills `drawer` via
  `Object.assign(drawer, toolbox)`; for a string, that copies one key per character
- so `expect(result).toMatchSnapshot()` writes a char-indexed object, and `result === 'x'` is
  always false — a silent, puzzling shape, not an error
- prior to #71 on `main` (`src/domain.operations/useThen.ts`)

## .the shape of the fix

in the `then` body of `createUseThenProxy`, after `toolbox = await input.fn()`, fail fast when
`toolbox` is not a non-null object: a `ConstraintError` that names the description and says to
wrap the value (`return { value }`). clamp it with a jest + vitest case that returns a string and
asserts the error text. the readme's `useThen` section can name the object-only contract.

## .why it is not done in this round

safe: no — it turns a silent pass into a red for any plain-js consumer who returns a primitive
today, a behavior change outside #71's retry semantics. clean: yes in code, but it deserves its own
release note.
