# case=12 — the teardown never runs, and the NEXT run says so

> cell 8b · `hooks=jest` · `termination=preempted` · `solo` · `reclaim`
> **feel** ⚡ **sharp** · **care** critipath — a green suite that reclaims not one dir and says no word
>
> **who** — kai, a consumer whose run was cut short by a signal, an OOM, or a `globalSetup` throw
> **came for** — a green suite, with no thought spared for temp dirs

## the gap this case closes

`case=10` builds a runtime invariant for the broken-chain cell, and it is a good one. but it lives
**in the teardown**:

```
 an entry EXISTS that is FRESH and carries NO run id
 dirs matched by OUR id  ==  0
 ⇒ the chain is broken. fail loud.
```

read the precondition that hides in plain sight: **the teardown must run for the invariant to
fire.** so it catches *"the teardown ran and matched zero"* and is structurally blind to
*"the teardown never ran."*

that second case is not hypothetical. a `SIGKILL` from a CI hard timeout, a `SIGINT` from a human's
`^C`, an OOM kill, or a throw inside `globalSetup` each end the process with the teardown unrun:

- every test that ran passes ✅
- the teardown does not run
- the invariant does not fire, because the code that holds it never executed
- the leak resumes, silently, under a green suite

that is **case=10's exact failure mode, reached by a path case=10's guard cannot see** — and the
first victim is `test-fns` itself, while the library advertises the fix.

> **`--forceExit` is NOT a cause of this cell.** the yield's **A6** settles it from installed
> source: `@jest/core` **awaits** `globalTeardown` at `build/index.js:3464`, and the flag's
> `exit(code)` fires afterward at `jest-cli:719`. this repo's three jest commands pass the flag
> (`package.json:53,56,59`) and none of them loses a reclaim to it.
>
> the flag does impose a **separate** constraint, and A6 carries it: `exit(code)` kills the process
> the instant the teardown's promise resolves, so **the reclaim must be `await`ed inside the
> teardown, never fire-and-forget**. a fire-and-forget reclaim is reaped mid-`rmSync` — a silent
> partial delete, which is [case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)'s
> defect rather than this one's.
>
> an arrears check that named the flag would send an adopter to audit a config that was never at
> fault. **it must name the marker and the residue, and leave the cause to the human.**

## why a clamp was not enough

execution owes a clamp on this cell: a child run killed by `SIGKILL` mid-run, counted before and
after. that is necessary and it is not sufficient:

| | a clamp (a test in our repo) | a fail-safe (a runtime guard on every machine) |
|---|---|---|
| catches it on the jest version we had the day we wrote it | ✅ | ✅ |
| catches it on the jest version a consumer runs three years out | ❌ | ✅ |
| catches it when a consumer's suite starts to take a `^C` mid-run | ❌ | ✅ |
| catches it when a consumer's CI adds a hard process timeout | ❌ | ✅ |

`rule.require.experience-coverage` grades *"a sharp critipath shown unhandled (no fail-safe)"* a
blocker. an owed clamp is not a fail-safe — it protects **us**, never the consumer.

## the fix — move the detect from the teardown to the NEXT run's setup

the teardown cannot report its own absence. a later run can.

```
   run N                                  run N+1
   ─────                                  ───────
   globalSetup   mints id, writes a        globalSetup   reads the marker of every
                 marker for this run                     PRIOR run in this scope
        ↓                                       ↓
   the tests     make dirs stamped R      the arrears   a prior run has a marker,
                                          check         still owns dirs, and its
        ↓                                                process is long gone
   globalTeardown  reclaims R,                  ↓
                   CLEARS the marker       ⚡ it never reclaimed. say so.
   ✋ pre-empted — the marker survives
```

the marker is the whole mechanism: a teardown that runs **clears** it; a teardown that never runs
**leaves it**. so an uncleared marker whose run is over is a positive, unambiguous record of a
teardown that did not fire — the one fact the teardown could never report about itself.

> ⚠️ **the marker must be a FILE, never a directory, and its name must sit outside the fixture
> pattern.** the marker is a new entry in a dir that **four** mechanisms iterate. as a directory it
> would fail the age gate's name parse and be preserved forever as class **E** — so
> [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md)'s
> *"could not read"* count would emit one line of permanent noise **per run**, and the report meant
> to make an invisible population visible would be the first to be muted. `pruneStale.ts:30`
> already filters `entry.isDirectory()`, so a **file** is skipped by construction rather than by a
> rule someone must remember.

### 🔴 and the marker must be REMOVED, not merely closed

the marker is a **file** so the age gate skips it. read that back as a lifecycle question and the
irony is exact:

> **`pruneStale.ts:30` filters `entry.isDirectory()`. so the age gate reclaims no file, ever.**
> a marker left on disk after its run is a **permanent** entry — and this mechanism writes one
> **per run**.

that is an unbounded accrual of small files in the contained dir, forever, added by the very
behavior whose wish opens *"no temp dir survives the run that made it."* **the file choice buys a
leak of its own** — it settles one collision by a move of the marker into the one entry class no
reclaim in this design touches.

**the fix, and why `closed` must not be a stored state:**

| final state | what the teardown does | why |
|---|---|---|
| **closed** (reclaimed) | **delete the marker** | its whole purpose is discharged; a stored `closed` is pure accrual |
| **held** | keep it — the age gate reclaims it with the dirs it describes | it still explains dirs that are still there |
| **partial** (began, met a stuck dir, was pre-empted) | it survives, and carries the residue path + `errno` | it explains dirs that are still there **and** names why |
| **open** (never reached the teardown) | it survives by definition | that is the signal |

so **absence is `closed`**, and only `open`, `partial` and `held` markers persist — each bounded by
the same age gate that bounds the dirs they describe.

### 🔴 the marker sweep is a REQUIREMENT, not a note

**and the age gate must reclaim aged marker files.** an `open` marker whose dirs the gate has
already taken explains no residue at all; if the gate cannot remove it (files are filtered today),
an interrupted run leaves one immortal file each. `pruneStale`'s `isDirectory()` filter is correct
for **fixtures** and wrong for **markers**.

⚠️ **filed as a mere note to execution, this leaks: the guard against a leak LEAKS.** trace every
party that can remove a marker:

| a marker from… | who clears it |
|---|---|
| a run whose teardown fired | its own teardown ✅ |
| a run that was **held** | its own teardown, settled as `held` ✅ |
| a run pre-empted **before** its teardown began — a signal, an OOM, a `globalSetup` throw | ❌ **no one** |
| a run pre-empted **mid-reclaim**, settled `partial` (cell 25) | ❌ **no one** |
| a run killed by `SIGKILL` | ❌ **no one** |
| the age gate | ❌ `pruneStale.ts:30` filters `entry.isDirectory()` — a file is never a candidate |

**rows 3, 4 and 5 are the exact population this case exists for.** so this mechanism accumulates one
small file per pre-empted run, **forever** — which fails the vision's own honest restatement of the acceptance
(*"zero new entries of any kind, once a run's marker is discharged"*) for precisely the runs it was
added to handle. small per occurrence, bounded in **rate** rather than in **total** — the identical
shape as the defect under repair.

```
   the age gate today:   readdir → filter isDirectory() → parse → age → rm
   the age gate needed:  readdir → TWO passes
                           ├─ dirs    → parse → age → rm        (extant)
                           └─ MARKERS → age → rm                (new, EXPLICIT)
```

the marker sweep is **simpler** than the dir sweep — a marker carries its own run id and timestamp
by construction, so it needs no name parse and cannot hit [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md)'s
hazard. two constraints:

- **exclude `readme.md` and `.gitignore`** — the contained dir holds both by construction
  (`genIsolatedTempInfra.ts:61-70`), and the `isDirectory()` filter excludes them for free where a
  marker sweep does not
- **age-bounded, never state-bounded** — a marker left `open` is this case's only evidence, so an
  eager sweep of open markers would delete the input the arrears check reads. sweep markers older
  than the age window, by which point their arrears have long since been reported

**and no, the marker should not become a directory instead.** a dir marker is parsed by
`computeStaleDirs`, fails the parse, and is preserved **forever** as class E — which trades a leak a
five-line sweep fixes for a leak with *no* reclaim at all, plus a line of permanent noise per run in
case=14's report. **the defect was never the file; it was the absent sweep.**

### 🔴 the marker needs MORE than two states

a two-state marker (`written` / `cleared`) **false-positives on two legitimate states**, both
surfaced by a pairwise check of this mechanism against every other one that reads `process.env` or
the config:

| state | what the run did | two-state verdict | truth |
|---|---|---|---|
| the **hold** hatch (`TEST_FNS_KEEP`) | the teardown ran and **chose** to keep | ⛔ "a teardown never fired" | it fired; it held on purpose |
| **half-wired** — `globalSetup` only | the mint ran; no teardown was ever configured | ⛔ "a signal pre-empted your teardown" | the consumer wired one key of two |

both would emit a loud, confident, **wrong** message on every subsequent run — which is precisely
the defect [case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md) found in
`case=10`'s guard, reproduced inside the mechanism built to fix it.

**the half-wired state is not hypothetical, and it is jest-only.** jest needs **two** keys
(`globalSetup` + `globalTeardown`); vitest needs **one** module that exports both. so a jest
consumer who copies the first line of the adoption snippet and misses the second lands here — and
the yield already named that asymmetry as *awkward*. this is the cost of the awkwardness, made
concrete.

**the fix — the marker records an outcome, not merely a presence:**

```
 absent        the mint never ran         ⇒ unhooked         → case=7's notice
 open          the teardown never ran     ⇒ the real arrears → this case
 closed        the teardown reclaimed     ⇒ healthy          → silence
 held          the teardown chose to keep ⇒ the hatch        → case=6's message, not this one
```

⚠️ **the settled set is `open` / `partial` / `closed` / `held`**, plus `absent` for a marker that was
never written. the next section derives `partial` from the cell that demands it.

and the arrears check must **read the config it can see** before it names a cause: if
`globalTeardown` is absent from the runner's config, the cause is *half-wired*, never *a signal*.

### 🔴 `partial` — the fourth state

the resource-state axis surfaces cell **25**, `unremovable × preempted`, and it is the one outcome a
three-state marker **cannot express**:

```
   the teardown STARTS                    → it is not `open`
   it meets an EACCES on one dir          → case=9 says: report it, loud, exit 0
   a signal tears it down mid-report      → it never reaches `closed`
   ──────────────────────────────────────
   under three states the marker reads `open`, and the NEXT run reports
   "a teardown never ran" — which sends the adopter to audit a config
   that was never at fault. the cause was a file mode.
```

**the constraint that falls out, and it is a real one:** the marker settles to `partial` at the
**moment the reclaim begins**, never at its end. a teardown torn down mid-flight gets no second
chance to write, so a state written only on completion is a state that never records a pre-empt.
the sequence is `open → partial → {closed | held}`, and each transition is written **before** the
work it describes rather than after.

`partial` also carries what `open` cannot: the **residue path and its `errno`**, captured the moment
`rmSync` threw. that is `case=9`'s report, persisted — so the human still receives it on the next
run even though the run that discovered it never printed a line.

### why this is sound where a liveness probe is not

[case=4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md) rejects *"reap any entry
whose owner pid is dead"* as unsound — pid reuse, container boundaries, reboots. the arrears check
does **not** revive that shape, for two reasons:

1. **it reports; it does not reap.** an unsound claim that only prints costs a false line of
   output. an unsound claim that deletes costs a human's work. the two live on opposite sides of
   the leak-vs-loss line this whole behavior is built around.
2. **it asks the liveness question directly — and it is entitled to.** the marker records the run's
   **pid and start time**; the check names a marker as arrears when its state is `open` or
   `partial` **and that process is gone.** a live peer answers at any suite duration; a pre-empted
   run's process is dead the instant it is torn down.

**the licence is point 1, and only point 1.** case=4 forbids a liveness probe that decides what to
**delete**; a probe that decides what to **report** costs a false line of output at worst. *a
mechanism's constraints are set by its powers* — the age gate deletes, so it may use only facts it
cannot be wrong about; this check reports, so it may use a fact that is occasionally unavailable.

### 🔴 the window alone cannot do this

a **liveness window** cannot carry this check — *"it fires only for markers older than a run could
plausibly still be live"* names a threshold that **does not exist**, and
[case=11](./1.vision.experience.case=11.a-friday-afternoon.md)'s `[t6]` is where it breaks: a
pre-empted run and a live peer sit **twelve minutes and two minutes** apart, so every threshold
either names both or names neither.

the two claims that pull it apart are both this vision's own:

| the claim | what it demands of a window |
|---|---|
| the yield: a casualty in `unit:jest` is named by `unit:vitest` **seconds later** | **short** — shorter than the gap between two invocations |
| `[t5]` below: a **live peer's** marker raises no alarm | **long** — longer than the longest suite |

a suite that runs 8 minutes and a next invocation 2 seconds later leave **no** correct value. this
is not a calibration problem, and to grant the quantity as merely open — *"it does not sink the
case"* — is true of the harm and false of the mechanism. **an open quantity that no value can
satisfy is not an open question; it is an absent mechanism.**

**the window survives as the FALLBACK.** where the liveness question cannot be answered — a marker
from another machine on a shared mount, a platform that will not let us query — fall back to age
and stay silent until it elapses. **fail toward silence, never toward a false accusation**, since
the cost of a wrong name is an adopter who audits a config that was never at fault, which is
precisely cell 25's harm.

so the check inherits none of the probe's danger and all of its detect power — because it sits on
the harmless side of the same leak-vs-loss asymmetry the rest of the design uses.

## what it costs, and the one it must not break

[case=1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md) asserts that a healthy run
**says no word** — silence is the success signal. an arrears check that chattered on every run
would break that, and a notice every consumer mutes is a notice that protects nobody.

so the check is **conditional by construction**: it speaks only when a marker is unsettled AND its
run's process is gone. a repo whose teardowns all fire sees this message **never**.

### 🔴 but "conditional" is not a bound — the check must speak ONCE per marker

this case's *"for free"* claim below and
[case=11](./1.vision.experience.case=11.a-friday-afternoon.md)'s friday contradict on this exact
mechanism unless the report is bounded. a `kill -9`'d run leaves an `open` marker with a dead
process, so **every** later run in that scope satisfies the predicate above. case=11's run A dies at
14:07 and its residue sits for **eleven days** — under the predicate as stated, B, C, D, D2, C2 and
every run between them all name it, and case=11's *"D said no word"* is false.

**the condition is real and it is not a bound.** it holds continuously for as long as the residue
does — which is longest exactly when the leak is worst. so the notice-every-consumer-mutes hazard
this section opens with is not avoided by the condition; it is *produced* by it.

the marker gains one nullable field, orthogonal to `state`:

```
   a marker is ARREARS when
     state ∈ { open, partial }      the teardown did not settle it
     AND the process is GONE        pid+startedAt no longer names a live process
     AND reportedAt is null         no run has said this out loud yet
```

and the check **stamps `reportedAt`** on every marker it names. one residue, one report, by the
first run whose setup sees it. every run after it is silent about that marker, while the marker
itself survives — it still explains the dirs, and it is swept by age alongside them.

three properties earn it:

1. **it keeps the state machine intact.** `reportedAt` is a field, never a fifth state, so
   `open → partial → {closed | held}` is unchanged and every `.state` assertion in this file still
   holds. that is the dividend of the by-field discipline.
2. **it does not cross the reports-never-reaps line.** the check writes to a marker **we** wrote;
   it removes no dir and alters no entry a human owns. `[t3]`'s fourth `then` is untouched.
3. **a duplicate report is benign.** two runs that start at once may both name one marker — the
   cost is a repeated line, never a lost one. it fails toward a second report, never toward
   silence, which is the correct direction for a mechanism whose whole purpose is to end silence.

## the narrative

kai runs the suite. CI's 10-minute hard timeout fires at minute 10, and the runner takes a
`SIGKILL` two test files from the end.

```
$ npm run test:integration
  Tests: 104 passed, 104 total
```

green, as far as the log got. 432 dirs on disk.

kai runs it again after lunch:

```
$ npm run test:integration
  Tests: 118 passed, 118 total

⛈️  test-fns found 432 temp dirs from a prior run whose teardown never ran

   prior run id:   r7f3a91c2   (started 3h ago, marker never settled)
   its process:    pid 48213 — gone
   dirs it owns:   432
   they fall to the age gate in 24h

   what this means: that run ended before its globalTeardown could reclaim.
   the usual causes are a signal (^C, a CI hard timeout, an OOM kill) or a
   throw inside globalSetup.

   no fix is owed if that run was one you interrupted on purpose.
   if it ended on its own, check your runner's logs at that timestamp.

   this notice prints once per residue. it will not repeat.
     runner: jest 30.2.0   node: v22.15.0
```

kai recognizes the CI timeout, raises it, and the message stops. **kai learned on run two rather
than on the monday eight months out when the laptop took four minutes to unlock.**

## how it fails safe — fast, loud, teaches the fix

| leg | how this case satisfies it |
|---|---|
| **fast** | the very next run in the same scope, rather than at the age gate a day on |
| **loud** | ⛈️ to stderr, with the count, the run id, and the dead pid — not swallowed like the extant `pruneStale` (`pruneStale.ts:42-45`) |
| **teaches the fix** | it names the evidence (marker, pid, count) and the cause **class**, then points at the runner's own logs — `rule.require.errors-name-the-fix` |

**it names a class of cause, never one specific cause, and that restraint is deliberate.** the
mechanism observes one fact — *this marker was never settled and its process is gone* — which is
consistent with a `^C`, a CI timeout, an OOM, and a `globalSetup` throw alike. a message that picked
one would send an adopter to audit a config that was never at fault, which is the exact defect
[case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md) names in the
broken-chain guard.

it is also honest that a deliberate `^C` needs no repair at all. a notice that scolds a human for an
interrupt they chose trains them to filter our output — which then hides
[case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)'s real failure.

## the timeline

```gherkin
given('[case12] an enhooked run whose globalTeardown never ran', () => {

  // ⚠️ the cast, declared up front: R, RHeld, RHalf, RWell, RPeer and RNext are
  //    bound in this given; RFull, R6, RZero, RNext6 and RAfterStamp are minted
  //    in the blocks that introduce them.
  const { pathPhysical } = getOneTempDirRoot();
  const R     = useThen('run N starts and is killed by a signal', () => mintRun({ preempted: true }));
  const RHeld = useThen('a run starts with the hold hatch set', () => mintRun({ keep: true }));
  const RHalf = useThen('a HALF-WIRED run starts — globalSetup, no globalTeardown', () =>
    mintRun({ wired: 'setup-only' }),
  );
  // ⚠️ RWell must COMPLETE before [t3]'s arrears pass, and a STEP must establish
  //    that. [t4] asserts the pass says no word about RWell — and if RWell had
  //    not yet run, the pass could not name it whatever the implementation
  //    does, so the assertion would be true by ACCIDENT of order and would
  //    exercise none of the conditional.
  //
  //    this is RPeer's constraint at the opposite pole, and the pair is what
  //    makes [t3]'s pass a real test rather than an empty one:
  //
  //      RPeer  must be LIVE      at the pass      → a marker it must NOT name
  //      RWell  must be COMPLETE  before the pass  → a marker it must NOT name
  //      R      must be DEAD      before the pass  → the marker it MUST name
  //
  //    three markers, three states, one pass. a conditional check needs at
  //    least one case it declines on for the SAME reason the implementation
  //    would decline — and "it did not exist yet" is not that reason.
  //
  //    ⚠️ note RWell's marker is DISCHARGED by its own teardown, so the pass
  //       finds none for it — and that is precisely the mechanism under test,
  //       never a hole in it. the pass is silent about RWell BECAUSE the
  //       teardown fired. what [t4] must pin is that RWell had its turn first,
  //       so the absent marker is an outcome rather than an unwritten one.
  const RWell = useThen('a HEALTHY run runs to completion BEFORE the pass', () =>
    mintRun({ runToCompletion: true }),
  );

  // ⚠️ RPeer is minted HERE, and that placement is the whole of [t5]'s validity.
  //    [t5] reads [t3]'s single arrears pass, so the peer must be live
  //    THROUGHOUT that pass. minted inside [t5] it would not exist at [t3],
  //    which makes "the same pass" a claim the timeline cannot support: under
  //    the `reportedAt` stamp R is named exactly once, so a LATER pass must be
  //    silent about R.
  const RPeer = useThen('a peer run starts and stays live throughout', () => mintPeerRun());
  const dirsMadeByPeer = useThen('the peer makes its fixture dirs', () =>
    countTempDirs(pathPhysical, { run: RPeer }),
  );

  // 📏 ONE marker record shape, asserted by FIELD.
  //    a file that alternates between `{ run, clearedAt }` and `{ run, state }`
  //    across its own steps offers no single record that satisfies both — two
  //    mutually exclusive claims about one handle, inside one demo. `state` is
  //    canonical: the settled machine has FOUR values (open / partial / closed
  //    / held) and a nullable timestamp expresses two.
  //    each assertion reads the ONE field it cares about, so the record may
  //    also carry `pid` + `startedAt` (which case=11's arrears check needs)
  //    and no assertion here goes stale.

  when('[t0] run N mints an id and writes its marker', () => {
    then('the marker exists, names the run, and is open', () => {
      expect(markerOf(R).run).toEqual(R);
      expect(markerOf(R).state).toEqual('open');
    });
  });

  // 📏 dirsMadeByRun is MEASURED here, never asserted as a literal.
  //    a fabricated constant such as `432` in a clamp measures the vision's
  //    imagination, not the behavior. what matters is that the count does NOT
  //    CHANGE across [t2] and [t3]; its absolute value is the suite's business.
  const dirsMadeByRun = useThen('the run makes its fixture dirs', () =>
    countTempDirs(pathPhysical, { run: R }),
  );

  when('[t1] the suite passes and makes its fixture dirs', () => {
    then('the dirs exist and carry R', () => {
      expect(dirsMadeByRun).toBeGreaterThan(0);
    });
  });

  when('[t2] a signal tears the process down before globalTeardown runs', () => {
    then('the dirs survive — leak, never loss', () => {
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(dirsMadeByRun);
    });

    then('the marker was NEVER settled — the record of the absent teardown', () => {
      expect(markerOf(R).state).toEqual('open');
    });

    then('the run itself said no word — it could not; it was already gone', () => {
      // ⚠️ `exitCodeOf(R)` is the form the neighbour steps use. a bare
      //    `exitCodeN`, bound nowhere, would be a free name in the very block
      //    that records the pre-empt — inside a file whose cast comment claims
      //    every handle is declared up front.
      expect(exitCodeOf(R)).toEqual(0);
      expect(stderrOf(R)).not.toContain('test-fns');
    });
  });

  // ⚠️ RNext is minted HERE. [t3], [t4], [t4a] and [t4b] each describe "the
  //    next" or "a later" run, so a bare `stderr` in any of them is tied to a
  //    run the timeline never produced. fix the instance, record the class: a
  //    repair applied only to the step a reviewer cites leaves its siblings
  //    broken.
  //    RNext is ONE run — [t3] and [t5] read the same pass, which is what the
  //    `reportedAt` stamp makes true and [t5]'s note leans on.
  const RNext = useThen('run N+1 starts in the same scope', () => mintRun());

  when('[t3] run N+1 starts in the same scope and its setup runs the arrears check', () => {
    then('it names the prior run and its dir count', () => {
      expect(stderrOf(RNext)).toContain(R);
      expect(stderrOf(RNext)).toContain(String(dirsMadeByRun));
    });

    then('it names the EVIDENCE — the unsettled marker and the dead process', () => {
      expect(stderrOf(RNext)).toMatch(/teardown never ran/);
      expect(stderrOf(RNext)).toContain(String(pidOf(R)));
    });

    then('it names a CLASS of cause, never one specific cause', () => {
      // the mechanism observes one fact — marker unsettled, process gone —
      // which a ^C, a CI timeout, an OOM and a globalSetup throw all satisfy.
      // a message that picked one would send an adopter to audit a config
      // that was never at fault. that is case=13's defect, in a new place.
      expect(stderrOf(RNext)).toMatch(/signal|timeout|OOM/i);
      expect(stderrOf(RNext)).not.toContain('--forceExit');
    });

    then('it does NOT scold a deliberate interrupt', () => {
      expect(stderrOf(RNext)).toMatch(/no fix is owed|interrupted on purpose/i);
    });

    then('it did NOT reap the prior run\'s dirs — it reports, never reaps', () => {
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(dirsMadeByRun);
    });
  });

  when('[t4] the teardown DOES fire on a healthy run, and discharges its marker', () => {
    then('RWell had already COMPLETED when the pass ran — the term that must be pinned', () => {
      // without this, "no word about RWell" is satisfied by a run that had not
      // started yet, which is true of every run never minted and proves none of
      // the conditional. the order is what makes the silence a DECISION.
      expect(startOf(RWell)).toBeLessThan(startOf(RNext));
      expect(endOf(RWell)).toBeLessThan(startOf(RNext));
    });

    then('and it says no word ABOUT IT — the arrears check is conditional', () => {
      // the discriminator, and it is why this pair must read ONE pass: RNext
      // names R and declines RWell in the SAME stderr. so the check is
      // demonstrably not silent in general — it is silent about RWell for
      // RWell's own reason, which [t4]'s next step names.
      expect(stderrOf(RNext)).not.toContain(RWell);
      expect(stderrOf(RNext)).toContain(R);
    });

    then('and its own marker is discharged — absence IS closed', () => {
      // ⚠️ an empty-namespace claim — `readRunMarkers(pathPhysical) === []` —
      //    goes RED against a CORRECT implementation. R's OWN marker from
      //    [t0]/[t2] is still on disk and minutes old: the arrears check
      //    reports it and never deletes it, and the marker sweep is age-bounded
      //    at 24h. the claim this step needs is run-scoped — the same
      //    shared-namespace discipline case=5 [t3] keeps.
      expect(markerOf(RWell)).toEqual(null);
      expect(markerOf(R).state).toEqual('open');  // R's is still here, and should be
    });
  });

  when('[t4a] the run HELD its dirs via TEST_FNS_KEEP', () => {
    then('the marker records held, never open — the teardown DID fire', () => {
      expect(markerOf(RHeld).state).toEqual('held');
    });

    then('the next run does NOT accuse it of a teardown that never ran', () => {
      // ⚠️ scoped to RHeld, never merely to RNext's whole stderr — RNext DOES
      //    say "teardown never ran" about R, so an unscoped assertion here is
      //    red against a correct implementation. the claim is about what is
      //    said OF RHeld, which is a narrower fact than what is said at all.
      expect(sectionOf(stderrOf(RNext), RHeld)).not.toContain('teardown never ran');
    });

    then('case=6 owns this message, not this case', () => {
      expect(sectionOf(stderrOf(RNext), RHeld)).not.toMatch(/signal|timeout|OOM/i);
    });
  });

  when('[t4b] the consumer wired globalSetup but NOT globalTeardown', () => {
    then('the marker is open — the teardown truly never ran', () => {
      expect(markerOf(RHalf).state).toEqual('open');
    });

    then('but the cause named is half-wired, NOT a signal', () => {
      // scoped to RHalf's section for the same reason [t4a] is: RNext names R
      // with a signal-class cause in the same output, so a whole-stderr
      // assertion here contradicts [t3] rather than tests this cell.
      // the config IS readable here, so this is the one row where the check
      // may name a specific cause — it has evidence, not a guess.
      expect(sectionOf(stderrOf(RNext), RHalf)).toContain('globalTeardown');
      expect(sectionOf(stderrOf(RNext), RHalf)).not.toMatch(/signal|timeout|OOM/i);
    });

    then('and the fix it teaches is the second config key', () => {
      expect(sectionOf(stderrOf(RNext), RHalf)).toContain('globalTeardown:');
    });
  });

  when('[t5] the SAME pass, read for the live peer beside R', () => {
    // 📏 this is [t3]'s ONE arrears pass, read for a different property — never
    //    a later one. under the `reportedAt` stamp settled above, R is named
    //    exactly ONCE, so a step that named R in a second pass would contradict
    //    [t3] outright. the "same pass" claim holds only because RPeer lives in
    //    the given, live throughout — so the pass genuinely sees both, and the
    //    two `then`s below are its two halves.
    // ⚠️ RPeer is a BOUND handle and its dir count is MEASURED, never a literal
    //    such as `150` — the same discipline case=11's RC2 keeps.

    then('the peer\'s marker is open — indistinguishable from R\'s by STATE', () => {
      expect(markerOf(RPeer).state).toEqual('open');
      expect(markerOf(R).state).toEqual('open');
    });

    then('its open marker raises no alarm — its PROCESS answers', () => {
      // ⚠️ no age window exists to lean on, so "a long run is not slandered by
      //    the window" is unavailable: case=11 [t6] places a live peer and a
      //    dead run MINUTES apart. the discriminator is the process, not the
      //    clock — and this check may ask, because it reports rather than reaps.
      expect(isProcessAlive(markerOf(RPeer))).toEqual(true);
      expect(stderrOf(RNext)).not.toContain(RPeer);
    });

    then('while R, whose process is GONE, IS named in that same pass', () => {
      // the two must be separated within ONE report, or the check is useless.
      // R is unreported at this pass — [t3] IS this pass, and the stamp it
      // writes is what makes every LATER pass silent about R.
      expect(isProcessAlive(markerOf(R))).toEqual(false);
      expect(markerOf(R).reportedAt).toEqual(null);   // before the stamp this pass writes
      expect(stderrOf(RNext)).toContain(R);           // RNext IS [t3]'s pass — one run, one pass
    });

    then('and a SECOND pass, after the stamp, names neither of them', () => {
      // the two halves of the bound in one step: R goes quiet because it was
      // reported; RPeer stays quiet because it is alive. an implementation with
      // only one of the two terms gets exactly one of these wrong.
      // ⚠️ named RAfterStamp, never RNext — a second identifier of the given's
      //    name would shadow it, and a reader who saw `stderrOf(RNext)` here
      //    and at [t3] would take them for one pass, which is the exact
      //    opposite of this step's claim.
      const RAfterStamp = mintRun();               // the pass AFTER [t3]'s
      expect(markerOf(R).reportedAt).not.toEqual(null);
      expect(stderrOf(RAfterStamp)).not.toContain(R);
      expect(stderrOf(RAfterStamp)).not.toContain(RPeer);
    });

    then('and the peer\'s dirs are untouched, as case=5 requires', () => {
      expect(countTempDirs(pathPhysical, { run: RPeer })).toEqual(dirsMadeByPeer);
    });
  });

  // 🔴 cell 3b — `scoped × preempted`, THIS REPO'S DEFAULT INVOCATION.
  // the catalog claims 3b is subsumed by this file, so this file must run a
  // SCOPED run: a subsumption claim that its own demo never exercises is not
  // coverage — it is an assertion about coverage.
  when('[t6] the pre-empted run was ALSO scoped — `--changedSince=main`, then killed', () => {
    // given: a run R6 invoked exactly as `package.json:53` invokes it
    //        · --changedSince=main   → only a SUBSET of test files load
    //        · then a signal         → the teardown is pre-empted
    // ⚠️ every run and every count below is minted or measured in-body; not one
    //    is assumed from elsewhere.
    // ⚠️ every mint below passes `preempted: true`. each block label says
    //    force-exited and each assertion below reads `state === 'open'` (the
    //    teardown never ran), so a mint without the flag lets a correct
    //    implementation's teardown FIRE and settle the marker — all three
    //    assertions red, and cell 3b's subsumption carried by a timeline that
    //    never produced the pre-empted state it asserts.
    //    `mintScopedRun({ preempted: true })` is the form case=5 [t4] uses.
    const RFull = useThen('a FULL, force-exited run starts', () =>
      mintFullRun({ preempted: true }),
    );
    const dirsMadeByFullRun = useThen('the full run makes its fixture dirs', () =>
      countTempDirs(pathPhysical, { run: RFull }),
    );

    const R6 = useThen('a SCOPED, force-exited run starts', () =>
      mintScopedRun({ preempted: true }),
    );
    const dirsMadeByR6 = useThen('it makes fewer dirs than the full run did', () =>
      countTempDirs(pathPhysical, { run: R6 }),
    );

    const RZero = useThen('a SCOPED, force-exited run selects ZERO test files', () =>
      mintScopedRun({ preempted: true, selects: 0 }),
    );

    then('the teardown was genuinely pre-empted — the precondition, asserted', () => {
      // without this the three `open` claims below rest on a mint option a
      // reader must take on trust. the run exited 0 and its teardown did not
      // settle the marker: that pair IS the pre-empt.
      expect(exitCodeOf(R6)).toEqual(0);
      expect(teardownRanFor(R6)).toEqual(false);
    });

    then('the marker exists and is open — scope never reaches the mint', () => {
      // the mint runs in globalSetup, BEFORE any test file is selected.
      // so a scope of ZERO files still writes a marker. this is the whole
      // reason the arrears check survives a scoped run where a per-file
      // afterAll would not.
      expect(markerOf(R6).state).toEqual('open');
    });

    // ⚠️ the NEXT run is minted HERE. the two assertions below read stderr, so
    //    without a run after R6/RZero anywhere in the file `stderr` is the
    //    unbound global handle and "the next run names it" is tied to a run the
    //    timeline never produced. cell 3b is this repo's DEFAULT invocation
    //    (`package.json:53`), and its fail-safe half — "the next run says so" —
    //    would then be walked nowhere. an assertion about a later run needs
    //    that later run to be a STEP.
    //    ⚠️ named RNext6, never RNext — the given binds an RNext for
    //    [t3]/[t4]/[t5], and a second one here would shadow it. this is a
    //    DIFFERENT invocation (it observes R6 and RZero, never R), and two runs
    //    under one name is how [t5]'s "a SECOND pass" nearly reads as [t3]'s
    //    first.
    const RNext6 = useThen('a LATER invocation starts, and its setup checks arrears', () =>
      mintRun(),
    );

    then('the next run names it, exactly as it names an unscoped pre-empt', () => {
      expect(stderrOf(RNext6)).toContain(R6);
      expect(stderrOf(RNext6)).toMatch(/teardown never ran/);
    });

    then('and it names the ZERO-scope run too — no test file is no exemption', () => {
      expect(stderrOf(RNext6)).toContain(RZero);
    });

    then('the count it reports is the SCOPED count, not the full-suite count', () => {
      // the failure mode this excludes: an arrears check that reports what a
      // FULL run would have made rather than what THIS run made would slander
      // every scoped run with a number it cannot reconcile against its own dir.
      //
      // ⚠️ two defects this form excludes, both carried by an
      //    `expect(stderr).toContain('6')` beside a `toEqual(6)`:
      //      1. `6` as a FABRICATED literal, which this file's own header note
      //         forbids ("a fabricated constant in a clamp measures the
      //         vision's imagination, not the behavior")
      //      2. `toContain('6')` is far too weak to carry the claim — a bare
      //         '6' appears in stderr for a dozen unrelated reasons (a node
      //         version, a path segment, a test count), so it would pass
      //         against an arrears check that reported the WRONG number.
      expect(getReportedDirCount(stderrOf(RNext6), { run: R6 })).toEqual(dirsMadeByR6);
      expect(dirsMadeByR6).toBeLessThan(dirsMadeByFullRun);  // scope really narrowed it
    });

    then('a scope that selects ZERO test files still leaves a marker', () => {
      // the degenerate end of the same axis, and the sharpest form of the claim:
      // no test file loads, so no fixture is made and no afterAll would exist —
      // yet globalSetup ran, so the run is still accountable for its own teardown.
      expect(markerOf(RZero).state).toEqual('open');
      expect(countTempDirs(pathPhysical, { run: RZero })).toEqual(0);
    });
  });
});
```

## the three assertions that carry this case

1. **`[t3]` fourth `then` — "it reports, never reaps."** this is the assertion that keeps the
   arrears check on the safe side of the leak-vs-loss line. the moment a maintainer upgrades it
   from a report to a reap, it becomes the very liveness probe
   [case=4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md) forbids and
   [case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)'s data loss returns.
2. **`[t4]` — the healthy run stays silent.** without it, the check becomes noise, consumers mute
   it, and the guard is worth less than no guard at all (the same trap `case=10`'s `[t4]` avoids).
3. **`[t5]` — a live peer's marker is not named, because its PROCESS answers.** an alarm that cries
   wolf at every parallel run teaches consumers to ignore it, which is how the 12,369 dirs accrued
   in the first place.

   > 🟠 **a summary must never name a mechanism the body rules out.** *"a live peer inside the
   > window"* is such a name — the window is ruled out four sections above, and `[t5]`'s own inline
   > note records it as ruled out. a summary that named it would be worse than a stale sentence: a
   > reader reaches the summary **last**, so it is the version they carry away.

## what this cell also fixes, for free

the same arrears check gives
**[case=4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md) the loud leg it
lacked.** a `kill -9`'d run leaves an uncleared marker for exactly the same reason any other
pre-empted run does — and it is the **same cell**, reached by one member of the same cause class.
so the next run names its residue with the same message, from the same evidence.

**and it names it exactly once**, per the `reportedAt` stamp settled above.
[case=11](./1.vision.experience.case=11.a-friday-afternoon.md)'s `[t1a]` is that sequence in full:
run A is `kill -9`'d at 14:07, run **B** names its 200 dirs at 14:12 as the first run whose setup
sees the marker, and C, D and every run after are silent about A while its residue sits for eleven
days. **the freebie is the report, never a permanent alarm** — which is what lets case=11's `[t3]`
keep its silent friday, and neither file bends its account of the mechanism.

that matters more than it looks. **the 12,369-dir leak grew unnoticed for months precisely because
no run ever said a word about a dir it did not reclaim.** one line, once, at the start of a run
would have surfaced it on day two.
