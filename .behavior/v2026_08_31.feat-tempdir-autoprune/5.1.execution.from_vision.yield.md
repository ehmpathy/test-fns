**a structural change fell out of A2.** the self-assert needs `isTempDir`, which lived in
`genTempDir.ts` — and `genTempDir.ts` imports the mint, so the assert would have closed a cycle.
`isTempDir` and its pattern now own `isTempDir.ts`; the contract imports from there directly rather
than through a forwarder (`rule.forbid.barrel-exports`).

**🔴 A4 was wrong when it first landed, and the repo's own suite proved it within the hour.**
`genTempDir` read the id and **passed it down** to `genEphemeralTempDir`. that reads as harmless —
until you notice `genEphemeralTempDir` has other callers. our own
`genEphemeralTempDir.integration.jest.test.ts` calls it directly, so **18 of its dirs landed
unstamped and survived a run whose count was otherwise zero**.

the fix moves the env read INTO `genEphemeralTempDir` — the allocation itself. that is the wish's
own words made literal: *the guarantee lives with the allocation, so no call site can forget.* a
caller-supplied stamp is a call site that CAN forget, and one did, immediately.

**🔴 A2's assert was RIGHT to throw and WRONG about who to blame.** the stamp's only marker is its
**shape and its position**, so on an **unhooked** run the consumer's own slug occupies exactly the
stamp's slot: `genTempDir({ slug: 'rdeadbeef' })` reads back as a run id no run ever minted. the
assert caught it, then reported *"the mint and the parse have diverged"* — which sends the consumer
to audit a library internal over a name **they** chose.

the branch now splits. when no run was stamped and yet one parses back, the slug is the sole
possible source, so the message names the slug and names the fix (*"rename the slug — any name that
does not match `r[a-f0-9]{8}` will do"*). the guard is bounded to the unhooked shape: with a real
stamp present the slug moves one segment right, so the same slug is accepted there.

*it lands on the unhooked path — every consumer's state on release day — which makes it the largest
population any misdiagnosis in this behavior could reach.*

the boundary is drawn by `rule.prefer.most-common-denominator`, applied one test uniformly:
**a leaf nests where it is used; the moment a second caller outside that nest reaches for it, it
lifts to their common ancestor.** the five files at the parent level each have exactly that shape —
autoprune reaches for them, and so does the allocation path. to draw the line by *"does it feel
like autoprune's?"* would have pulled `runMarker` and `warnIfUnhooked` inside, and then
`pruneStale` and `genEphemeralTempDir` would reach **into** a child dir for them.

`autoprune.ts` also split three ways on the move. it had carried `setupAutoprune`,
`teardownAutoprune`, and `warnIfUnhooked` — three operations with three distinct call sites — in
one file, against `rule.require.single-responsibility` and `rule.require.sync-filename-opname`.
there is **no** `autoprune/index.ts`: the adapters import each file directly
(`rule.forbid.barrel-exports`).

## three findings that cost more than the line they moved

**1 — `findsertFile` throws on content drift, so a revision of the shipped readme was a BREAK.**
`genIsolatedTempInfra` findserted its readme, and `findsertFile` throws when the file exists with
different content. so I1's edit meant: **every consumer whose temp root predates the upgrade throws
on their first `genTempDir` call**, deep inside their own test, at a path they never chose. that is
the one outcome a backwards-compatible upgrade must not produce — the same class as the
`ENAMETOOLONG` hazard the vision named, reached by a different route. the repair is
`upsertFile.ts`, and the readme is now **upserted**. *findsert is the right verb for a fixture and
the wrong one for a doc that will be revised.*

⚠️ **and the first repair over-reached, in the one direction this behavior cannot afford.** it was
an *atomic write-then-rename*, which put `readme.md.<pid>.staged` into the temp **root** — the
shared namespace the run reclaim, both age-gate passes, the arrears check, and a consumer's own
clamp all iterate. it matches **none** of their filters, so a process killed between the two calls
left a file **no mechanism would ever reclaim**. that is register row 18's leak, re-introduced
under a different name.

the atomicity was never required — `readme.md` is read by no production code — so it bought a
cosmetic property and paid in immortal residue. it is replaced by **convergence**: write only when
the content differs. since this runs on every `genTempDir` call in every worker, and the content
matches after the first write, the common path performs **no write at all** — concurrent writers
become almost unreachable rather than merely made safe. clamped in
`upsertFile.integration.jest.test.ts`.

**2 — a global hook loads OUTSIDE the runner's `moduleNameMapper`.** the adapters and every module
reachable from them must import **relatively**; an `@src` alias binds in a test file and throws in
a setup file. it failed loudly at first run rather than silently, so it cost minutes — but it is a
constraint on every future edit to that path, so it is noted in each affected file rather than only
here.

**3 — 🟢 A1's env chain is PROVEN, and the repo proved it by accident.** see J2.

## the defects the clamps and the reviews found — none of which the vision had named

**🔴 4 — a nested run inherited its parent's id, so its teardown would have REAPED the parent's
live dirs.** `setupAutoprune` read `getOneRunId() ?? genOneRunId()`. a child process inherits our
env, so a consumer whose test drives a nested runner — a cli under test, a fixture repo with its
own suite — would have the **child's** teardown reclaim the **parent's** live fixture dirs
mid-run. that is **loss**, the one failure mode this design keeps off the table at every other
edge; the vision's own words are *"every failure mode leaks; not one loses."*

the reuse bought an idempotency that a once-per-invocation global hook never needs. it now mints
**always**, which makes the nested reap unreachable rather than merely unlikely — rung 1 of
`rule.prefer.prevent-over-correct`. `case=5`'s peer-safety cell, reached by a nested run rather than
by two humans, and reachable far more cheaply than the two-humans shape that case presents.

*it was found because the clamp had to answer "is my child peer-safe from my parent?" before it
could be written at all.* the clamp now asserts it directly, so the reuse cannot return.

**🟠 5 — `genTempDir` yields the SYMLINK view, and `pathPhysical` is not its parent.** the two
views name one place, so `path.dirname(genTempDir(...)) === pathPhysical` reads as obviously true.
it is false. **I wrote that assertion myself in the J3 probe and it went red** — which is the best
possible evidence that a consumer will write it too. this is precisely why the export yields
**both** rather than choose for the caller (open question 3, settled at the vision). it is now
clamped on both runners, with the physical view asserted to hold the same dir.

**🔴 6 — the age gate fired W+1 times per invocation, where 1 would do.** E3 moved the gate to
`globalSetup` and the extant `genTempDir` trigger was kept too, on the vision's line *"the gate
**stays** on `genTempDir` as well, **for the unhooked consumer**."* the verb was kept and the
qualifier dropped, so it fired unconditionally. the throttle is a module-level flag — once per
**process** — and `genTempDir` runs in every **worker**, so an enhooked run paid one scan at setup
plus W more, all redundant, in the exact environment where a scan over a swollen `/tmp` is measured
in seconds. the fix is one condition, `if (!getOneRunId())`, and a non-null id is proof the gate
already swept this run. clamped **both ways** — enhooked ⇒ the gate does not fire, unhooked ⇒ it
does — because the danger is never that it fires, it is *for whom*.

**🔴 7 — the library's own suite left IMMORTAL dirs behind.**
`genEphemeralTempDir.integration.jest.test.ts` planted five hand-named fixture dirs
(`.test-fixture-clone`, …) **directly in the shared root**. those names match no filter at all:
`isTempDir` rejects them so every reclaim skips them, and `computeStaleDirs` cannot parse them so
the age gate **preserves them by design** (case=14 — correct, since we may not have minted them).

they are the exact class the vision calls immortal — *"no run's id claims it, and no age check can
read it"* — left by the suite that exists to verify the behavior whose whole purpose is that no
entry outlive its run. the fixtures now allocate through `genEphemeralTempDir`, so their names
carry the run stamp and the reclaim owns them by construction; the suite dogfoods the mechanism it
tests. *the five extant dirs stay until a human removes them — which is exactly what E4's
`namesUnreadable` report now tells them, on every run. the report added in this behavior already
earns its place against residue this behavior did not create.*

### what the self-review rounds bought

seven self-review rounds ran against this stone, each indexed on a **different question** rather
than a different file set. the gaps they found are fixed and clamped above (defects 4–7, and the

| round's index | what it can see | what it is blind to |
|---|---|---|
| the file list | a file that reads wrong on its own | a defect between two files |
| the mechanism list | an uncovered producer | an uncovered **requirement** |
| the wish's acceptance list | an uncovered requirement | an order or an edge |
| the vision's invariants | orders and edges | a **standards** violation |
| the role's practice index | standards violations | (disjoint from all above) |

the vision walk and the standards walk found **zero overlap** — the files did not change between
passes; the question did.

## lessons

1. **the guarantee must live with the ALLOCATION, and a caller-supplied stamp is a call site that
   can forget.** one did, immediately — 18 dirs from our own suite (defect A4).
2. **a green clamp proves what the code DOES, never that what it claims to exercise is what it
   exercises.** five separate instances on this stone.
3. **a value with two producers is half-audited by a census that finds one, and it feels finished.**
4. **a census is two choices — the question and the frame.** the question was iterated nine times
   and the frame twice, and each widen felt like the correction.
5. **coverage of a PRODUCER is not coverage of its CONSUMER, and a grep cannot tell them apart.**
   index the census on the **requirement**, never on the mechanism that serves part of it.
6. **a file-by-file walk cannot see a defect that lives between two files.** the files read
   correctly on their own; their **order** was wrong. the questions that found it were
   invariant-shaped: *the marker is written ahead of the work it describes — where ELSE can this
   process end?* and *this validator rejects a partial record — which of its fields is UNCHECKED?*
7. **the vision walk and the standards walk find DISJOINT classes** — same files, different
   rulebook, zero overlap.
8. **enumerate the index from disk, before the walk.** from memory, `consistent.glossaries` reads as
   irrelevant; it turned out to need a real argument.
9. 🔴 **a repair is itself a change, and a change that has not been graded is a change whose defects
   are unmeasured.** one `as`-cast fix created a lint complaint, caught only because the linter ran
   after it.
10. **when two rules conflict, the way out is usually a SCOPE question, not a precedence one.**
11. 🔴 **prod code was clean; every standards violation lived in the code written to TEST prod
    code.** four reviews had walked the prod modules; not one had walked the clamps with the same
    rulebook — *because a test that passes feels finished, and a green test is exactly what a defect
    in a test looks like.*
12. **an unreachable branch is worse than an absent one: it answers the question a reviewer would
    otherwise have asked.** the `JEST_CONFIG` read named a file it could never name.
13. **a clamp whose assertions the wrong answer also passes is a clamp for the sentence in its
    title, not for the behavior.**
14. **a probe neutralized by the harness looks exactly like a clamp that does not bite.** to dogfood
    a blackbox clamp, revert the SOURCE and let the harness rebuild.
15. **an atomic write into a shared namespace is a leak with extra steps.** the staged file matched
    no reclaim filter, so a kill between the two calls left it immortal — the guard against a leak
    became one. convergence (write only on drift) has no such window.
