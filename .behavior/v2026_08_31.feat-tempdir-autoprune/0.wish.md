# wish: no temp dir `genTempDir` made survives the test run that made it

## .source of record

**`ehmpathy/test-fns#64`** — read it FIRST and in full. it is the authoritative spec for the
autoprune itself. this wish carries what sits **above** the issue: why the fix belongs here rather
than downstream, the one tie that bites, and the bound on scope.

secondary reads, both cited below and neither in scope for this tree:

- **`ehmpathy/test-fns#66`** — the age gate + the git-common-dir scope key
- **`ehmpathy/test-fns#65`** — expose the physical path

## .what

`genTempDir` cleans up after itself. a test run that used it leaves **zero** new temp dirs behind.

the guarantee must hold for a run that **fails**, a run that is **scoped** to a subset, and a run
**interrupted** part way — not only for a clean full pass. and a parallel run of the same suite
must **not** reap a peer run's live dirs.

alongside it, one export: **the contained temp path**, so a consumer can derive the directory
rather than hardcode a literal of it. (see *the tie that bites*, below — this is what makes the
outcome measurable at all.)

## .why

### the defect is `genTempDir`'s, so the fix is `genTempDir`'s

`ehmpathy/rhachet` is where a **12,901-dir leak** was measured on one dev machine, 2026-08-30. it
is not where the defect lives. `genTempDir` allocates and never reclaims, so **every `test-fns`
consumer carries the same hole today** — rhachet is simply the one that got large enough to be
noticed.

the costs, in the order they bite on the machine that measured them:

1. a large `/tmp` blocks boot for minutes on a LUKS system — `systemd-tmpfiles-setup.service`
   walks it
2. tools degrade — a ripgrep over `/tmp` blew a 20s timeout purely on directory count
3. inodes are held and never returned
4. a daily `find -mtime +3 -delete` sweep cannot keep up; fixtures are remade faster than a daily
   pass clears them

### the acceptance signal for the choice of repo

downstream should end with **no** temp-dir prune, registry, or teardown of its own. if a consumer
still holds prune machinery once this lands, the fix landed in the wrong repo.

## .acceptance

- a full test run leaves zero new dirs that `genTempDir` made — measured by a count before and
  after
- the guarantee survives a **failed** test, a **`--scope`d** run, and an **interrupt**
- a parallel run of the same suite does **not** reap a peer run's live dirs
- an escape hatch exists for a human to inspect a failed test's dir (`TEST_FNS_KEEP` is the
  issue's proposal for it)
- the **contained temp path is exported**, so a consumer derives it rather than hardcodes it
- a regression clamp that **bites**: red before the fix, green after
  (`rule.require.clamp-edge-cases`)

## .the tie that bites — why the export is in scope, and is not a nicety

**#66 moves the directory that #64's clamp counts.**

today the contained dir is keyed on the **worktree** name, so a consumer's branch writes to
`/tmp/test-fns/<worktree>/.temp/`. #66 re-keys it to the git **common** dir, so it becomes
`/tmp/test-fns/<repo>/.temp/`.

a clamp that hardcodes either literal counts **0 before and 0 after** once the other is live —
green, and blind.

that is the `1,786 orphan dirs accrued under a green clamp` precedent a third time. from
`term=partial-audit`, verbatim:

> a per-case sweep read its dir list **as of the moment it ran**, so dirs registered later
> survived every run — and under `--scope` its whole subject set went unswept with no verdict
> rendered at all.
>
> the cure was structural rather than a sharper check: move the guarantee to a teardown that
> **neither order nor scope can step around**, and make it FAIL LOUD.

so the export is not convenience. it is what makes the outcome **verifiable by anyone downstream
without a hardcoded literal that a later change silently invalidates** — and, per the handoff, it
retires #65 in the same stroke.

## .evidence — three probes, each of which CLOSED a design question

run in `ehmpathy/rhachet` on 2026-08-31. these are **evidence**, not instruction — the author ran
them and they came back as stated. they bound what is reachable; they do not prescribe a shape.

| probe | verdict | what it settles |
|---|---|---|
| a `process.on('exit')` hook in a jest worker | ⛔ never fires | a library cannot own the teardown invisibly — a consumer-side hook is unavoidable |
| a per-worker id in `process.env` | ⛔ erased between test files | a session id must be minted **before** the workers exist |
| `JEST_WORKER_ID` reaches every test file | ✅ nine files deep | the fork spreads the main env — a mint-before-fork chain holds |

**the honest bound, stated by the author:** links 1–2 of that chain are jest's *implementation*,
not its documented contract. so **clamp the chain rather than trust it** — a defect there is
silent, and it fails toward *dirs survive under a green suite*, which is the exact failure mode
this wish exists to end.

## .prior art — the shape is in production, in a third repo

verified 2026-08-30 by direct read, not recalled.

`nheuron`'s `.agent/repo=.this/role=any/skills/work/work.harness.ts:62` declares
`genTempDir({ slug })`, which allocates **and** registers into a module-level `DIRS_TEMP`, paired
with a sweep called from an `afterAll`. two hazards it solved that a naive form does not:

- **never sweep by a bare prefix glob.** it sweeps only what *this process* made, so a parallel
  run of the same suite cannot reap its peer's live dirs
- **a reaper must skip both this run's own dirs and a peer's live ones** —
  `work.harness.ts:715` skips dirs in `DIRS_TEMP` (the `afterAll` owns them) and dirs named in a
  live process's argv

a second precedent worth a read for its **safety contract** rather than its mechanism:
`rhx clone prune` in `ehmpathy/rhachet` — plan-by-default, never prunes what it cannot verify,
fails loud with the residue named.

both are **evidence** the shape is reachable and a catalogue of real hazards. they are different
repos with different constraints. do not port either.

## .the HOW is yours — itemized

per `rule.require.wish-outcome-over-proposal`, `.what` / `.why` / `.acceptance` are authoritative.
all else is ground, not instruction. specifically:

- **the three probes above** — **evidence**. the author ran them and they hold. treat them as
  bounds on what is reachable, never as a design to transcribe
- **`TEST_FNS_KEEP`, "session mint", "stamped dir name", "`afterAll` prune"** — **proposals** made

  allocation, so no call site can forget*. the names, the mechanism, and their home are yours
- **the two-config-key shape a consumer would adopt** — a **proposal** that follows from probe 1
  only. probe 1 proves a consumer-side hook is needed; it does not prove there are exactly two, or
  that they are jest config keys
- **`work.harness.ts` and `rhx clone prune`** — **evidence** + a hazard catalogue. do not port
- **"retires #65 in the same stroke"** — a **proposal** about which issues close. deliver the
  export; whether #65 closes is the maintainer's call

open questions to settle in-repo, not by me:

- does a fixture or harness layer already exist here that should own the teardown?
- is the prune plan-by-default (the `clone prune` contract), or does a test run reap silently?
- what does the exported path name itself, and is one export enough for both the clamp's use and
  a consumer's own allocator?

## .scope

**`ehmpathy/test-fns` only**, and within it **#64 plus the contained-path export**.

explicitly OUT:

- **the already-leaked dirs on any machine.** that is a cleanup chore, not this behavior. this
  behavior stops the source
