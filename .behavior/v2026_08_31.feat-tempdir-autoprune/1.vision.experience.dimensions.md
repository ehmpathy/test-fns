# 1.vision.experience.dimensions

## .what

the orthogonal axes the temp-dir-reclaim experience varies over, and the product they generate.

the inventory (`1.vision.experience.case=_.md`) walks this product and verdicts every cell.

## .why walk a product rather than free-list

a free-list of "the suite passes" and "the suite fails" would have missed the two paths that
carry the whole risk: **peer-parallel** (a run reaps its neighbour's live fixtures — data loss)
and **unhooked** (a consumer upgrades, gains no reclaim, and is never told). both fell out of the
grid, not out of memory.

⚠️ **and a grid can still hide a constant.** axes A–E all vary what happens *within* one runner
invocation, while the invocation itself sits fixed and undeclared. that silent constant hides three
real experiences. **the walk protects you from what you forgot to list; it does not protect you
from what you assumed.** axis F below is the repair, and the general rule it earns is: *every
constant your axes rest on is an axis you have not declared yet.*

## the axes

### A. hooks — how the consumer's runner is configured (5)

> 🔴 the fifth value, `halfwired`, adds 64 points to the raw product; all 64 collapse (collapse 2)
> to **two** cells, 28 and 29. see the value's own note below, and the collapse-2 note for the
> arithmetic.

| value | sense |
|---|---|
| `jest` | **enhooked** for jest — consumer wired the two jest keys |
| `vitest` | **enhooked** for vitest — consumer wired the one vitest key |
| `unhooked` | consumer upgraded the package, wired no hook |
| **`halfwired`** | **jest only** — one of the two required keys is present and the other is not |
| `broken` | wired correctly — the runtime dropped the id in transit |

#### 🔴 `halfwired` — the value the two-key asymmetry creates, and jest alone can reach

> execution ships a bespoke message for one direction of it (`autoprune.messages` `[case6]` —
> *"the autoprune TEARDOWN ran, but its SETUP did not"*), and `case=10`'s seven-cause table names
> the other direction as a cause. an axis that named neither would leave the catalog with no row
> either could match.

the vision's *awkward #4* argues this state into existence, so the axis must hold it:

> *"two keys means a **half-wired** state exists that vitest cannot reach … **a config surface with
> two required keys does not merely ask for two lines; it creates a distinct broken state per absent
> key, and each needs its own diagnosis.**"*

**it is a value on axis A, not a variant of `unhooked` or of `broken`**, and the three-way split is
by *who is at fault and what the fix is*:

| value | the config | who fixes it, and how |
|---|---|---|
| `unhooked` | neither key | the adopter — add both |
| **`halfwired`** | **exactly one key** | the adopter — add the **other one, named** |
| `broken` | both keys, correct | **us** — the runtime dropped the id; file an issue |

**its two directions do NOT collapse**, because each breaks a different half of the mint→reclaim
chain and each needs a different sentence:

| direction | what happens | the signal |
|---|---|---|
| `setup` only | ids are minted, every dir is stamped, and **not one is ever reclaimed** — the leak the wish exists to end, at full rate, under a green suite | the next run's arrears check meets an `open` marker every time (`case=12` `[t4b]`) |
| `teardown` only | no id is minted, so the teardown runs with **no run to reclaim** — today's leak, plus a teardown that does work for no one | its own message: *"the autoprune TEARDOWN ran, but its SETUP did not"* |

**vitest cannot reach either**, since its `globalSetup` module exports `setup` and `teardown`
together — which is why the value carries the runner in its sense line. walked as cells **28** and
**29**.

**`enhooked`** names the union of `jest` and `vitest` — *the hooks are in place, whichever runner
holds them*. it is the declared umbrella the region walks use, and it is the exact complement of
`unhooked`.

> 🟠 **a term that carries weight in the inventory must be minted by the axis that defines the
> space** — else a reader who checks a region header against axis A meets a word with no row. a
> bare `hooked` is such a word: the regions need the union, and only `enhooked` is on the axis.
>
> **the pair is `enhooked` / `unhooked` rather than `hooked` / `unhooked`, and the prefix is the
> point** (`rule.prefer.symmetric-term-pairs`). `hooked` is a **bare participle** and `unhooked` is a
> **prefixed** one, so the two read as *a base state and its negation* — which invites `hooked` to be
> heard as the default and `unhooked` as the deviation. **the truth is the reverse: `unhooked` is
> every consumer's state on release day**, and `enhooked` is the one someone must act to reach.
>
> two matched prefixes make them siblings rather than a norm and its exception, and `en-` carries the
> right sense besides — *to put into*, an act someone performs, which is precisely the pair of config
> keys probe 1 proves cannot be avoided.

> **`broken` is a value because the seam scan finds it.** `howto.experience.enumerate` move 3
> surfaces the `globalSetup env → worker env` handoff as a boundary that owes a cell. it is distinct
> from `unhooked` in cause, in who fixes it, and in verdict — see
> [case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md). a three-value axis treats
> a silent chain break as indistinguishable from a config lapse, which would ship the wish's own
> worst failure mode undemonstrated.

**why an axis:** probe 1 (in the wish) settles that a library cannot own the teardown invisibly —
the reclaim must hang off a hook the *framework* calls. so the consumer's config state is a real,
observable input to the experience, not an implementation detail.

**why orthogonal:** every termination, concurrency, and keep-intent value is reachable under each
hooks value. `unhooked` does not force a termination mode.

**why `vitest` is its own value, not a footnote:** this repo ships `test-fns/vitest.setup` in
`package.json:exports` (line 23) and invokes `vitest run` **four times across three of its own
test scripts** (`package.json:54,57,61`) — unit, integration, and acceptance. a jest-only reclaim
would leave the library's own suite to leak.

### B. termination — what became of the TEARDOWN (4)

| value | what became of the teardown | typical cause |
|---|---|---|
| `pass` | **ran to completion**, tests green | normal exit |
| `fail` | **ran to completion**, a test failed | normal exit, non-zero |
| `preempted` | **began, then was pre-empted** mid-flight | a signal or an OOM lands while the reclaim runs |
| `interrupt` | **never began** | `kill -9` before teardown, a `globalSetup` throw, a crash |

> **a flag is never an axis value; the STATE it produces is.** an axis that asks *"how did the run
> END"* and then names `jest --forceExit` as one of its values lets a green run under that flag
> carry two values of one axis — the identical non-orthogonality that disqualifies `scoped` one
> axis over.
>
> **the repair is the question, not the values.** what every cell here turns on is *what became of
> the teardown* — and under that question the four are exclusive by construction: the teardown
> either completed (split by test outcome, because `case=2` exists to prove the reclaim ignores the
> exit code), was pre-empted part-way, or never started.
>
> **the reframe also settles A6, and settles it against the flag.** `--forceExit` does **not**
> pre-empt the teardown — `@jest/core` awaits `globalTeardown` at `build/index.js:3464` and the
> flag's `exit(code)` fires after, at `jest-cli:719`. so a `--forceExit` run lands in `pass`/`fail`
> like any other. what the flag *does* impose is a constraint on the reclaim's shape: it must be
> `await`ed inside the teardown, since `exit(code)` fires the instant that promise resolves.
>
> **this is why the axis value must not name a cause.** a value named for one mechanism inherits
> that mechanism's fate — disprove the mechanism and the cell looks empty, though the state it names
> is reached daily by four other causes.

> 🔴 **`scoped` is NOT a fifth value of this axis.** `scoped` answers *which tests ran*; the four
> values above answer *what became of the teardown*. they are
> **not mutually exclusive** — a scoped run can pass, fail, be force-exited, or be interrupted — so
> a five-value axis that packs both is non-orthogonal, and its product double-counts the space.
>
> **the overlap hides this repo's own DEFAULT invocation.** the jest commands append
> `--changedSince=main` (`package.json:53,56,59`), so a scoped run that is then killed —
> `scoped × preempted` — is a reachable local path, and a five-value matrix cannot express it: it
> verdicts cell 3 (`scoped`, happy — the teardown still runs) and cell 8b (`preempted`, sharp —
> the teardown never runs) as though a run takes exactly one value. **a run can be both**, which is
> the pair `case=12` `[t6]` walks.
>
> `scoped` is its own axis — **G. coverage**, below.

### G. coverage — WHICH tests the run covered (2)

> it is not a value of axis B; it is a dimension.

| value | sense |
|---|---|
| `full` | the whole suite ran |
| `scoped` | a subset ran (`--scope` / `-t` / `--changedSince=main`) |

**why an axis:** it is the value that produced the `1,786 orphan dirs under a green clamp`
precedent — a scoped run's subject set went unswept **with no verdict rendered at all**. that is a
distinct failure mode from a failed run, never a shade of it.

**why orthogonal to B:** every `coverage × termination` pair is reachable, and two of them are the
cells a termination-only axis cannot name:

| the pair | reachable? | verdict |
|---|---|---|
| `scoped × pass` / `scoped × fail` | yes | cell 3 — the teardown is config, so scope cannot reach it |
| **`scoped × preempted`** | **this repo's DEFAULT** | 🔴 the compound of cells 3 and 8b — walked below as cell **3b** |
| **`scoped × interrupt`** | yes | walked below as cell **3c** |
| `full × *` | yes | the region-1 rows as written |

**it DOES multiply the raw product by 2 — and collapse 5 takes almost all of it back.** every
`scoped × X` cell **collapses** into `full × X`, **except** where X is itself about the teardown's
own survival.

the reason the collapse is so near-total: coverage is **orthogonal to the reclaim's mechanism by
construction** — the teardown is a config hook, not a test, so no scope filter can deselect it.
that is `case=3`'s entire result. so `coverage` changes *which fixtures exist to reclaim*, never
*whether the reclaim runs*. the exception is exactly `preempted` and `interrupt`, which is why
those two get walked cells (**3b**, **3c**) and the rest collapse — see collapse 5, below.

> 🟠 **an axis multiplies the raw product** (that is what an axis is) **and its cells may then
> collapse** (that is what a collapse rule is). one sentence that says both says neither. a claim
> that coverage *"does not multiply the product by 2"* is flatly false against the formula it was
> written to explain — drop the factor and the arithmetic breaks.
>
> **the raw product and the survivor count are two numbers, and the whole raw-product → survivor-count
> progression is only legible if they are kept apart.** *(both live in
> [the product section](#the-product) and its* what survives *table; this note names them rather
> than copies them.)*

> **`preempted` is a value because an axis is only as complete as its least-examined value set** —
> a lesson that applies to axis B as much as to axis A.
>
> it is not hypothetical. a CI hard timeout, a human's `^C`, and an OOM kill each reach it, and each
> is common on a suite that runs for minutes. a `globalTeardown`-based reclaim is **structurally
> blind to its own absence**, so this value is the one that needs an out-of-band detector — the
> arrears check at [case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md).

**two more facts this repo's own commands settle, both read from `package.json`:**

- `scoped` is this repo's **default**, not an edge — the jest commands append
  `--changedSince=main` unless `THOROUGH` is set (`package.json:53,56`). so
  [case=3](./1.vision.experience.case=3.scoped-run-still-reclaims.md) is the common path here.
- the acceptance command runs `--runInBand` (`package.json:59`) — **one process, no fork**. so the
  acceptance suite structurally *cannot* exercise the mint chain's fork hop. any clamp on A1 must
  live in the unit or integration suites, which do fork.

**why an axis:** the wish's `.acceptance` names three of these explicitly. the fourth (`pass`) is
the baseline they are measured against.

**why orthogonal:** independent of hooks, concurrency, keep-intent, and coverage.

### C. concurrency — who else writes to the same scope (2)

| value | sense |
|---|---|
| `solo` | one run owns the scope |
| `peer-parallel` | a second run writes the same contained dir, concurrently |

**why an axis:** the contained dir is keyed per repo (and, after #66, shared across worktrees), so
two runs that share a scope is normal, not exotic. verified live: `/tmp/test-fns/` holds three
`rhachet.*` worktree scopes side by side today.

**why orthogonal:** a peer may run under any hooks, any termination, any keep-intent.

### D. keep-intent — whether the fixture is wanted after the run (2)

| value | sense |
|---|---|
| `reclaim` | default — the run's dirs go back |
| `hold` | a human asked to keep them for inspection |

**why an axis:** the wish's `.acceptance` requires an escape hatch. to hold is a deliberate,
orthogonal choice — a human can hold a `pass` run's dirs as easily as a `fail` run's.

### E. attendance — is a human present (2)

| value | sense |
|---|---|
| `attended` | a developer at a terminal |
| `unattended` | ci, a cron, a pre-push hook |

**why an axis:** it changes what a **sharp** edge may do. an attended run may print a hint and let
a human act; an unattended run has nobody to read it, so the same edge must settle itself or fail
the build.

### F. invocation — what "a run" IS (3)

> axes A–E all vary what happens *within* one runner invocation. not one of them asks **what an
> invocation is** — the walk holds that constant at *"one runner, started once, exits once"*.
> **a dimension held constant is a dimension undeclared.**

| value | sense |
|---|---|
| `once` | one runner invocation: `jest -c …` starts, runs, exits. the assumed default of axes A–E |
| `session` | a watch invocation: one `globalSetup`, N re-runs, one `globalTeardown` at exit |
| `absent` | no runner at all — a cli, a `tsx` one-off, a codegen step that calls `genTempDir` directly |

**why an axis:** it changes **the unit the guarantee is measured in**. under `once` the promise is
per-invocation. under `session` it is per-session, so 40 re-runs share one id and reclaim together.
under `absent` there is no teardown to hook, so the promise cannot be made at all — and `case=7`'s
notice names a fix that does not apply to them.

**the count that forces it:** `npm test` in this repo is **seven** runner invocations
(`package.json:53-64`). so kai's "a run" is seven of ours, and the guarantee holds end-to-end only
because the seven chain with `&&`. a consumer who parallelizes them reaches
[case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md) inside a single command.

**the settled unit, stated once so the rest of the vision can rest on it:**
**a run is one runner invocation.**

### H. resource-state — what condition the contained dir AND its entries are in (6 — one barred)

> 🔴 **the axis's SUBJECT is the contained dir AND its entries.** a subject scoped to the
> **entries** alone lets a fourth state hide: the **root itself** can exist and still refuse to
> open. see `unopenable`, below.

> 🔴 `rule.require.dimensional-decomposition`'s absent-axis check names *resource-absent /
> resource-state* as a usual omission. cells **18** (an unremovable dir) and **21** (a name the age
> gate cannot read) are the behavior's two sharpest edges; to **free-list** them into the inventory
> on the admission that they *"sit outside the product by design"* is the defect, not an exemption
> — **a cell outside the product is a cell the walk did not protect.**

| value | sense | verdict |
|---|---|---|
| `sound` | the entry parses and removes cleanly — the assumed default of axes A–G | walked |
| `unreadable` | its name does not parse, so the age gate preserves it forever (`computeStaleDirs.ts:28-29`) | walked |
| `unremovable` | `rmSync` throws — `EACCES`, `EBUSY`, an open handle, a read-only `git init` artifact | walked |
| **`unopenable`** | the **root** exists and will not open — `readdir` throws `EACCES`/`EPERM`/`ENOTDIR`, so not one entry is ever enumerated | **walked — below** |
| **`unparseable`** | a **run marker** opens and reads, and its **content** will not parse — a torn write, a truncated file, a hand-edit | **walked — below** |
| **`absent`** | there is no entry to act on at all | **barred — with reason, below** |

#### 🔴 `unparseable` — a marker whose CONTENT will not parse

> its source is `autoprune.messages` `[case4]`:
> *"1 run marker(s) could not be read, so no run's fate could be judged from them. ├─ unparseable:
> `run.rtornwrite.marker.json` └─ fix: remove them by hand — a marker we cannot parse names no run."*

**it is not cell 21.** `unreadable` is a **dir** whose **name** does not parse, which blinds the
**age gate**. this is a **file** whose **content** does not parse, which blinds the **arrears
check** — a different subject, a different mechanism, a different victim, and a different fix:

| | `unreadable` (21) | `unparseable` (30) |
|---|---|---|
| the subject | a fixture **dir**'s name | a run **marker** file's content |
| what parses it | `computeStaleDirs` / `TEMP_DIR_PATTERN` | the arrears check's marker read |
| who goes blind | **the age gate** — the backstop 4 cells lean on | **the arrears check** — cell 12's only signal |
| the fix | ours: keep the stamp inside the slug segment (`case=14`) | the human's: remove the file, since it names no run we can act on |

**how it is reached:** a torn write — the marker is written at `globalSetup` and rewritten at
teardown, so a `SIGKILL` mid-write leaves a partial file; also a truncated disk, or a hand edit by
someone who went to look. **it pairs live with cell 8b**, since the same signal that strands a
marker can strand it mid-write.

**why it does not simply reduce to "the teardown never ran":** an unparseable marker names **no
run**, so the check cannot say whose it was, cannot say when it began, and must not guess. so it
reports the *file* rather than a *run* — the one arrears message that names a path instead of an
id. walked as cell **30**, one row, `alterpath`.

#### 🔴 `unopenable` — the root exists and refuses to open

> execution ships a message for this state — `pruneStale.ts:291-296`, snapped by
> `autoprune.messages` `[case11]` — so the catalog owes it a row. per
> `rule.require.experience-catalog-evolution`'s backward direction, a tested experience outside the
> catalog is a blocker.

```
   unreadable    an ENTRY's NAME does not parse   → that one entry is preserved forever
   unremovable   an ENTRY's rmSync throws         → that one entry survives, reported
   unopenable    the ROOT's readdir throws        → NO entry is reached at all — the
                                                     gate does not run, it does not start
```

**why it is a value and not a variant of the other two:** those two break the reclaim **per entry**,
and the run still reaches every other entry. `unopenable` takes the whole mechanism down at once —
the gate, the arrears check, and the run reclaim all begin with a `readdir` over this one path. it
is the difference between *one fixture is stuck* and *the backstop 4 cells stand on is offline*.

**how it is reached, and it is not exotic:** `chmod 000` on the scope dir; a mode a prior root-run
left; an NFS or container mount that drops; a `tmpfs` remounted read-only; a path that got replaced
by a **file** (`ENOTDIR`). none needs a hostile actor.

**why it does NOT collapse across termination (axis B):** it fires at the **first** `readdir` of a
run's setup, so it precedes every value of B — pass, fail, preempt and interrupt all meet it
identically, and the collapse is total rather than partial. walked as cell **27**, one row.

**the shipped contract:** report and **carry on** — `pruneStale` catches, names the path, the
`errno` cause, the fix, and *"until then temp dirs accrue there, reclaimed by no mechanism"*, then
returns. it does **not** fail the run: a scope the process cannot read is the human's to repair, and
a broken build over it would take a consumer's suite down for a disk concern — the same trade
`case=6` `[t2]` and `case=9` each settled the same way.

#### 🔴 `absent` — declared and barred, so the axis is a CLOSED set

> the rule's absent-axis check names *"resource-absent states"* by name. to declare axis H and then
> omit the very value the checklist names is the same defect one level down — **a value outside the
> set is a value the walk did not protect, exactly as a cell outside the product is.**

`absent` splits into two, and they are settled differently:

| the absence | verdict | why |
|---|---|---|
| **an absent ENTRY** — no dir carries this run's id | **not a distinct state — it is the healthy RESULT** | every reclaim's success condition is `{ run: R } === 0`. it is the *outcome* axes A–G already measure ([case=1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md) asserts it directly), never a condition a run could begin in. to walk it as an H value would double-count region 1 entire |
| **an absent contained DIR** — `.temp/` itself does not yet exist | **impossible by nature** — but see the reconciliation below | `genIsolatedTempInfra` creates the dir, its `readme.md` and its `.gitignore` **before** it returns a path (`genIsolatedTempInfra.ts:61-76`). so no reclaim, gate, arrears check or clamp can ever observe its absence — by the time any of them holds a path, the dir is there. the reclaim over it would be **vacuous**, and vacuous is unreachable rather than untested |

##### 🔴 the reconciliation — absence is barred, UNREACHABILITY is not

the bar above is **correct on its own terms**: the dir is created before any path is handed
out, so its *non-existence* is genuinely unobservable. what the bar must never be read to imply is
the part that is wrong:

> *"no reclaim, gate, arrears check or clamp can ever observe its absence"*
> — read as: **a mechanism that holds a path can always reach the dir behind it.**

it cannot. **`unopenable` is the reachable twin of the barred state** — the dir exists, so `absent`
stays barred by nature; the dir will not open, so every mechanism behind that path is down anyway.
the *effect* the bar dismisses as impossible arrives through a door the bar never checked.

| | `absent` | `unopenable` |
|---|---|---|
| does the dir exist? | no | **yes** |
| observable by a mechanism that holds the path? | **no** — creation precedes the path | **yes** — `readdir` throws at it |
| verdict | **barred, by nature** | **walked** — cell 27 |

⚠️ **the lesson:** *a bar must be argued against the STATE it names, never against the CONSEQUENCE
that state would have.* to bar `absent` because the dir cannot fail to exist is true — to take that
as settlement of *"the reclaim always reaches its dir"* is a strictly larger claim and a false one.
**when a bar's reason reaches past its own value, the reach is where the next reachable cell hides.**

**so `absent` yields no region-7 cell**, and that is stated outright rather than left silent. the
distinction that matters: the first is barred as a **double-count** (it is already covered, under a
different axis), the second as **impossible by nature** (the code makes it unreachable). a reader
can tell that the gap was considered rather than skipped, which is the whole of the rule's
*barred-with-reason* check.

⚠️ **the lesson:** *a repair made in response to an absent-axis blocker must re-run the same
checklist against the axis it just added.* to declare H's three notable values and stop, because
the two blocker cells (18, 21) are covered, lets the **blocker's** scope set the **axis's** scope —
and an axis is a closed set or it is not an axis.

**why an axis:** the reclaim's contract is *reach, then identify, then remove*. each value breaks a
different stage of it — `unopenable` breaks **reach**, `unreadable` breaks identify, `unremovable`
breaks remove — and each has a distinct victim, a distinct signal, and a distinct fix:

| value | who it hurts | the demo |
|---|---|---|
| `sound` | no one | every region-1 cell |
| `unreadable` | **the age gate**, silently — the backstop 4 cells lean on | [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md) |
| `unremovable` | **the run's own report** — silent-partial | [case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md) |
| **`unopenable`** | **every mechanism at once** — gate, arrears check and run reclaim each open with the same `readdir` | `autoprune.messages` `[case11]` |

> ⚠️ **a contract stated as *"identify, then remove"* drops the first stage, and the absent stage is
> exactly where a value hides. a two-stage contract admits two failure values; a reader who counts
> stages counts the axis.** state the whole pipeline and the axis enumerates itself.

**why orthogonal:** an entry can be unremovable under any hooks, any termination, any coverage, any
concurrency. the state is a property of the **filesystem**, not of the run.

**what the walk yields that the free-list did not** — the product `4 resource-state × 4 termination`
surfaces one pair neither case demonstrates:

- 🔴 **`unremovable × preempted`** — the teardown meets a stuck dir *and* is torn down mid-report.
  the residue survives (as `case=9` intends) but the **report never prints**, so the human learns
  of it only from `case=12`'s arrears check on the next run — which reports *"a teardown never
  ran"*, not *"a dir would not delete"*. **it is the FOURTH row of `case=10`'s seven-cause table,
  with a message of its own.** walked as cell **25**, itemized.
- ✅ `unreadable × *` collapses — the age gate's blindness does not vary by how a run ended
- ✅ `unremovable × pass|fail` is one cell (`case=9` demoes it), since both exit normally
- ✅ **`unopenable × *` collapses totally** — cell **27**. it fires at the run's **first** `readdir`,
  which precedes every value of axis B, so no termination can reach a different outcome

### I. adopter-goal — what the human who wires this up wants to do (4)

> region 4's cells are a **walked axis**, never a free list, because *the adopter* is an actor with a
> goal set, and a goal set is a dimension. it is crossed with **axis J** below, which is what gives
> the two refusal cells a home in the product.

| value | sense | demo |
|---|---|---|
| `wire` | make the reclaim run at all | [case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md) |
| `verify` | prove the leak is closed, without a hardcoded path | [case=8](./1.vision.experience.case=8.clamp-derives-the-path.md) |
| `diagnose` | understand a residue the reclaim could not take | [case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md) |
| `retire` | delete the prune machinery they already hand-rolled | [case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md) |

**why an axis:** the wish's `.why` states the acceptance signal for the choice of repo as
*"downstream should end with **no** temp-dir prune machinery of its own"* — which is the `retire`
value, and a walk without this axis has no cell for it at all. an actor's goals are enumerable, so
they are walkable; the claim that *"only a re-walk of the actor protects region 4"* is an admission
of a free-list, not a property of the domain.

**why orthogonal:** an adopter pursues any goal under any runtime state.

### J. precondition — whether the state the goal needs is present (2)

> 🔴 axis I alone walks only goals **served**. a walk that stops there has no cell for the two
> attempts this contract **refuses** — and execution ships a bespoke `throw` for each, so the
> catalog owed both a row. per `rule.require.experience-catalog-evolution`'s backward direction, a
> tested experience outside the catalog is a blocker.

| value | sense |
|---|---|
| `met` | the contract's precondition holds — the assumed default of axis I's four cells |
| `unmet` | a precondition is violated, so the behavior must choose: **refuse**, or guess |

**why an axis and not two appended rows:** *"a cell outside the product is a cell the walk did not
protect"* is this file's own thesis, applied to itself. the two refusals are a **pair**, not a
coincidence, and what they share has a name: an adopter pursued a declared goal from a state the
contract does not accept. once that is a value, the pair falls out of `I × J` rather than surviving
by memory.

**why orthogonal to I:** every goal has preconditions; whether they hold is independent of which
goal is pursued.

**the walk — `4 goals × 2` = 8 raw, 2 survive:**

| goal × `unmet` | what the precondition is | outcome |
|---|---|---|
| `wire` | `TEST_FNS_RUN` is ours to mint, or absent | **cell 16b** — refuses, `BadRequestError` |
| `verify` | the derive is called inside a checkout | **cell 17b** — refuses, `UnexpectedCodePathError` |
| `diagnose` | — | **void**: the residue report renders over whatever audit it is handed; there is no state it refuses |
| `retire` | the hooks are wired before the hand-roll is deleted | **collapses** to cells 14/15 — an adopter who retires with no hooks in place is simply `unhooked` on axis A, which is already walked |

**the completeness claim:** with H, I and J declared, **every cell in the inventory is a point in
some declared axis's product.** a claim of *complete by construction* holds only while no cell is
added by hand outside the grid — and that is the whole reason these axes exist rather than a tidier
inventory.

## the product

the **runtime** product is
`5 hooks × 4 termination × 2 coverage × 2 concurrency × 2 keep-intent × 2 attendance` = **320
cells**, taken over `resource-state = sound`, `invocation = once`.

the **three** axes that do **not** multiply that number, and why:

| axis | why it does not multiply |
|---|---|
| **F. invocation** | axes A–E are defined *within* one invocation. `session` and `absent` each collapse the whole runtime product to a single experience (collapse 4) |
| **H. resource-state** | `unreadable`, `unremovable` and `unopenable` collapse across termination (collapse 6), except the one pair the walk surfaced — `unremovable × preempted`, cell 25 |
| **I. adopter-goal** ×<br>**J. precondition** | their `4 × 2` product is a **separate space** — an adopter's goal is not a point in a run's runtime state. the pair is walked in region 4 rather than crossed with the runtime product |

> 🟠 **a header that disagrees with its own rows is a class of defect, not a slip.** it has been met
> at region 1, at region 2, at axis A, at the demoed row, and at this section's own count.
>
> **the cause is structural, not careless:** a count in prose is a **copy** of a fact the table
> holds, and every copy goes stale independently of its source. markdown cannot derive one from the
> other, so the only defenses available are (a) state both quantities where they genuinely differ,
> and (b) **treat any prose count as a site to re-check whenever its table changes** — which is
> written down rather than left to attention.

> **a product figure that lags its own axes is the exact false-completeness this decomposition
> exists to prevent**, so the count is recomputed whenever an axis widens.

the raw product is over-ceremony, and most of it is genuine redundancy rather than laziness. **six**
collapse rules — each a real discovery, not a shortcut — reduce it to the distinct cells the
inventory walks:

### collapse 1 — `attendance` × `keep-intent` is not a free square

`unattended × hold` is **a real experience the behavior must bound**: a run with no human to inspect
the fixtures should not hold them silently. no guard stops a consumer who exports the keep flag in
CI, so this is attemptable — the behavior must bound it and say so, or CI becomes an unbounded disk
leak that no teardown ever reclaims.

> 🟠 ***bounded by nurture* is the wrong words for cell 13** — it borrows the vocabulary the mandate
> reserves for **barred** cells. cell 13 is barred by no one: it is attemptable, reachable,
> tolerated, and **demoed** at `case=6` `[t2]`. *"the behavior must bound it"* is a **requirement on
> execution**, and a requirement is not a verdict — a distinction the inventory's own legend states,
> and the reason its verdict column holds the mandate's four values.

> the settled verdict is **bound loudly, proceed, exit 0** — never *reject* (yield register row 2,
> demoed at `case=6` `[t2]`). a refusal would kill the one legitimate use: a human who debugs a
> CI-only flake, which is exactly when a fixture cannot be reproduced locally.

this is the latent-axis payoff the decompose brief predicts: **`attendance` was not visible until
the grid forced `ci × hold`.** the free-list would have shipped the escape hatch with no CI guard.

### collapse 2 — `unhooked` flattens `termination` and `keep-intent`

with no framework hook, no reclaim runs at all. so `unhooked ×` **every** termination value —
`pass`, `fail`, `preempted`, `interrupt` — **and every coverage value** is **one** experience:
*no dir is reclaimed, the age gate is the only backstop*. the sole variable is whether the consumer is
**told**.

`unhooked × hold` **collapses into `unhooked` too** — there is no reclaim to opt out of, so the flag
changes no outcome.

> 🟠 **that pair is not *impossible by nature*.** the attempt is entirely possible: a consumer
> exports `TEST_FNS_KEEP` with configs they never wired. what is impossible is for the flag to
> **change** the outcome, and an unchanged outcome is a collapse. a sentence that sits inside a
> section titled `collapse 2` and calls its own subject impossible contradicts the title three lines
> above it.
>
> **the confusion to guard against:** *"the behavior cannot distinguish this"* is a statement about
> the **outcome space**, while `impossible` is a claim about the **attempt space**. they coincide
> only when nature bars the act itself — which is true of exactly one item in the whole walk, the
> absent contained dir. cells 12 and 13 are this same confusion, one region over each.

**`broken` collapses the same way, for a different reason.** a wired-but-broken run also reclaims
no dir under any termination value — but its *cause*, its *fix*, and its *verdict* differ from
`unhooked`, so it is its own cell, not a fifth row of this one. see
[case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md).

🔴 **`halfwired` collapses the same way, and for the same reason as `broken`.** neither of its
directions reclaims a dir under any termination or coverage value, so the runtime product flattens;
but its cause (*one config key*) and its fix (*add the named other one*) are its own, so it yields
**two** cells rather than a row of this one — cells **28** (setup only) and **29** (teardown only).
the two do not merge into each other because each strands a different half of the mint→reclaim chain
and speaks a different sentence. see axis A.

> ⚠️ **the fifth axis-A value RAISES the raw product and adds two cells — +64 points, +2 distinct.**
> the product formula multiplies the full axis, so a fifth value takes it to
> `5 × 4 × 2 × 2 × 2 × 2` = **320**. all 64 new points then collapse under this rule to the two
> cells above, exactly as `unhooked`'s 64 collapse to two and `broken`'s to one.
>
> **that ratio is the axis's own signature, and it is worth a reader's notice:** three of the five
> hooks values contribute **5 cells out of 192 points**, while `jest` and `vitest` contribute the
> rest. a config state either works — and then every runtime axis matters — or it does not, and
> then only *which way it is broken* matters at all.

### collapse 3 — `jest` and `vitest` differ only at the hooks seam

once the run id is minted and the teardown is called, the reclaim is runner-agnostic — it reads a
directory and matches names. so the two runners generate **one** experience per
`termination × concurrency × keep-intent` cell, and diverge only in axis A's own adoption
experience (which keys a consumer wires, and how many).

this is a **claim the execution stage must clamp**, not an assumption to rest on. if it fails, the
two runners split back into separate rows.

### collapse 4 — `session` and `absent` each flatten the WHOLE runtime product

> 🟠 **a collapse rule states no number at all.** the product is stated once, in
> [the product section](#the-product), and every other mention is a copy that goes stale
> independently of its source — and a collapse rule is read as the current ruleset rather than as
> history. a collapse rule needs only the *claim* that the axis flattens the product entire, which
> survives any later change to what the product is.

- **`session`** — a watch invocation is *one* mint, *one* marker, *one* reclaim, regardless of how
  many times it re-runs inside. under a **clean** termination every A–E value behaves exactly as it
  does under `once`; only the **unit** the guarantee is measured in changes. so it is **one** cell
  for the clean half, whatever the product's current size — **plus one sharp variant, split out
  below.**

#### 🔴 the sharp variant collapse 4 does NOT flatten — `interrupt × session` (cell **22b**)

> it is a genuine hole rather than a repair of prose. the flatten claim *"every A–E value behaves
> exactly as it does under `once`"* **is false for a sharp termination**, and the falsity is in the
> direction of a larger residue:

```
   interrupt × once      →  one run's dirs stranded            (cell 4)
   interrupt × session   →  FORTY re-runs' dirs stranded       (cell 22b)
                            ── one marker, one id, N re-runs' worth of allocation
```

the mechanism is exactly why: the session mints **one** id and holds **one** marker across all N
re-runs, so its accumulated dirs are the sum of every re-run inside it — and a `SIGKILL` at re-run
40 strands all forty re-runs' fixtures at once. cell 22's stated reason, *"bounded and loses none"*,
is true **only of a session that ends normally**; carried across a termination it does not survive,
it reads as a guarantee.

| | verdict | feel | care |
|---|---|---|---|
| **22** — a session that ends cleanly | **itemized** | happy | **alterpath** — bounded, loses none |
| **22b** — a session **interrupted** mid-flight | **itemized** | ⚡ **sharp** | **alterpath** — see below |

> 🔴 **22b may NOT be filed `demoed by subsumption` at case=4 — the subsumption is false.** case=4's
> every step is a single invocation (`[t4]` mints `mintScopedRun()`); **no step anywhere mints a
> session.** so that demo never exercises `session`, which is the one axis value 22b differs from
> cell 4 on — and the catalog's own falsifiability Part 2 demands exactly that value be exercised.
> it cites a **file** besides, never a step, so the check cannot even be run.
>
> *"cell 4's mechanism is cell 22b's entire mechanism"* is a **claim about the design**, which is
> precisely what a demo exists to test rather than to assume.
>
> ⚠️ **the pattern to watch:** *a cell is split because it is distinct, then covered with a demo of
> the cell it was just declared distinct from.* those are contradictory claims, and **the split is
> the moment the check must fire** — which is the moment the two look most alike.

**what the subsumption would need, and does not have.** cell 4's mechanism is *plausibly* cell
22b's entire mechanism — the marker is unsettled, the process is gone, the arrears check names it,
the age gate floors the residue, and no new guard, message, or state is obviously owed. what differs
is a **magnitude**. but a magnitude claim over an **unwalked axis value** is still a claim, and the
three facts it rests on are tested by no demo:

1. a session writes **one** marker at `globalSetup` — never one per re-run
2. the arrears report names the **session**, and its N-accumulated count
3. N re-runs' dirs all carry the **one** session id, so one filter takes them all

each follows from the design as stated; not one is observed. so 22b is **itemized** with that gap on
record, and the probe is filed at **register row 26**. a session-interrupt demo would be the stronger
answer — it is not owed by an alterpath, and to write one that mints a session no adapter yet defines
would be to demo an imagined mechanism.

**and the care grade, freq × cost first:**

- **frequency** — a watch session is common, and a `ctrl-c` out of one is arguably *more* common than
  out of a single run: a human in watch mode ends the session by hand every time. but a clean `ctrl-c`
  is a `SIGINT`, which the teardown **can** answer; only a `SIGKILL` or a hard crash reaches this
  cell. rare.
- **cost** — it **leaks, never loses**, and the leak is bounded by the same age gate as cell 4 —
  N times larger, but N × bounded is still bounded. and it is **never silent**: the next invocation's
  arrears check names it, exactly as it names cell 4's. so this is a *scale* on cell 4's cost, not a
  new *kind* of cost.

low freq × bounded, non-silent cost → **alterpath**. it would be a critipath if the residue were
unbounded or the report absent, and it is neither.

⚠️ **the lesson, and it is the one worth a carry out of this collapse:** *a collapse rule is a claim
of equivalence, and an equivalence must be checked against every value of every axis it crosses —
the sharp values above all.* `session` checked against the happy path of A–E and generalized is how
the hole opens. the sharp values are exactly where an equivalence breaks, and exactly where a reader
most needs to know it did.
- **`absent`** — a non-runner caller has no hook of any kind, so termination, concurrency,
  keep-intent, and attendance are all moot: no reclaim exists. **one** cell. it is `unhooked`'s
  cousin (collapse 2) with one sharp difference — an unhooked *test* consumer can wire the hooks,
  while an `absent` caller cannot, so a notice that names that fix is noise to them.

a third cell falls out of `once` itself once F is declared: **parallel invocations inside one
command** — cell **24**. it is mechanically cell 5 (peer-parallel) reached far more cheaply than by
two humans, so it is **demoed by subsumption** at [case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)
`[t5]` rather than in a case of its own — and it is a **critipath**, since its loss profile is
cell 5's.

> 🟠 **cell 24 is `demoed by subsumption · critipath`, never `itemized`**, and one artifact must not
> state two verdicts for one cell. `itemized` is the graver of the two to leave in place: it reads
> as *a real experience deliberately not demoed*, which is precisely the promise a critipath may not
> make.
>
> **and cell 24's demo needs a step, not a file** — `[t5]` asserts the two runs mint **different**
> ids despite one parent process and one cwd, which is the property this cell exists for and the
> only mark that distinguishes it from cell 5.

### collapse 5 — `coverage` collapses against every termination EXCEPT the two that kill the teardown

**the reclaim is a config hook, not a test**, so no scope filter can deselect it — that is
`case=3`'s whole result. so `scoped` changes *which fixtures exist to reclaim*, never *whether the
reclaim runs*:

| the pair | collapses? | why |
|---|---|---|
| `scoped × pass` | ✅ into cell 1 | the teardown runs; fewer fixtures, same verdict |
| `scoped × fail` | ✅ into cell 2 | same |
| **`scoped × preempted`** | 🔴 **NO** | both halves attack the teardown, from opposite ends: scope narrows what it would reclaim, force-exit stops it outright. **and this is the repo's default invocation.** walked as cell **3b** |
| **`scoped × interrupt`** | 🔴 **NO** | the residue is a *scoped subset* that carries an id which looks live, the exact `1,786 orphan` shape. walked as cell **3c** |

**the general rule this collapse teaches:** a coverage axis collapses against outcomes that leave
the mechanism intact, and does **not** collapse against outcomes that attack the mechanism itself.
a five-value axis B could express neither un-collapsed pair, which is precisely the defect.

> 🔴 **the two exceptions above are scoped to `solo`.** the exceptions' ground — *both halves attack
> the teardown* — is a claim about **our own run's reclaim**, so it is silent about the peer. and
> what `peer-parallel` adds is peer-safety, which is a property of the **name**, fixed at
> allocation, so it reads neither coverage nor termination (`case=5`).
>
> so under `peer-parallel`, coverage **does** collapse: the scoped branches of cells 8c and 8 add no
> distinct experience and fold into them. per the rule that *a fold is a coverage claim that owes
> evidence*, `case=5` `[t4]` mints its force-exited run **scoped**, so the demo exercises the fold.
>
> **the lesson, and it is about the shape of an exception rather than this cell:** an exception
> carved on one axis pair must state **which other axes it holds across**. an exception that does
> not lets a third axis cross it and produce a combination with no verdict — the silently-absent
> cell a walked product is supposed to make impossible.

### collapse 6 — `resource-state` collapses across termination, with one exception

- **`unreadable ×` every termination** collapses to one cell (21): the age gate's blindness to an
  unparseable name does not vary by how the run ended — the gate runs later, from a different
  process, and sees only the name.
- **`unremovable × pass|fail`** collapses to one cell (**26**): both exit normally, so the reclaim
  runs, meets the stuck dir, and reports — `case=9`.
- 🔴 **`unremovable × preempted` does NOT collapse** — cell **25**. the reclaim meets the stuck dir
  *and* is torn down mid-report, so the residue survives but **the report never prints**. the human
  learns of it from `case=12`'s arrears check, whose message would be *"a teardown never ran"* —
  true, and the wrong diagnosis. **so it is the FOURTH row of `case=10`'s seven-cause table, with a
  message of its own** — one that sends the reader to the filesystem rather than to the wire-up,
  which is the opposite of every other arrears message. the `partial` marker state (yield register
  row 24) is what carries the discrimination, along with the residue path and its `errno`.
- `unremovable × interrupt` collapses into cell **4**: the reclaim never began, so the dir's
  removability was never tested. it is residue like any other.

> 🔴 **why `unremovable × interrupt` is cell 4 rather than a fold into cell 25.** cell 25 rests on
> the marker's **`partial`** state, which means *"the teardown BEGAN and was torn down mid-report."*
> under `interrupt` the teardown **never begins**, so the marker stays **`open`** — a different
> state, a different message, a different cause row in `case=10`'s table. a claim that *"a SIGKILL
> mid-report has the identical outcome"* is simply false: the two are settled differently by the
> very state machine cell 25 introduced.
>
> and `unremovable × pass|fail` is cell **26**, never cell 18 — 18 is the adopter *goal* under
> axis I.
>
> **the general shape:** when a repair splits one cell into two (18 → 18 + 26) or introduces a new
> state (`partial`), **every artifact that cites the old cell numbers is stale until swept** — and a
> reader who meets two classifications cannot tell which holds, which is exactly the checkability
> this rule exists to protect.

## a note on the actor

there is one actor with two hats, not three actors:

- the **consumer developer** — writes tests that call `genTempDir`, and lives with the residue
- the same person in an **adopter** hat — wires the config once per repo, writes the clamp that
  measures the guarantee, and **retires whatever prune machinery they already hand-rolled**
  ([case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md))

> the adopter's goals must be an **axis**, never a free list — a free-listed region is exactly the
> region that loses a member.
>
> 🔴 **the free list itself is the defect.** the argument that *"region 4's goals are not points in
> the runtime axes' space, so no product arithmetic would have surfaced the gap — only a re-walk of
> the actor protects region 4"* is an **admission of a free-list dressed as a property of the
> domain**. an actor's goal set is enumerable, so it is walkable: it is simply a **different space**
> from the runtime state, not an unwalkable one. it is declared as **axis I. adopter-goal** and
> walked like any other.
>
> **the lesson:** *"this does not fit the grid"* is a claim that needs the same scrutiny as any
> other. twice in this vision it meant *"I have not yet found the axis"* — once for the adopter's
> goals, once for the resource states (axis H).

`attendance` (axis E) captures the only *behavioural* difference a `ci` actor would have added, so
a separate `system` actor row would be a duplicate axis, not a new one. the library maintainer is
not an actor here — they author the behavior, and their concerns land in the vision's evaluation,

this file states *how the space is cut*, so every collapse rule necessarily quotes a verdict whose
home is the inventory or a case file. it is the highest-copy-density artifact in the set, and
therefore **the one that goes stale by other files' edits** rather than by its own — the identical
property `case=11` carries among the demos, and the identical caution that file gives its next
author. a collapse rule frozen at the moment before its own home changed is the shape this takes:
a rule that still calls a cell `itemized` a regrade later, or still asks for a message that already
landed.

> **a fact stated in two places is a fact that will disagree with itself.** when a verdict is
> regraded or a work item lands, its copies here must be **deleted or turned into citations** —
> never annotated, never left for a later sweep. a text sweep catches the instance; only the
> question *where does this fact live?* catches the class.
