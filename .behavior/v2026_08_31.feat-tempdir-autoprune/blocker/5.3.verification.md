## the lessons, for the next traveler

1. **an overflowed lane is a task, never a verdict.** a `constraint` renders no verdict, and an
   absent verdict looks exactly like a clean one.
2. **read `tokens.expected.md` before you call an overflow structural.** the reviewer writes it on
   every overflow and prints the path.
3. **`--goal representative` is the DEFAULT and it SAMPLES.** four lanes read `0/0` under it; the
   same rubrics under `exhaustive` held 2 blockers and 5 nitpicks.
4. **`--paths-with` alone silently drops the `--diffs since-main` default** — `intersect` against an
   empty diff set resolves to zero files and reports `all clear`. pass `--diffs` explicitly, then
   read `input.scope.debug.json`.
5. **a filed issue is not a spent lever.**
6. **check what is IN a subject before you argue it cannot shrink.** a quarter of the first one was
   a process artifact the repo's own convention already said should not be tracked; a further large
   share was a rule violation the driver owned.
7. 🔴 **when a rubric names its own subject, scope to THAT — and it usually names it in `.how`.**
   four token-weight reductions failed or risked a false clean; the rubric's own declared subject
   (`src/**`) ran at **38.6%** where the whole branch sat at 85.2%. *before you trade coverage for
   tokens, read what the rule says it grades.*
8. 🔴 **`--paths-wout` takes ONE glob.** a comma list and a brace set each match no file, silently,
   and the tell is that the reported subject gets **bigger**. always read the file count.
9. 🔴 **re-measure a remedy before you re-assert it.** this record carried *"one exclusion takes the
   gate from failed to passed"* — true when written, **false today** at 76.1%. an escalation that
   quotes a stale measurement hands the human a fix that no longer works.
10. 🔴 **a lane that gets WORSE on re-run is the lane at work.** r4's second scoped pass raised a
    blocker its first had not, on the wish's own acceptance signal. *a verdict that only ever
    improves is a verdict you should distrust.*
11. 🔴 **verify a claimed ACT and a cited NUMBER, not merely a measurement.** lesson 9 catches a
    stale measurement; this catches a stale *deed* and a wrong *pointer*. one pass with
    `gh issue view <n>` found **both** in this record: *"filed as new evidence on #424"* (the issue
    is open with **zero comments** — an intent written in the past tense), and an upstream table in
    which **two of three issue numbers named the wrong issue**. neither error looks uncertain on the
    page; both are one command from disproof. *quote the title beside the number, so the next reader
    re-checks in one command rather than trusts you.*

12. 🔴 **a HUMAN-GATED row is the one kind that goes stale in silence, so it owes a re-measure at
    WRITE time.** key 1 of this record — the stage grant — was asserted open, in the present tense,
    with the exact command to run, while `git status` had already read `A ` for all seven files. a
    `[research]` row is re-run by whoever owns it and cannot drift unseen; a row that waits on a
    human waits with no signal either way, so **the absence of news is not evidence the wait is
    still real.** lesson 9 says re-measure a remedy and lesson 11 says verify a deed; this is the
    third face of the same rule, and the one most likely to survive several rounds unchallenged
    *because an awaited human key is exactly the kind of item a driver stops to re-check.*
13. 🔴 **a clean verdict expires when the diff does.** the four lanes were driven to `0/0`, then the
    diff moved — a grammar change, a branch collapse, a RESNAP gate. a re-run at the same scope
    raised **2 fresh blockers**. *a verdict is a measurement of a subject, and it is stale by exactly
    the amount the subject moved since. re-run the lanes after the last repair, never before it.*

14. 🔴 **"is this act permitted?" is a QUERY, not a judgment.** key 3 of this record read *"a
    shared-state act, so it waits on a word"* — sound in general, and never checked against the
    permission system, which reads `allowed` at every level. the seed had been granted before the
    drive began. worse than lesson 12's stale row: **that one was true once; this one was false when
    written**, in a paragraph three sections below the lesson that names it. *every shared-state act
    here has a surface that answers it — `rhx radio.uses get`, `rhx git.commit.uses get`,
    `route.stone.set --help`. run the query before you write the word "waits".*
15. 🔴 **a verdict you dislike may be an ARITHMETIC artifact, and the tell is that it names no
    location.** two rounds recorded `rejected` on reviews whose own text raised zero blockers — one
    counted the word inside a clause that denied it, the other counted two numerals inside a citation
    of a 23-round-old *already-fixed* verdict, with a valid `Verdict: 0 blockers, 0 nitpicks` line
    four lines above. **a review with a real blocker names a file, a line, and a fix.** if the tally
    says three and the prose cites none, answer with a `.taken` that quotes both — *a repair invented
    to clear a phantom count enters the diff, widens the subject every other lane grades, and answers
    nobody.*

16. 🔴 **a permission meter moves in BOTH directions, so query it at WRITE time — not once.**
    lesson 14 says *"is this act permitted?" is a query, not a judgment*, and was written after a
    row sat on this list that was never gated. hours later the same meter read `global: blocked`,
    so the row is a key again — **wrongly listed, correctly struck, correctly re-listed, in one
    day.** a query answers only for the instant it is run, and a human can turn the meter between
    your read and your act. *the rule is not "check once and record"; it is "check at the moment
    you write the claim, in both directions" — a discharged key and a newly-gated one are equally
    invisible until you look.*
