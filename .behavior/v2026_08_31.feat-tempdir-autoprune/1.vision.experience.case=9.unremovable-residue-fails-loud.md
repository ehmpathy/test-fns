# case=9 — an unremovable dir fails loud, with the residue named

> cell 18 · the adopter's seam · **feel** ⚡ **sharp** · **care** critipath — silent-partial is
> the exact failure mode this wish exists to end

## the narrative

kai's suite made 432 fixture dirs. one of them holds a file a subprocess still has open, or a
read-only path a `git init` produced, or a mount kai's container cannot unlink.

the reclaim removes 431 of them and cannot remove the 432nd.

```
$ npm run test:integration
  Tests: 118 passed, 118 total

⛈️  test-fns could not reclaim 1 of 432 temp dirs

   reclaimed: 431
   residue:   1
     └─ /tmp/test-fns/test-fns/.temp/2026-08-31T14-22-01.443Z.r7f3a91c2.git-test.a1b2c3d4
        EACCES: permission denied, rmdir

   the other 431 were reclaimed. this one was not.
   remove it by hand, or let the age gate take it in 7d.
```

> 📏 `432` / `431` / `118` are **illustrative**, not measured — see
> [case=1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md)'s note. the bdd below
> asserts against a **measured** `dirsMadeByRun`, never a literal.

kai sees it, and knows exactly which dir and exactly why.

## ⚠️ loud, but NOT fatal

*fail the run, or report at exit-zero?* is not an open question here. **the vision decides this
class**, in [case=6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md) `[t2]`:

```gherkin
    then('the run does not fail the build over it', () => {
      // loud, not fatal: a leak is not worth a broken pipeline
      expect(exitCodeOf(RCi)).toEqual(0);
    });
```

> 🟠 **a quote of another artifact is a copy, and it goes stale exactly as a count does** — worse,
> it looks like evidence. a quote that cites `case=6` to settle a decision inherits every later move
> `case=6` makes.
>
> **so the verdict word stays out of the argument entirely.** what this passage needs from `case=6`
> is its `exit 0` and its reason, both quoted above and both stable. a verdict word is decoration
> that has to be re-checked whenever its source moves. for the record: cell 13 is **`demoed`**, and
> what it demoes is a tolerated, loudly-bounded leak.

that cell is a hold left on in CI, which `case=6` `[t2]` tolerates at `exit 0` over an **unbounded**
leak in the highest-volume environment. this cell's residue is **one dir**, bounded by the age gate.
so a non-zero exit here would fail a build over one dir while it passes a build over an unbounded
leak.

| | case=6 cell 13 | case=9 (this cell) |
|---|---|---|
| the residue | **unbounded** — every dir of every CI run | **one dir** |
| its reclaim | the age gate only | the age gate, in 24h |
| the inconsistent pair | loud, **exit 0** | loud, **exit ≠ 0** ← inconsistent |
| the settled verdict | loud, exit 0 | **loud, exit 0** |

**and the tie-break is not merely consistency.** an `EACCES`/`EBUSY` on one dir is *transient* — a
subprocess that has since exited, a mount that unmounts next boot. a fatal exit converts a bounded,
transient residue into an **intermittent red build**, which is precisely the outcome the vision's
own con names: *"a flake that trains consumers to unwire the hooks"* — which costs the whole
behavior, to guard against the smallest harm it handles.

**`rule.forbid.failhide` does not argue the other way.** it forbids a failure that is *swallowed*. a
named, loud, residue-listed report is the opposite of swallowed. a rule about swallowed failure is
not the rule that applies here.

**what does NOT change:** the *reclaim the rest first, then report* order, and every requirement on
the message's content. the defect this cell exists to prevent is **silent-partial** — and it is the
**silence** that is forbidden, never the exit code.

## why loud, when [case=1] argues for silence

silence is the signal that all is well. **this run is not well.** the contract is precise:

| state | voice |
|---|---|
| reclaimed every dir | silent ([case=1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md)) |
| deliberately held | one notice ([case=6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md)) |
| **could not reclaim** | **loud, residue named, exit 0** |

a reclaim that swallows the failure is `rule.forbid.failhide` in its purest form: the run reports
green, the guarantee is broken, and the leak resumes with no signal. **that is precisely the shape
of the defect this whole wish exists to end** — a hole that stays invisible until it is 12,901
dirs deep.

## the two properties, and their order

they can conflict, so the order matters:

1. **do not abort the batch on the first failure.** one un-removable path must not strand the
   other 431. reap every reachable dir first.
2. **then fail loud, with every residue named.** not "cleanup failed" — the list of paths and the
   reason each one resisted.

this is the `rhx clone prune` safety contract the wish cites as precedent: *never prune what it
cannot verify, fail loud with the residue named.* the mechanism differs; the contract is the same.

reversed, the two properties produce the worst outcome: a throw on the first bad path leaves the
other `N-1` dirs stranded **and** reports a failure — maximum leak, maximum noise, minimum
information.

## the report is shaped like a `MalfunctionError` — but it is REPORTED, never THROWN

per `rule.require.failloud`'s split, the **fault** is server-side: kai made no mistake. kai wrote a
normal test; the filesystem refused. so the report carries a malfunction's shape and a malfunction's
metadata — the residue paths, the count reclaimed, and each path's `errno` — which is what a human
needs without a debug session.

⚠️ **but the run still exits 0, and the two facts are not in tension.** `rule.require.failloud`
governs **who the message addresses**; it does not decide **whether the process dies**. this case
settles the second question at exit 0, for the reason `case=6` `[t2]` settled it first:

> *loud, not fatal: a leak is not worth a broken pipeline.*

a bounded, age-gated residue that fails the build becomes an intermittent red that trains consumers
to **unwire the hooks** — which loses the entire behavior to guard against the mildest of its
failure modes.

> 🟠 **this section must never say *"carries exit code 1"*** — the *loud, but NOT fatal* section
> and `[t1]` both assert `exitCode === 0` in this same file. **a sharp critipath with two
> contradictory fail-safe verdicts is worse than one with none** — execution reads whichever it
> finds first. the confusion is between a rule about **addressee** and a decision about **exit
> code**; they are different axes, and prose must not fuse them.

## the timeline

```gherkin
given('[case9] an enhooked run whose contained dir holds one un-removable entry', () => {

  // ⚠️ the cast, declared up front — every demo owes this, so R, pathPhysical
  //    and pathBad are never free variables.
  const { pathPhysical } = getOneTempDirRoot();
  const R = useThen('a run starts and mints an id', () => mintRun());

  // 📏 the counts below are RELATIVE to a measured total, never a literal.
  //    `432` is invented; `N` and `N-1` say the same and cannot bake a
  //    fabricated constant into a clamp.
  const dirsMadeByRun = useThen('the run makes its fixture dirs', () =>
    countTempDirs(pathPhysical, { run: R }),
  );
  const pathBad = useThen('one of them is made un-removable', () =>
    makeUnremovable(oneDirOf(R)),
  );

  when('[t0] the run allocated N dirs, one of which resists removal', () => {
    then('the un-removable one is genuinely un-removable', () => {
      expect(() => rmSync(pathBad, { recursive: true })).toThrow();
    });
  });

  when('[t1] the global teardown runs', () => {
    // ⚠️ `report` is BOUND here. the four `then`s below read `report.message`
    //    and `report.metadata.*`, so without this step the whole content this
    //    sharp critipath owes — *loud, residue named, exit 0* — would be
    //    asserted against an object that exists nowhere.
    //    a cast that binds every RUN and stops is not enough: a report is a
    //    value the teardown YIELDS, and a yielded value needs a step to yield
    //    it exactly as a run needs a step to mint it.
    //    case=14 [t1] carries the same form (`error = getError(...)`).
    const report = useThen('the teardown yields its residue report', () =>
      runTeardownFor(R),
    );

    then('the other N-1 ARE reclaimed — the batch did not abort', () => {
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(1);
    });

    then('it REPORTS rather than pass silently — loud, but not fatal', () => {
      // NOT `expect(error).toBeInstanceOf(MalfunctionError)`.
      // case=6 [t2] settles this class: "a leak is not worth a
      // broken pipeline". silence is what this cell forbids, not exit 0.
      expect(stderrOf(R)).toContain('could not reclaim');
      expect(exitCodeOf(R)).toEqual(0);
    });

    then('the error names the residue path, not merely a count', () => {
      expect(report.message).toContain(pathBad);
    });

    then('the error names WHY that path resisted', () => {
      expect(report.metadata.residue[0].reason).toContain('EACCES');
    });

    then('the error names how many DID go back, so the human knows the scale', () => {
      expect(report.metadata.countReclaimed).toEqual(dirsMadeByRun - 1);
    });

    then('the error names the fix', () => {
      expect(report.message).toMatch(/remove it by hand|age gate/);
    });

    then('and the report the HUMAN sees carries the same facts as the object', () => {
      // the report is an object AND a printed message. an assertion on the
      // object side alone leaves the human's side unclamped: both must name
      // the residue, or a consumer who reads only stderr gets a count with no
      // path.
      expect(stderrOf(R)).toContain(pathBad);
    });
  });

  when('[t2] a LATER run meets no un-removable entry of its own', () => {
    // ⚠️ this is NOT "the same run", and it must not assert `{ run: R } === 0`.
    //    [t1] leaves `pathBad` on disk and pathBad carries R's id, so R's
    //    population is 1 from that point on — no step removes it, and case=9's
    //    own contract (reap the rest, name the residue, LEAVE it) is exactly
    //    what forbids R from ever counting 0. the healthy case needs its own
    //    run.
    //
    //    case=11 carries a kin of this confusion — *a verdict is not a
    //    population*. here it is **a rerun is not the same run**: an id is
    //    minted once per invocation, so a second run carries a second id, and
    //    the residue the first left stays tied to the first.
    const R2 = useThen('a later run starts and mints its OWN id', () => mintRun());

    then('it reclaims all of its own and says no word', () => {
      // ⚠️ these two are scoped to R2, never bare — this is the one block
      //    whose whole point is that R2 behaves unlike R. an unscoped
      //    `stderr` in a two-run block cannot carry that contrast: it
      //    would be satisfied by R's output as readily as by R2's, and R's
      //    stderr DOES contain 'could not reclaim'.
      expect(countTempDirs(pathPhysical, { run: R2 })).toEqual(0);
      expect(stderrOf(R2)).not.toContain('could not reclaim');
      expect(exitCodeOf(R2)).toEqual(0);
    });

    then('and R\'s residue is untouched — it is R\'s, and it is not yet aged', () => {
      // the healthy case must not quietly reap the unhealthy case's evidence
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(1);
      expect(existsSync(pathBad)).toEqual(true);
    });
  });
});
```

## `[t1]`'s first assertion is the one that inverts naively

the instinct is to assert "the reclaim reported". that alone passes under an implementation that
gives up on the **first** bad path and strands N-1 dirs — the worst outcome, dressed as correct
behavior.

**assert the N-1 first, the report second.** the order of the assertions encodes the order of the
properties.

## the ergonomic bound, and how it is settled

this report must not become a flake source. a reclaim that fails a green suite over a transient
`EBUSY` would train consumers to disable the hooks entirely — which costs the whole behavior, to
guard against a rare, benign residue.

that tension is not a **fulcrum for the wisher**: the vision **already** decides this class, in
`case=6` `[t2]`, for a strictly worse harm. see the *loud, but NOT fatal* section above — the
resolution is **loud, named, exit 0**, and it is consistent across both cells rather than opposite
in each.

> ⚠️ sketch, not proof. the report's carrier is execution's choice — a `console.error` with the same
> `.message` / `.metadata` shape serves; `helpful-errors` is already a dependency
> (`package.json:77`) if a structured object is wanted. what is **fixed** is that the run says the
> words, names the path and the reason, and does **not** exit non-zero.
