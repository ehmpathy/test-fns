# case=10 — the mint chain breaks, and the run says so

> cell 19 · `hooks=broken` — wired correctly, chain silently failed
> **feel** ⚡ **sharp** · **care** critipath — **the linchpin's own failure mode**

> **the seam this case covers.** `howto.experience.enumerate` move 3 — *"a seam: a handoff where one
> part's output is another's input"* — names this one: **globalSetup's env → the worker's env.** so
> the `hooks` axis carries a fourth value beyond `jest`, `vitest` and `unhooked`: **wired, but the
> handoff dropped the id.**

## why this is the most important sharp path in the vision

the wish names this failure mode explicitly, and names why it is the worst one:

> links 1–2 of that chain are jest's *implementation*, not its documented contract. so **clamp the
> chain rather than trust it** — a defect there is silent, and it fails toward *dirs survive under
> a green suite*, which is the exact failure mode this wish exists to end.

**every other cell in this behavior fails in a way someone eventually notices.** this one does
not. kai wires both config keys correctly, upgrades a jest minor version two years from now, the
env handoff changes shape, and:

- every test still passes ✅
- the teardown still runs ✅
- it matches zero dirs, because they carry no id
- it reports success, because it removed all that it matched — which was empty
- the leak resumes, silently, under a green suite, in every consumer at once

that is the 12,369 dirs, reintroduced by a dependency bump, with a green clamp that watches it
happen. **a vision that leaves this cell undemonstrated has an unhandled sharp critipath**, and by
`rule.require.experience-coverage` that is a blocker.

## the narrative

kai upgrades jest. the chain breaks. kai's next run:

```
$ npm run test:integration
  Tests: 118 passed, 118 total

⛈️  test-fns could not reclaim ANY temp dir — the run id did not reach the workers

   this run made 432 temp dirs. 0 of them carry this run's id.
   run id (main process): r7f3a91c2
   a sample dir name:     2026-08-31T14-22-01.443Z.my-test.a1b2c3d4
                                                  ↑ no id here

   the hooks ARE wired, so this is not a config error — the id was minted
   but did not survive the handoff to the test workers.

   this is a test-fns defect against your runner version. please report:
     https://github.com/ehmpathy/test-fns/issues
     runner: jest 31.0.0   node: v22.15.0

   the 432 dirs carry no id, so we cannot target them and neither can you.
   they fall to the age gate in 24h, and that is the reclaim we offer.

   ⚠️  do NOT sweep /tmp/test-fns/test-fns/.temp/* — that scope dir is shared
       with every parallel run in this repo, and an unstamped sweep would take
       a live run's fixtures out from under it. wait out the gate.
```

> 🔴 **the message deliberately offers no reclaim command.** a close of
> `rm -rf /tmp/test-fns/test-fns/.temp/*` is a **wildcard wipe of the shared scope** — precisely the
> peer-reap shape `case=5` demonstrates this design must never perform, and that `case=13`'s
> narrative warns the adopter against in their own hand-rolls. a library whose whole reason to exist
> is *"never reap a peer's live dirs"* cannot hand that command to a human as its recovery.
>
> and such a line is **redundant besides**: the sentence above it already names the age gate, so the
> command buys no reclaim the message has not already promised. it buys only the hazard.
>
> **the general shape, and it is why this is worth a note rather than a quiet edit:** the broken-chain
> state is exactly the state in which *no id-based selector exists* — the dirs are unstamped, so
> there is no safe target to give. a remediation that cannot be written safely should be **withheld
> and its absence explained**, never approximated with a wider one. an over-wide command in an error
> message is `rule.require.errors-name-the-fix` satisfied on the letter and broken on the intent: it
> names *a* fix, and the fix is worse than the fault.
>
> ⚠️ `case=6`'s hold message keeps its `rm -rf "…/.temp"/*.r7f3a91c2.*` — that one is **run-scoped
> by the very stamp this cell reports absent**, so it is safe for the same reason this one is not.
>
> *a cross-reference is a claim about a file you do not own. it can be falsified by an edit you
> never see, and no test you write in your own file will catch it* — which is why the two commands
> are clamped as a **pair**: `case=6` asserts the stamp is in its glob, and this cell asserts no
> scope-wide sweep is offered at all.

kai loses ten minutes and files an issue. kai does **not** lose eight months and 12,901 dirs.

## the fail-safe — a checkable invariant, not a hope

the design cannot *prevent* the chain from breakage; jest's internals are not ours. but it can
make the break **impossible to miss**, and the mechanism is a two-line invariant available for
free at the exact moment it matters:

> **the teardown runs in the same process as the mint, so it always knows the true run id.**
> if a **fresh, unstamped** entry sits in the contained dir while **zero** entries carry that id,
> the handoff is broken.

```
 an entry EXISTS in the contained dir that is
   · newer than this run's start          ← observable: dirent mtime vs our start stamp
   · carries NO run id at all             ← observable: parse the name
 dirs matched by OUR id  ==  0            ← observable: the reclaim's own match count
 ────────────────────────────
 ⇒ the chain is broken. fail loud.
```

> **the first term is an ORPHAN predicate, and never a DELTA.** a delta form — *"dirs made this run
> is above zero — observable: count before, count after"* — silently assumes **the growth of the
> contained dir across our run is OUR growth.** it is not: the dir is a **shared** namespace — that
> is [case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)'s
> whole premise. cross a **scoped run that matched zero files** with a **live peer** and every term
> of a three-term delta form holds while each one lies about us:
>
> ```
>    our run made 0 · matched 0        ← healthy
>    the peer made 300, stamped ITS id ← in OUR contained dir
>    ⇒ grew? yes. ours? none. still present? yes (the peer is alive)
>    ⇒ a MalfunctionError that names test-fns at fault, on a perfectly healthy run
> ```
>
> and `--changedSince=main` is this repo's **default** (`package.json:53,56,59`), so the scoped
> half is the common case rather than the edge.
>
> **the answer is not a fourth conjunct — conjuncts over a wrong population never converge.** the
> orphan predicate is one a peer's dir **cannot satisfy by construction**: a peer's dir carries the
> peer's id, so an *unstamped* entry is excluded from their population and included in ours. that is
> rung 1 of `rule.prefer.prevent-over-correct` rather than rung 3 — the peer is not filtered out,
> they were never in.
>
> it **strengthens** the guard besides: a delta form cannot fire at all on a run that made zero
> dirs, so a broken chain inside a small scoped run goes undetected. the orphan form catches it on
> the first unstamped entry.
>
> **and it folds in a third term.** a third term (*the made paths STILL EXIST*) would separate *a
> break* from *another reclaim took them first*
> ([case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md)). the orphan form
> subsumes it: a hand-rolled teardown that already deleted our dirs leaves **no entry to find**, so
> the first term is false and the guard stays silent — the same separation, by presence rather than
> by a second lookup.

this is what makes the invariant sound: the teardown never has to *trust* the chain it checks. it
sits on the main process's own `process.env`, which is the source the mint wrote to — one hop, not
three. so the check is **independent of what it checks**.

### the symptom has seven causes, and each needs its own message

*"no dir was reclaimed"* is one symptom with **seven** causes. a guard that names one will
confidently misdiagnose the other six:

| cause | the discriminator | who fixes | verdict |
|---|---|---|---|
| the consumer wired no hook | no marker at all — the mint never ran | the consumer | green + a notice ([case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)) |
| **wired `globalSetup` only** (jest's two keys) | marker `open`, and `globalTeardown` absent from config | the consumer | green + a notice ([case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md)) |
| the teardown was pre-empted **before it began** | marker `open`, `globalTeardown` **present** in config | the consumer | green + a notice ([case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md)) |
| 🔴 **the teardown BEGAN, met an unremovable dir, and was pre-empted mid-report** (cell 25) | marker `partial` — the teardown wrote its own start and never settled | the consumer, **but at the filesystem**, never at the config | green + a notice that names **the residue path and its `errno`**, not the wire-up |
| the id did not reach the workers | dirs present, unstamped, marker `closed` | **test-fns** | non-zero + `MalfunctionError` (this case) |
| another reclaim took them first | dirs gone entirely, marker `closed` | the consumer | green + a notice ([case=13](./1.vision.experience.case=13.adopter-retires-their-own-teardown.md)) |
| **a peer's dirs grew the shared dir, and ours made none** | the fresh entries carry **another** run's id — so they are not orphans and were never our population | **no one — it is healthy** | **stay silent** |

> **only ONE of these rows is our defect; the rest must never receive its message.** and note the
> discriminators: the marker's **state** is what separates the pre-empt rows from the reclaim rows,
> which is why the marker needs four states rather than two.
>
> **the peer-dirs row is the only row whose correct verdict is silence** — the other six each earn
> some message. the invariant above handles it **by construction** rather than by that row's
> discriminator, which is why the row reads as a note rather than a branch.
>
> 🔴 **the fourth row comes from cell 25** (`unremovable × preempted`). it is the row whose default
> message **misdirects hardest**: without it, a pre-empted run that was truly an `EACCES` on one
> directory reads as *"a teardown never ran"*, and the adopter audits their config forever while the
> cause sits in a file mode. **it is also the row that fixes the marker's state set**: `open` and
> `closed` cannot express *"the teardown began and did not finish"*, so cell 25 is why a `partial`
> state must exist at all — and the marker must settle to `partial` at the **moment the reclaim
> starts**, never at its end, since a teardown torn down mid-flight gets no second chance to write.

### why it must not be confused with the unhooked case

[case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md) has the same *symptom* (no dir
reclaimed) and the opposite *cause* and *fix*:

| | unhooked (case=7) | broken chain (case=10) |
|---|---|---|
| cause | the consumer wired no hook | the consumer wired correctly; the runtime dropped the id |
| who fixes | the consumer | **test-fns** |
| the message must say | "add these two config keys" | "this is our defect — please report it, with your runner version" |
| verdict | green — no forced migration | **non-zero** — a broken guarantee is a failure |
| error class | a notice, not an error | `MalfunctionError` (`rule.require.failloud`) |

to hand kai case=7's message here would be actively harmful: it tells kai to add config kai has
already added, and blames kai for our defect. **the two cells share a symptom and must never share
a message.**

## the timeline

```gherkin
given('[case10] a repo whose hooks ARE wired, but the id does not reach the workers', () => {

  // ⚠️ R is minted HERE, because [t1] and [t3] both read it and a handle read
  //    in two steps must be bound in the given.
  //    [t0]'s `process.env` assertion does NOT establish a handle.
  const R = useThen('the main process mints a run id', () => mintRunId());

  when('[t0] the main process mints the id', () => {
    then('the id exists in the main process, and it IS R', () => {
      expect(process.env.TEST_FNS_RUN).toBeDefined();
      expect(process.env.TEST_FNS_RUN).toEqual(R);
    });
  });

  when('[t1] the handoff drops it, and the suite allocates dirs anyway', () => {
    // ⚠️ an UNFILTERED delta — `expect(countTempDirs(pathPhysical))
    //    .toBeGreaterThan(countBefore)` — measures growth of the whole SHARED
    //    dir with no run filter, the exact shape this file's own orphan note
    //    declares unsound three paragraphs above. it does not bite in a solo
    //    scenario, which is precisely how such a term survives: a defect that
    //    is correct by accident under the demo's own preconditions.
    then('the dirs were made, and they are OURS — an orphan count, never a delta', () => {
      expect(countTempDirs(pathPhysical, { orphan: true })).toBeGreaterThan(0);
    });

    then('but none carries the run id — the break, observed', () => {
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(0);
    });
  });

  // ⚠️ every handle in this block is run-scoped to R. a bare `error`, `exitCode`
  //    or `stderr` reads as whichever run a reader assumed, and this file has
  //    THREE runs by the end (R, RIntact, RPeer/RZeroScope) — an unscoped
  //    handle in a multi-run file names none of them.
  when('[t2] the global teardown runs and finds the mismatch', () => {
    then('it does NOT report success on an empty match', () => {
      expect(exitCodeOf(R)).not.toEqual(0);
    });

    then('it throws a MalfunctionError — this is OUR defect, not the caller\'s', () => {
      expect(errorOf(R)).toBeInstanceOf(MalfunctionError);
    });

    then('it names the two numbers that prove the break', () => {
      expect(errorOf(R).metadata.countMade).toBeGreaterThan(0);
      expect(errorOf(R).metadata.countMatched).toEqual(0);
    });

    then('it does NOT tell kai to wire hooks kai already wired', () => {
      // .note = the anchor is the unhooked notice's own first line, so this
      //         asserts the ABSENCE of that whole message rather than of a phrase
      //         that appears in neither. an anchor like `'hooks are absent'` —
      //         a phrase the shipped notice never carries — could never fail
      expect(stderrOf(R)).not.toContain('never reclaimed here');
    });

    then('it names the runner version, so the report is actionable', () => {
      expect(stderrOf(R)).toMatch(/jest|vitest/);
      expect(stderrOf(R)).toContain(process.version);
    });

    // ⚠️ asserted as a STEP rather than left to the prose note above it — a demo
    //    is repaired by a step, never by a note about the step.
    then('it offers NO scope-wide sweep — the peer-reap this design forbids', () => {
      // the dirs are unstamped, so no safe selector exists. we say that, and
      // we hand over no command at all rather than a wider one.
      expect(stderrOf(R)).not.toMatch(/rm -rf \S*\.temp\/?\*?\s*$/m);
      expect(stderrOf(R)).toContain('do NOT sweep');
    });

    then('and it names the reclaim that IS safe — the age gate', () => {
      expect(stderrOf(R)).toMatch(/24h|age gate/);
    });
  });

  // ⚠️ the control mints its OWN id. to read `{ run: R }` here — where R is the
  //    run whose chain BROKE at [t1] — reads as "the same run, but now well". a
  //    healthy run is a NEW invocation with a NEW id: a rerun is not the same
  //    run, the same conflation case=9 [t2] and case=13 [t0] each guard against.
  when('[t3] a LATER invocation, whose chain is INTACT, runs the same suite', () => {
    const RIntact = useThen('it mints an id that DOES reach the workers', () =>
      mintRun({ chain: 'intact' }),
    );

    then('no such error appears — the invariant does not false-positive', () => {
      expect(errorOf(RIntact)).toEqual(null);
      expect(countTempDirs(pathPhysical, { run: RIntact })).toEqual(0);
    });

    then('and R\'s unstamped residue is untouched by it — we take only our own', () => {
      // the healthy run cannot reclaim the broken run's dirs: they carry no id
      // at all, so no run's filter can match them. that is WHY the message at
      // [t2] offers no command — see the peer-reap note above.
      expect(countUnstamped(pathPhysical)).toBeGreaterThan(0);
    });
  });

  when('[t4] a run makes ZERO dirs (a suite that never calls genTempDir)', () => {
    // ⚠️ this run is NOT R. R is the BROKEN run, which made many dirs; a suite
    //    that never calls genTempDir is a different invocation entirely, and a
    //    bare `error` / `exitCode` here would blur the two. a rerun is not the
    //    same run — the same discipline [t3] keeps.
    const RQuiet = useThen('a run whose suite never calls genTempDir', () =>
      mintRun({ allocates: 0 }),
    );

    then('zero-made + zero-matched is NOT a break — it is a quiet success', () => {
      // the invariant is a conjunction; this is the guard against a noisy false alarm
      expect(countTempDirs(pathPhysical, { run: RQuiet })).toEqual(0);
      expect(errorOf(RQuiet)).toEqual(null);
      expect(exitCodeOf(RQuiet)).toEqual(0);
    });
  });
});
```

## `[t3]` and `[t4]` are what make the invariant shippable

`[t2]` alone would pass under an implementation that always throws. the two negative cases are the
ones that earn trust:

- **`[t3]`** — the healthy path must stay silent, or the alarm gets muted by every consumer
- **`[t4]`** — a suite that makes **no** dirs matches **no** dirs, which is *not* a break. an
  invariant written as `countMatched === 0` alone would fire on every project that uses test-fns
  for `given/when/then` and never touches `genTempDir` — which is most of them

`[t4]` is the false-positive that would have made this whole guard a liability. the conjunction —
*an unstamped fresh orphan exists* **AND** *we matched none* — is what makes it precise.

### ⚠️ `[t5]` — the false alarm the orphan form excludes, and the clamp it owes

```gherkin
  when('[t5] OUR run is scoped to zero files while a PEER run is live in the same scope', () => {
    // ⚠️ BOTH parties are minted here. a `when` with no mints at all leaves the
    //    peer in the title, the zero-scope run in the title, and `error` /
    //    `exitCode` as unbound global handles — so the ONE clamp that separates
    //    the orphan predicate from the discarded delta form has no population
    //    to bite against, and its premise is prose.
    //    for the linchpin's precision guard that is the worst place for it:
    //    a clamp that cannot go red under the shape it rejects proves none of
    //    the repair (rule.require.clamp-edge-cases).
    const RPeer = useThen('a PEER run starts, and stays live throughout', () =>
      mintPeerRun(),
    );
    const dirsMadeByPeer = useThen('the peer makes many fixture dirs', () =>
      countTempDirs(pathPhysical, { run: RPeer }),
    );

    const RZeroScope = useThen('OUR run starts, scoped to ZERO test files', () =>
      mintScopedRun({ selects: 0 }),
    );

    then('the premise holds — we made none, the peer made many', () => {
      expect(countTempDirs(pathPhysical, { run: RZeroScope })).toEqual(0);
      expect(dirsMadeByPeer).toBeGreaterThan(0);
    });

    then('the peer\'s dirs are FRESH, yet not one is an orphan', () => {
      // this pair IS the discrimination. the delta form sees only the first
      // line and calls the growth ours; the orphan form reads the second and
      // excludes every one of them BY CONSTRUCTION — a peer's dir carries the
      // peer's id, so it can never satisfy "carries no run id at all".
      expect(countFresherThan(pathPhysical, startOf(RZeroScope))).toEqual(dirsMadeByPeer);
      expect(countOrphans(pathPhysical)).toEqual(0);
    });

    then('so we stay SILENT — no false alarm against a healthy run', () => {
      expect(errorOf(RZeroScope)).toEqual(null);
      expect(exitCodeOf(RZeroScope)).toEqual(0);
      expect(stderrOf(RZeroScope)).not.toContain('could not reclaim');
    });

    then('and the peer is untouched — we said no word AND took no dir', () => {
      expect(countTempDirs(pathPhysical, { run: RPeer })).toEqual(dirsMadeByPeer);
    });
  });
```

**this is the clamp that separates the two invariant shapes.** the delta form goes **red** here
(it counts the peer's growth as ours, then reports a `MalfunctionError` at test-fns); the orphan
form goes **green**. per `rule.require.clamp-edge-cases`, a clamp that passes under both shapes
proves none of it — `[t5]` bites, and it is the reason the orphan predicate is a replacement rather
than a fourth conjunct.

### the lessons this guard teaches

`case=13` holds the first: *"no dir was reclaimed" is one symptom with several causes, and a
guard that names one will confidently misdiagnose the rest.*

the second is about the **terms** rather than the causes:

> **every term computed over the contained dir must state which population it measures.** the dir is
> **shared**, so *"what changed here"* is never the same question as *"what did we do"*. a term that
> conflates them is wrong no matter how many conjuncts sit beside it.

🟠 **the third is about where a lesson has to live.** a repair to the **invariant** that leaves
`[t1]`'s first precondition on an unfiltered delta sits three paragraphs below the note that
declares that shape unsound, and it does not fail, because a solo scenario has no peer to miscount.
**a defect that is correct by accident under its own demo's preconditions is invisible to the demo**,
which is exactly the class of defect this whole case exists to guard against, committed inside the
guard.

> **a lesson written in prose does not propagate to the assertions that predate it.** when a term's
> shape is declared unsound, every term of that shape in the same artifact is a defect — the ones in
> the `given` and the preconditions too, which read as setup rather than as claims. the sweep is part
> of the repair, never a follow-on to it.

## what this cell adds to the vision

it converts the wish's instruction — *"clamp the chain rather than trust it"* — from an
**assumption owed to execution** (A1, which a reviewer can only take on faith) into a **runtime
invariant that clamps itself on every consumer's machine, forever**.

that is stronger than a test. a test clamps the chain on the jest version we had the day we wrote
it. this clamps it on the jest version each consumer actually runs, years from now, on the upgrade
nobody thought to re-probe.
