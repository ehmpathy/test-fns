# 1.vision.yield — no temp dir survives the run that made it

> the vision implied by [`0.wish.md`](./0.wish.md), whose source of record is `ehmpathy/test-fns#64`.

## the outcome world

### the day in the life

kai opens a laptop and the disk unlocks in nine seconds, as it did the day the machine was new.

kai runs the suite forty times before lunch — red, red, red, green. each run allocates its fixture
dirs and gives them back. kai does not know that, because there is no moment where kai would find
out. a `ls /tmp` shows a handful of entries and one of them is a socket.

kai has never read this vision, never heard of a run id, and paid the whole cost of this behavior
**once**, six months ago, as one pair of keys in each runner config.

> ⚠️ **that cost is per runner config, not per repo.** `test-fns` itself holds **nine** config files
> that share no base, so its own honest cost is **ten lines**, not two. see cons and *awkward #4*.

### the before / after

| | before | after |
|---|---|---|
| a full run of one consumer's suite | **+N dirs, forever** *(N is per-suite and **unmeasured**)* | +0 |
| `/tmp/test-fns` on this machine, today | **12,369 dirs** *(**measured**, `tree -a -L 3 -d`)* | bounded by run concurrency |
| reclaim trigger | a later `genTempDir` call from the same repo, 7 days on | the runner's own teardown, this run |
| the backstop's window | 7 days — a margin against a guess, since the gate had no ownership signal | **24 hours** — the marker's `pid` + `startedAt` replace the guess with an answer |
| an **enhooked** repo whose last run was months ago | orphaned permanently — no caller remains to trigger the gate | already reclaimed at the time |
| an **unhooked** repo whose last run was months ago | orphaned permanently | **still orphaned** — the gate fires only on the next `genTempDir` call, at any window, so no window value reaches this class. it belongs to the machine's own cron |
| boot on a LUKS system | minutes, as `systemd-tmpfiles-setup` walks `/tmp` | seconds |
| ⚠️ **a note on the two kinds of number above** | every figure in this vision is tagged at first use as **measured** or **illustrative**. one **invented** figure (`432`) once sat beside a **measured** one (`12,369`) with no cue to tell them apart, and spread across 11 artifacts and into a bdd assertion — **a claim inherits the credibility of its neighbours**, so the tag is the only guard against that spread | |
| a consumer's cost | a leak they cannot fix without a local reimplementation | one pair of keys per runner config — **10 lines** for a repo shaped like this one |

### the aha

the "aha" is **an event that stops occurring**.

before, kai learned about this behavior at 08:40 on a monday, eight months in, when the laptop
took four minutes to unlock and a `ripgrep` over `/tmp` blew a 20-second timeout. after, that
monday does not arrive.

there is a second, sharper aha, and it belongs to the maintainer rather than the consumer:

> **the leak was never rhachet's. it was `genTempDir`'s, and every consumer already had it.**

the evidence is on this machine right now. `/tmp/test-fns/` holds five scope dirs. every single
one belongs to a **consumer** — `rhachet` (×3 worktrees), `rhachet-roles-bhrain`,
`rhachet-roles-rhight`. not one belongs to `test-fns`. the library that allocates never pays; the
consumers that call always do. that asymmetry is the argument for the choice of repo, and it is
observable rather than argued.

### the guard behind case=10 is an ORPHAN predicate, never a delta

a delta-based invariant (*made > 0 AND matched == 0*) false-positives on any consumer who kept a
hand-rolled teardown: their `afterEach` deletes our dirs before we look, so the delta holds while
the chain is perfectly healthy — and the message tells them to file an issue against us.

the settled form is *a **fresh** entry that carries **no run id at all**, while dirs matched by our
id == 0*. a peer's dir cannot satisfy it by construction (a peer's dir carries the peer's id), so it
is rung 1 of `rule.prefer.prevent-over-correct` rather than rung 3; it **subsumes** the third term a
conjunct-based repair would have added, since a hand-roll that already deleted our dirs leaves **no
entry to find**; and it fires on a run that made zero dirs, which the delta form could not.

the general lesson is written into case=10: **"no dir was reclaimed" is one symptom with SEVEN
causes, and a guard that names one will confidently misdiagnose the other six.**

> ⚠️ **every artifact that QUOTES a mechanism is a copy that goes stale independently of its
> source.** the superseded delta form survived in four other artifacts after the orphan predicate
> replaced it. **a repair recorded only in the file where it was made is a repair the rest of the
> vision has not received.**

### the two the grid found that a free-list would not

## the shape

**four parts.** the disk is the record; there is no in-memory registry.

```
   1. MINT              2. STAMP                    3. RECLAIM
   ─────────            ────────                    ──────────
   the runner's         genTempDir folds the run    the runner's global
   global setup         id into the dir name        teardown removes the
   mints a run id       ↓                           entries whose name
   BEFORE it forks,     2026-…Z.r7f3a91c2.slug.hex  carries THIS run id,
   and writes a         ↑                           and CLEARS the marker
   run MARKER           the mint asserts this        (once, main process)
                        name parses back — or
                        it throws before any
                        dir is made

   4. ARREARS  ── at the NEXT run's setup ────────────────────────────────
   a marker still unsettled, whose PROCESS is gone, and which no run
   has yet REPORTED, is a positive record that a teardown never fired.
   name it, stamp it reported, and never reap it.
```

> **part 4's discriminator is the PROCESS, not a clock.** `case=11`'s `[t6]` shows no clock window
> can exist: a live peer
> and a pre-empted run sit **minutes** apart, while the yield demands detection **seconds** after a
> pre-empt and `case=12` demands a live peer is never slandered. so the marker records the run's
> `pid` + `startedAt`, and the check asks whether that process still answers. **it is entitled to
> ask because it REPORTS and never reaps** — `case=4` forbids a *reap* by liveness guess, not a
> report. a mechanism's constraints are set by its powers. the age window survives as the
> **fallback** where the question cannot be answered.

> 🔴 **part 4 also carries a `reportedAt` term, and without it the report never stops.** a two-term
> predicate (*unsettled* AND *process gone*) holds **continuously for as long as the residue does**,
> so `case=11`'s killed run A would be named by all six later runs across eleven days, and that
> composite's *"D said no word"* is red. a condition that never lapses is not a bound. so the marker
> carries a nullable **`reportedAt`**, the predicate gains `AND reportedAt is null`, and the check
> stamps every marker it names — **one residue, one report, by the first run whose setup sees it.**
> `reportedAt` is a field, never a fifth state, so the `open → partial → {closed | held}` machine
> and every `.state` assertion in the demos are untouched.
>
> **the general shape:** *conditional* is not *bounded*. a guard whose
> trigger persists as long as its subject does fires forever — which is how a real alarm gets muted,
> and the exact hazard `case=12`'s own "what it costs" section opens with.

> **parts 1 and 4 exist because a three-part shape is blind twice over.** it could not detect **a
> teardown that never ran** (`kill -9`, a CI hard timeout, an OOM, a `globalSetup` throw) nor **a
> name the age gate cannot read** — both silent, both catastrophic. see
> [case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md) and
> [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md).

### ⚠️ the marker must be a FILE, and it must not look like a fixture

the marker is a **new entry in the contained dir**, and every sweep in this design iterates that
dir. so the marker collides with two mechanisms:

| if the marker is… | what breaks |
|---|---|
| a **directory** | `computeStaleDirs` parses its name, fails, and preserves it forever as class **E** — so case=14's new *"could not read"* count reports **one line of permanent noise per run**, and the report added to make an invisible population visible is the first to become noise |
| named like a fixture | the run-scoped reclaim treats it as a candidate and deletes its own marker mid-run, which is the arrears check's only evidence |

**the constraint:** the marker is a **file**, never a directory — `pruneStale.ts:30` already filters
`entry.isDirectory()`, so a file is skipped by construction rather than by a new rule. and its name
must sit outside the fixture pattern, so no reclaim reads it as a candidate.

> ⚠️ **and that exclusion needs its own reclaim.** the
> constraint above keeps the marker out of the dir sweep, then leaves **no mechanism at all** to
> remove one whose run was pre-empted: its teardown never ran, and the age gate filters files. so
> the guard against a leak **leaked** — one file per pre-empted run, forever. **the age gate gains an explicit second pass over
> markers** — age-bounded, never state-bounded (an `open` marker is the arrears check's only
> evidence), and it must exclude the `readme.md` / `.gitignore` the `isDirectory()` filter used to
> exclude for free. see register row 18.

**the general shape of that near-miss is worth a record:** the contained dir is a **shared namespace
that four mechanisms now iterate** — the run reclaim, the age gate, the arrears check, and the
consumer's own `countTempDirs` clamp. every new entry placed there is an input to all four.
execution must not add a fifth entry kind without this same check.

⚠️ **and the rule has a second half.** the dir does not merely hold what
*we* add — it already holds **`readme.md` and `.gitignore`**, written by
`genIsolatedTempInfra.ts:61-70` on every run. so the rule has two halves:

| | the rule |
|---|---|
| **every entry you ADD** | is an input to all four mechanisms — check it against each |
| **every entry ALREADY THERE** | is an input to any mechanism you add — check your mechanism against each |

the second half cost two defects: a clamp that counts raw entries reads 2 on a pristine dir
([case=8](./1.vision.experience.case=8.clamp-derives-the-path.md)), and the new marker sweep would
have deleted both infra files, since the `isDirectory()` filter had excluded them invisibly.

### ⚠️ the alternative shape this vision did NOT take — a per-run subdirectory

the issue proposed a **"stamped dir name"**, and the wish explicitly says *"the names, the
mechanism, and their home are yours."* so the proposal owes a challenge:

```
   the stamp (adopted)                  a run subdir (the alternative)
   ────────────────────                 ──────────────────────────────
   .temp/                               .temp/
     2026-…Z.r7f3a91c2.slug.hex           2026-…Z.r7f3a91c2/     ← one dir per run
     2026-…Z.r7f3a91c2.slug.hex             2026-…Z.slug.hex     ← names UNCHANGED
     2026-…Z.rOTHER123.slug.hex             2026-…Z.slug.hex
                                          2026-…Z.rOTHER123/
   reclaim = readdir + parse each       reclaim = rm -rf ONE dir
```

| property | the stamp | a run subdir |
|---|---|---|
| peer-safety (case=5) | by name-match — correct, but a filter one can write wrong | **by containment** — a peer's dirs are not in your subtree |
| the reclaim | readdir, parse N names, rm the matches | **one `rm -rf`** |
| the fixture name | **mutated** — the source of case=14 and the `PATH_MAX` break | **untouched** — that hazard class evaporates |
| the age gate's parse | parses a name we changed | parses the **run dir's** name — a hazard we own outright |
| broken chain (case=10) | dirs unstamped ⇒ detectable | dirs land flat ⇒ **equally detectable** |
| unhooked (case=7) | today's behavior | today's behavior — same |

**why it matters:** five of this design's sharpest hazards — `case=14`, the `ENAMETOOLONG` break,
`case=10`'s name-based detection, the ugly name, and `case=12`'s marker — all descend from the one
decision to encode ownership **in a filename**. the subdir does not remove every hazard (the age
gate still parses a name), but it moves peer-safety from *"our filter is correct"* to *"a peer's
dirs are not in our subtree"* — which is rung 1 of `rule.prefer.prevent-over-correct` rather than
rung 3.

**it is not adopted here**, because it changes the physical layout, touches `genIsolatedTempInfra`,
and may interact with #66's re-key of the scope in ways this vision has not traced. **but it is the
one fulcrum in this vision that is NOT a clean rework** — the two shapes differ in layout, so a
switch after execution is a teardown rather than a rename. it is raised as open question 5, and it
is the **first probe execution should run**: one afternoon before any code settles it far more
cheaply than any afternoon after.

### where this diverges from the issue's proposal, and why

the wish grants permission for a shape it did not imagine, and asks that we say why. there is one:

> **the reclaim hangs off the runner's `globalTeardown`, not off an `afterAll` in
> `setupFilesAfterEnv`.**

the issue proposed `setupFilesAfterEnv: [...extant, 'test-fns/jest/setupAfterEnv']` with
`afterAll(() => pruneTempDirs())`. that runs **per test file, in every worker** — so across N test
files it fires N times, concurrently (this repo runs `maxWorkers: '50%'`,
`jest.integration.config.ts:33`), each fire a full `readdir` + `rm` pass over the same directory.

`globalTeardown` runs **once, in the main process, after every test file**. it is strictly better
against the issue's own hazard 2:

| hazard 2 asks for | `afterAll` per file | `globalTeardown` |
|---|---|---|
| "not per-case" | it *is* per-file | once, after all |
| "not scope-dependent" | a zero-match scope loads no file → no teardown at all | the runner calls it regardless |
| "a teardown neither order nor scope can step around" | a test filter can deselect it | it is config, not a test — no filter reaches it |
| no races on the same dir | W workers × N files race `rm` | single reader, single writer |

the issue's hazard 2 argues for exactly this shape; its proposed mechanism does not yet reach it.
**the config cost is identical** — two jest keys either way — so this is a strict improvement, not
a trade.

it also removes a question the `afterAll` shape must answer: what happens when a zero-match scope
loads no test file at all. under `globalTeardown` the question does not arise.

three renames from the issue's proposals, each for a stated reason:

| issue's word | this vision | why |
|---|---|---|
| `session` | **`run`** | `session` is overloaded (a login, a repl, a lesson). the domain's own word for this is *a test run* — one word, one sense (`rule.require.ubiqlang`) |
| "the contained path" | **`pathPhysical`** / **`pathSymlink`** | already the canonical pair in `genIsolatedTempInfra.ts:40`. do not mint a third word for a thing that has two |
| `test-fns/jest/globalSetup` | **`test-fns/autoprune.setup.jest`** | the extant `exports` convention is `{feature}.{role}.{runner}` — `slowtest.reporter.jest`, `slowtest.reporter.vitest` (`package.json:21-23`). ✅ **shipped, and the case demos now carry it.** this cell read *"the case demos carry the placeholder form"* — a true note that became a **licence** to leave them stale, and they stayed stale for three stones past the settlement. see [case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)'s footer, and the exports-map clamp that makes a repeat a red test rather than a footnote |

### the three open questions the wish asked us to settle in-repo

**1 — does a fixture or harness layer already exist that should own the teardown?**
no. the contract surface (`src/contract/index.ts`) is a flat re-export of domain operations. there
is no harness. but there **is** a precedent for consumer-side config entry points:
`./vitest.setup`, `./slowtest.reporter.jest`, `./slowtest.reporter.vitest`. the reclaim hooks
follow that extant pattern rather than invent a layer.

**2 — is the prune plan-by-default (the `clone prune` contract), or does a run reap silently?**
**it reaps.** the `clone prune` contract does not transfer, and the reason is a difference in
trust, not in caution:

- `rhx clone prune` is a human-invoked CLI over dirs **it did not make**. it cannot verify
  ownership, so it must ask.
- this reclaim acts only on dirs **it made, this run**, identified by a stamp it minted. ownership
  is established by construction; there is no claim left to verify.

plan-by-default here would mean *leak by default*, which is the defect. `TEST_FNS_KEEP` is the
opt-out, and it is per-invocation rather than a standing mode. what **does** transfer from
`clone prune` is its *failure* contract — never partial-silent, fail loud with the residue named
([case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)).

**3 — what does the export name itself, and is one enough?**
**`getOneTempDirRoot()` → `{ pathPhysical, pathSymlink }`.** one export, three consumers: the
downstream clamp, the hold message's `at:` line, and the reclaim itself. it is enough **provided
it yields both paths** rather than choose for the caller — the clamp and the human want
`pathPhysical`; discoverability wants `pathSymlink`.

## the mental model

### how kai describes it to a friend

> "the test helper cleans up after itself now."

that is the whole model, and its shallowness is the win. a consumer should never need a deeper
one.

the adopter, one level down:

> "each run tags its scratch dirs with an id, and at the end it deletes its own. so two runs at
> once don't step on each other."

### the analogies that fit

- **a name tag at a conference.** you take your own badge home. you do not take the badge of
  whoever is still in the hall. the *tag* is what makes it safe, not a rule about who leaves first.
- **a lab notebook, not a memory.** the dir name *is* the record of ownership. a registry in
  memory would be forgotten every time jest resets the module registry between test files — which
  is exactly what probe 1 measured.
- **a coat check.** you get a ticket at the door (mint before the fork), the ticket rides with the
  coat (the stamp), and you claim only what your ticket matches (the reclaim).

### their words vs ours

| kai says | we say | keep which |
|---|---|---|
| "cleans up" | reclaim / prune | **kai's**, in docs and messages. `prune` in code, to match extant `pruneStale` |
| "temp dir" | contained dir · physical path | **kai's** — `genTempDir` already taught them the word |
| "test run" | run · run id | 🔴 **NOT shared — the same word, two units.** see below |
| "keep them so I can look" | the hold hatch · `TEST_FNS_KEEP` | **kai's** intent, our key name |

#### ⚠️ "a run" is one word with two units

*test run* reads as shared vocabulary, on the argument that `run` is the domain's own word. that
argues for the **word**; it says not one thing about agreement on the **concept**. the concept does
not agree:

```
   kai's run                          our run
   ─────────                          ───────
   $ npm test                         one runner invocation
     ├─ test:unit:jest                  ↳ one globalSetup
     ├─ test:unit:vitest  (×2)          ↳ one run id
     ├─ test:integration:jest           ↳ one marker
     ├─ test:integration:vitest         ↳ one reclaim
     ├─ test:acceptance:jest
     └─ test:acceptance:vitest
     = SEVEN of our runs
```

**the settled unit: a run is one runner invocation.** `npm test` is seven of them. the guarantee
holds per invocation; kai reads it per command. it still holds end-to-end **only because the seven
run sequentially** (`&&`) — a consumer who parallelizes them reaches
[case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md) **within one command**,
which is far cheaper to reach than the two-humans shape that case presents.

one benefit falls out of the same count: with seven sequential invocations,
[case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md)'s arrears check fires
at the **next invocation, seconds later** — a pre-empted run in `unit:jest` is reported by
`unit:vitest` in the same `npm test`, not hours later by the next human.

the gap to watch: **kai believes it is automatic.** it is not — it needs a pair of config keys per
runner config. that gap is the entire subject of
[case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md), and the reason the unhooked
notice is a critipath rather than a nicety. a mental model that is *ahead* of reality is a bug in
the behavior, not in the human.

## evaluation

### against the wish's acceptance

| criterion | how this vision meets it | demo |
|---|---|---|
| a full run leaves zero new dirs, count before/after | run-scoped reclaim in `globalTeardown`. ⚠️ stated honestly: **zero new entries of any kind** — the run marker is discharged too, so this is not met on the technicality that a marker is a file rather than a dir | [1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md) |
| survives a **failed** test | the teardown does not read the exit code | [2](./1.vision.experience.case=2.run-fails-still-reclaims.md) |
| survives a **scoped** run | the teardown is config, not a test — no filter reaches it | [3](./1.vision.experience.case=3.scoped-run-still-reclaims.md) |
| survives an **interrupt** | 🔴 **it does not — and that is a requirement amendment for the wisher, not a caveat.** delivered instead: the residue survives (leak, never loss), bounded by the age gate, and the next run names it. **raised as open question 7** | [4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md) + [12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md) |
| a parallel run does not reap a peer's live dirs | peer-safety is a property of the name | [5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md) |
| an escape hatch for inspection | `TEST_FNS_KEEP`, plus its unattended bound | [6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md) |
| the contained temp path is exported | `getOneTempDirRoot()` → both paths | [8](./1.vision.experience.case=8.clamp-derives-the-path.md) |
| a clamp that bites | red-before/green-after, demanded of execution | [8](./1.vision.experience.case=8.clamp-derives-the-path.md) |

**the interrupt row is the one honest gap**, and it is a boundary rather than an omission. no
in-process mechanism survives `SIGKILL`. the design's answer is to fail toward leak, keep the age
gate as backstop, and say so out loud instead of imply a guarantee it cannot hold.

### pros

- **the guarantee lives with the allocation.** a call site cannot forget, because a call site is
  not asked to remember. this is the property the wish named as essential.
- **peer-safety by construction, not by check.** the filter is the name. there is no probe to be
  wrong, no race to lose, no lock to leak.
- **no in-memory state at all.** the three hazards that empty a registry — module reset per file,
  a dead worker, a scoped subset — cannot rename a directory.
- **the fix lands where the defect is.** every consumer gains the **capability** from a version
  bump, and the **fix** once the hooks are wired into each of their runner configs. downstream ends
  with **no** prune machinery of its own, which is the wish's stated acceptance signal for the
  choice of repo.

  ⚠️ **r4 corrected this pro by one word.** it read *"every consumer inherits **it**"*, which
  overstates: a bump delivers a capability, never a fix. an inherited capability that stays unwired
  is precisely the state the leak lives in today — which is why
  [case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)'s notice is a critipath.
- **backwards compatible.** an unhooked consumer gets exactly today's behavior plus one actionable
  notice. no forced migration, no broken build on upgrade.
- **it retires #65 in passing.** `pathPhysical` is outside every git repo, which is the capability
  #65 asks for.
- **orthogonal to #66.** the guarantee is a property of the dir name, not the dir layout — so #64
  and #66 land in either order, as the wish requires.

### cons

- **it costs the consumer config — and the cost is PER RUNNER CONFIG, not per repo.**

  ⚠️ **"two lines per repo" is wrong by 5×, and the count in this very repo says so:**

  ```
  $ ls *.config.ts
  jest.acceptance.config.ts     vitest.acceptance.config.ts
  jest.config.ts                vitest.config.ts
  jest.integration.config.ts    vitest.integration.config.ts
  jest.unit.config.ts           vitest.unit.bdd.config.ts
                                vitest.unit.globals.config.ts
  ```

  **nine configs, and they share no base** — `jest.unit`, `jest.integration`, `jest.acceptance` each
  declare a standalone `Config`; the four vitest configs are four independent `defineConfig` calls.
  so `test-fns`'s own honest cost is **3 jest × 2 keys + 4 vitest × 1 key = 10 lines**, re-paid on
  every new config a repo adds.

  that is not a shrug — it is a **maintenance surface**, and it drifts silently: a consumer who adds
  a tenth config gets no signal it is unhooked except
  [case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)'s notice, which fires per
  invocation rather than per config. so **case=7's notice must name the config file at fault**, not
  merely "your test runner".

  probe 1 settles that a library cannot own the teardown invisibly, so the cost cannot be zero. but
  it **can** be one line per config rather than two: `test-fns` could **ship a preset**
  (`test-fns/jest.preset`, `test-fns/vitest.preset`) that already carries the hooks, so a consumer
  writes one `extends` per config and is robust to a config regenerator besides. **flagged for
  execution** — the *need* is settled; the merge shape is not.
- **the run id lengthens the dir name, and for someone that is a break.**
  `2026-08-31T14-22-01.443Z.r7f3a91c2.my-slug.a1b2c3d4` adds ~10 chars to every fixture path.

  ⚠️ **it is a named hazard, never a tidy concern.** a consumer whose fixture tree sits **within 10
  characters of `PATH_MAX` today** passes now and fails on upgrade with `ENAMETOOLONG` — deep
  inside their own test, at a path they never chose, with no mention of `test-fns` in the error.
  **this behavior would introduce a new failure into code that passes today**, which is the one
  outcome a backwards-compatible upgrade must not produce.

  it is the *limit* locator from `howto.experience.enumerate` move 3 — the one sharp-edge locator
  this vision had walked for **seams** (which found `case=10`) but never for **limits**.

  **the mitigations, in the order execution should reach for them:**
  1. keep the id short — 8 hex, as illustrated. the cost is ~10 chars, not ~40
  2. **fold the id into the extant hex suffix rather than add a segment.** the suffix is already
     8 random hex; if the run id occupies part of that budget the name grows by **zero**, and
     `case=14`'s parse constraint is satisfied by construction. this is the option that makes the
     con vanish rather than shrink, and it deserves a real look before the additive shape is
     committed
  3. if a length must be added, catch `ENAMETOOLONG` at `genTempDir` and re-throw with the
     `test-fns` name, the full path, and its length — so the consumer's error names the cause
     rather than a bare filesystem code (`rule.require.errors-name-the-fix`)
- **it rests on an undocumented env-propagation chain.** see assumptions, below. this is the
  largest risk in the vision and it fails **silently** in the exact direction we most fear.
- **two runners, two adapters.** jest and vitest each need their own entry points. collapse 3
  claims the reclaim core is shared; if that claim breaks, the surface doubles.
- **`globalTeardown` runs after the reporter's summary in some configurations.** so a
  [case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md) error may print *below*
  the test summary, where a human who scans upward could miss it. an ergonomics question for
  execution.
- **it adds two directory scans per runner invocation** — the arrears check at setup, the reclaim at
  teardown. with `npm test` at seven invocations, that is **14 scans** of the contained dir per full
  suite, and the environment where they are slowest is the one this behavior exists for: the wish
  records *"a ripgrep over `/tmp` blew a 20s timeout purely on directory count."*

  **the honest bound:** the scans are confined to **one scope dir**, not all of `/tmp`, and they are
  bare `readdir` calls over names — the wish's ripgrep walked ~12,369 dirs across five scopes and
  `stat`ed and read every file within them, which is a different order of work. **but this is an
  assumption, not a measurement — execution should time it once on the leaked machine.** added by
  r4; it is also a second argument for A5's age gate to stay functional, since a small scope keeps
  these scans cheap.

### the edge cases, and how each keeps kai in a pit of success

| edge | the pit-of-success property |
|---|---|
| two runs share a scope | the name is the filter — a wrong reap is not reachable by a filter bug, only by a design change ([5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)) |
| `kill -9` mid-run | fails toward **leak**, never toward loss; the residue carries a dead id no later run claims ([4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md)), and the next run names it rather than let it accrue in silence ([12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md)) |
| a CI hard timeout, an OOM, or a `globalSetup` throw ends the run | the teardown cannot report its own absence, so the **next** run does — an unsettled marker whose process is gone is a positive record ([12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md)) |
| the reclaim is written fire-and-forget | forbidden — `--forceExit`'s `exit(code)` fires the instant the teardown resolves, so an unawaited reclaim is killed mid-`rmSync` (A6) |
| a scope that matches zero files | the teardown is config, not a test — it still runs and still renders a verdict ([3](./1.vision.experience.case=3.scoped-run-still-reclaims.md)) |
| a dir that will not delete | reap the rest **first**, then report loud with the residue named — **exit 0**, on `case=6` `[t2]`'s precedent ([9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)) |
| a consumer who never wires it | today's behavior + one actionable notice — a strictly-no-worse default ([7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)) |
| the hatch left on in CI | loud, exit 0, and bounded; the grid caught this one ([6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md)). 🔴 **a hold narrowed to a failed test's dirs alone is UNBUILDABLE at this hook** — a `globalTeardown` is handed no test results, which is the same property that makes it unskippable (`case=3`). so the hold is **run-wide**, the message **names that scope and its cause**, and the cell is **bounded rather than unreachable** |
| the contained dir moves (#66) | consumers derive it, so their clamps follow the move ([8](./1.vision.experience.case=8.clamp-derives-the-path.md)) |
| a **watch session** re-runs the suite 40× | `globalSetup` fires once per session, so 40 re-runs share one id and reclaim once **at exit**. dirs accrue within the session, then all go together — bounded, and not one is lost |
| a caller who is **not a test runner** (a cli, a `tsx` one-off, a codegen step) | no teardown exists for them, so today's leak stands. the constraint: case=7's notice must be **suppressible** and must not fire where no runner is detectable, else its named fix does not apply |

the through-line: **every failure mode leaks; not one loses.** that asymmetry is the pit of
success, and it is deliberate at each of the nine rows.

## open questions & assumptions

### assumptions — ranked by what a silent failure would cost

**A1 — jest's `globalSetup` env reaches its workers, and its `globalTeardown`.** 🔴 the linchpin.

the wish's probe 3 verified that `JEST_WORKER_ID` — injected by jest-worker at fork
(`env: { ...process.env, JEST_WORKER_ID }`) — reached every test file's env copy, nine files deep
in one worker. so a value on the main env at fork time should arrive the same way.

but the wish states the honest bound, and this vision adopts it verbatim:

> links 1–2 of that chain are jest's *implementation*, not its documented contract. so **clamp the
> chain rather than trust it** — a defect there is silent, and it fails toward *dirs survive under
> a green suite*.

this vision adds a second link the probes did not cover: **does a `process.env` mutation in
`globalSetup` survive to `globalTeardown`?** they run in the same process, so it should. it is not
a documented guarantee. **both links owe an explicit clamp at execution, and each must fail LOUD
rather than degrade to a silent no-op.**

**the mitigation:**
[case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md) turns this assumption into
a **runtime invariant** rather than a test:

```
 an entry EXISTS that is FRESH and carries NO run id
 dirs matched by OUR id  ==  0
 ────────────────────────────
 ⇒ the chain is broken. fail loud, non-zero, name the runner version.
```

> ⚠️ **the first term must be an ORPHAN, never a DELTA (*"the dir grew"*).** a delta over the
> contained dir attributes a **live peer's** dirs to us — so a scoped run beside a peer fires a
> `MalfunctionError` at test-fns on a perfectly healthy run, and `--changedSince=main` is this
> repo's default. the orphan predicate excludes a peer **by construction** (their dirs carry their
> id), which is rung 1 of `rule.prefer.prevent-over-correct`, and it also catches a break inside a
> zero-dir run that the delta form could not fire on at all. see
> [case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md)'s `[t5]`.

the teardown sits in the same process as the mint, so it knows the true id without traversal of
the chain it checks — the check is independent of what it checks. **that ships the clamp to every
consumer's machine, so a jest upgrade three years out that breaks the handoff is caught on the
first run rather than eight months and 12,901 dirs later.** A1 remains unprobed by me, but it no
longer carries the load in silence.

#### 🔴 the question under A1 — must the id TRAVEL at all?

probes 2 and 3 settle **how** an id gets from the parent to a worker, which makes *minted before the
fork and handed down* the obvious read. that read is sound *given the framing* — and the framing is
that the id is a secret the parent holds. **A1's entire risk, A2b's, and `case=10`'s whole existence
are properties of that hand-down.**

an id both ends can **compute** has no chain to break — which is rung 1 of
`rule.prefer.prevent-over-correct` rather than rung 3:

| candidate | the parent knows | the worker knows | honest verdict |
|---|---|---|---|
| the runner's pid | `process.pid` | `process.ppid` — a worker's parent **is** the runner | ⚠️ promising, real hole: `--runInBand` forks nothing, so the test's `ppid` is the shell. needs a discriminator (is `JEST_WORKER_ID` set?), and `test:acceptance:jest` uses that flag (`package.json:59`) |
| a file the setup writes at a **derivable** path | it wrote it | it reads it | ⚠️ the path must derive without env, so two concurrent runs in one scope collide on one file — unless keyed by the pid above, which is circular |
| the contained dir's mtime, or a lockfile | | | unexplored |

**none of these is proven and none is adopted.** it is recorded because a switch from a minted id to
a derived one is a **clean rework** — the stamp, the reclaim, the marker, and every case demo are
unchanged; only the mint's body differs — so it is best-guessed per `rule.always.defer-fulcrums-to-last`
rather than escalated. **execution's first probe now answers a strictly larger question: does the env
chain hold, AND do we need it?**

the lesson recorded with it: *awkward #5* confesses *"I am confident about a chain I did not
personally probe."* the honest form of that discomfort is never *"probe the chain"* — it is
**"ask whether the design needs a chain."** a risk labelled 🔴 is a risk that has stopped being
questioned; the label does the reassurance the question should do.

**A2a — vitest offers an equivalent setup/teardown pair.** 🟢 **verified from installed source**:
a vitest `globalSetup` file must export `setup`, `teardown`, or
a default (`vitest/dist/chunks/cli-api.BKg19Fvw.js:8480-8497`), and the config key is
`globalSetup?: string | string[]` (`reporters.d.Rsi0PyxX.d.ts:2692`). the teardown has a home.

**A2b — env propagates across vitest's worker pool, so collapse 3 holds.** 🟠 **not** verified.
vitest's own error text notes that `globalSetup` "runs in a different context"
(`utils.DvEY5TfP.js:7`), and its pool may be threads or forks — which differ in whether
`process.env` is shared or copied. **execution owes a probe before it commits to the shared
core.** if it fails, the two runners split and the surface doubles.

**A3 — `globalTeardown` runs on a failed run and a zero-match scoped run.** 🟠 believed, unverified
here. cases [2](./1.vision.experience.case=2.run-fails-still-reclaims.md) and
[3](./1.vision.experience.case=3.scoped-run-still-reclaims.md) rest on it entirely.

**A4 — the run id survives `computeTempDirName`'s parse regex.** 🟢 verified **for one shape**, so it
is a **constraint** rather than an assumption.

the pattern at `computeTempDirName.ts:31` takes `.+` for the slug segment, so an id folded **into
the slug** survives both the write and the age-gate parse. that much is verified by direct read.

⚠️ **that fact is NOT a property of every name execution might choose.** the pattern anchors its
final segment to `[a-f0-9]{8}`, so an id
placed one segment further right (`…Z.my-slug.a1b2c3d4.r7f3a91c2`) fails the parse. and the failure
is invisible at all three layers:

| layer | what it swallows | cite |
|---|---|---|
| `computeStaleDirs` | an unparseable name → preserve, say no word | `computeStaleDirs.ts:28-29` |
| `pruneStale` | any `rmSync` throw | `pruneStale.ts:43-45` |
| `pruneStaleOnce` | the whole promise | `pruneStale.ts:64-66` |

so a stamp in the wrong position turns the **age gate off** for every dir the new version makes —
and the age gate is the floor cells 4, 8b, 13, and 8c all stand on. every one of their demos would
stay green while the bound they promise is gone.

**the constraint, stated so execution cannot miss it:** the run id MUST sit inside the slug segment
(`<timestamp>.<…free text…>.<8 hex>`), and the mint MUST assert its own output parses back —
`parseTempDirTimestamp(name) !== null` and `isTempDir({ path: name })` — **before any dir is made**.
see [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md), which also
repairs the failhide at `computeStaleDirs.ts:29` (preserve is correct; the silence is not).

**A5 — the age gate stays, and its window shortens to 24 hours.** 🟢 a design decision, not a guess.
it is the only reclaim available to cells 4 and 13, so this tree must not remove it.

#### 🔴 where the gate fires — the SETUP scan, not a `genTempDir` call

today the gate rides `genTempDir` (`pruneStale.ts:53-67`), so **a run that allocates no fixture dir
never fires it.** that is a real hole: an arrears-only run — one whose tests happen to call no
`genTempDir` — sweeps not one aged dir, and it is the exact shape
[case=11](./1.vision.experience.case=11.a-friday-afternoon.md)'s observer runs take.

the gate moves to the runner's **`globalSetup`**, beside the arrears check. three reasons, in order
of weight:

1. **it fires for every run**, not only for one that allocates. the reclaim's coverage stops being
   a function of what the tests happened to do.
2. **it costs no new scan.** the setup already reads this dir for the arrears check, so the gate
   rides that read rather than add a third — which pays down the scan-count con directly.
3. **it runs once per invocation, in the main process**, so it cannot race a worker or itself. the
   extant call fires per `genTempDir`, from any worker, concurrently.

the gate **stays** on `genTempDir` as well, for the unhooked consumer — who has no setup at all, and
for whom the extant trigger is the only one there is.

#### 🔴 the window moves from 7d to 24h, and the reason is evidence rather than nerve

the extant 7 days is a **margin against a guess**. the gate has no ownership signal at all, so its
window must be long enough that no plausible run is still in flight — which is why
[case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md) is the sharpest cell in
this vision.

after this behavior the gate no longer guesses. the marker carries `pid` + `startedAt`, so
*"is this residue's owner still alive?"* has an **answer**. the window shrinks because evidence
replaced the margin.

| who the gate serves | at 7d | at 24h |
|---|---|---|
| **unhooked consumers** — every consumer on release day, and their only reclaim | 7 days of accrual | 1 day |
| interrupt / pre-empt residue | 7 days | 1 day |
| held dirs (`TEST_FNS_KEEP`) | 7 days to inspect | **1 day** — the one real cost |

the hold is the only loss, and it is small:
[case=6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md)'s narrative is *"kai opens
the dir, sees the problem in ninety seconds."* a friday-afternoon hold inspected monday is the edge,
and the hold message names its own window, so a human is never surprised by it.

**two constraints ride with the shorter window:**

1. **it lands WITH the liveness check, never before it.** at 7d a suite that outlives the window is
   unthinkable; at 24h it is merely unlikely. without `pid` + `startedAt` a 24h gate trades a leak
   for **loss**, which is the one failure mode this design keeps off the table everywhere else.
2. **it is a default, not a law.** a consumer whose suite genuinely runs long, or who inspects holds
   across a weekend, needs the window configurable.

**and it fixes no orphan class.** the gate fires only when `genTempDir` is next called in that
scope, so a repo whose last run was months ago is orphaned permanently at *any* window. that class
belongs to the machine's own cron, and this vision should not imply otherwise.

#### ⚠️ "it stays" was never "it works"

cells 4, 8b, 13, and the interrupt row all rest on the gate as their **only** floor, and its
persistence was asserted without a check of whether it reclaims at all. the evidence cuts both ways:

- the wish measured **12,901** dirs on 2026-08-30
- a re-measure read **12,369** on 2026-08-31

the magnitude is confirmed. but the count went **down by ~530 in one day**, which is a *moved*
number offered as confirmation of a *static* claim. either the gate does reclaim (good — the floor
is real), or the human's own `find -mtime +3 -delete` sweep ran, in which case the floor belongs to
someone else's cron.

**the probe, and it is one minute:** touch a contained dir's mtime back past the window, call
`genTempDir` in that scope, look. it decides whether four cases have a floor at all, and it is
cheaper than any of the analysis built on top of it. **it must run before the window shortens** —
a 24h gate that does not fire is a 24h promise with a 7d reality.

**A6 — `jest --forceExit` does not pre-empt `globalTeardown`.** 🟢 **verified from installed
source**, `@jest/core@30.2.0/build/index.js`:

```
3429   await runGlobalHook({ moduleName: 'globalSetup'    })
3457   await scheduler.scheduleTests(...)
3464   await runGlobalHook({ moduleName: 'globalTeardown' })   ← AWAITED
3472   await processResults(...)
         ↓ runCLI resolves
jest-cli:657   readResultsAndExit(results, globalConfig)
jest-cli:719   if (globalConfig.forceExit) exit(code)          ← the exit
```

the `--bail` path has the same shape — `TestScheduler` line 1243 awaits `globalTeardown` in a
`finally`, then hard-exits at 1249. **the flag fires strictly after the teardown resolves.** all
three of this repo's jest commands pass it (`package.json:53,56,59`) and none of them loses a
reclaim to it.

#### 🔴 the constraint this read replaces the assumption with

`exit(code)` kills the process the instant the teardown's promise resolves. **so the reclaim must be
`await`ed inside `globalTeardown`, never fire-and-forget** — and fire-and-forget is exactly the shape
the extant code uses:

```ts
// pruneStale.ts:53-67
pruneStale({ tmpDir, maxAgeMs }).catch(() => {
  // ignore errors - prune is best-effort
});
```

copy that pattern into the teardown and `--forceExit` reaps the reclaim mid-`rmSync`, silently, on
every run — a partial delete with no report, which is the precise defect
[case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md) exists to forbid. the
teardown must return a promise the runner can await, and every branch within it must be awaited.

#### what still needs the arrears check

a teardown that never runs remains real — `SIGKILL`, `SIGINT`, an OOM, a throw inside
`globalSetup`. it fails in the same silent direction as A1, and A1's mitigation does **not** reach
it: [case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md)'s invariant lives
*inside* the teardown, so it fires only if the teardown runs. **a teardown that never runs at all is
blind to its own absence.**

so that class gets its own fail-safe rather than only a clamp:
[case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md) moves the detect to
the **next run's setup** — each run writes a marker that its own teardown settles, so an unsettled
marker whose process is gone is a positive record of a teardown that did not fire. that is the one
fact a teardown could never report about itself.

**the two guards are complementary and neither substitutes for the other:**

| | case=10's invariant | case=12's arrears check |
|---|---|---|
| lives in | the teardown | the **next** run's setup |
| catches | the teardown ran, matched zero (broken chain) | the teardown never ran (signal, OOM, setup throw) |
| blind to | a teardown that never runs | a teardown that runs and matches zero |

**execution owes one clamp here** — a child run killed by `SIGKILL` mid-teardown, counted before and
after — so the consumer is protected on their own jest version, not merely on ours.

**two further facts from the same read, which shape where the clamps must live:**

- **`scoped` is this repo's default**, not an edge: the jest commands append `--changedSince=main`
  unless `THOROUGH` is set. so case=3's path is the common one here.
- **the acceptance suite runs `--runInBand`** (`package.json:59`) — one process, no fork. it
  therefore *cannot* exercise the mint chain's fork hop. **any clamp on A1 must live in the unit
  or integration suites.** an acceptance-only clamp would be green and blind — the same shape as
  the `1,786 orphan` precedent, a fourth time.

#### 🔴 row 18, stated in full — the marker is reclaimed by no mechanism today

`case=12` has each run write a **marker file** which its own teardown settles. it is a **file** so
the dir sweep skips it — correct, and it leaves the marker invisible to the one reclaim that
survives a dead process:

| a marker from… | who clears it |
|---|---|
| a run whose teardown fired | its own teardown ✅ |
| a run that was **held** | its own teardown, settled as `held` ✅ |
| a run pre-empted before its teardown began — a signal, an OOM, a `globalSetup` throw | ❌ **no one** |
| a run killed by `SIGKILL` | ❌ **no one** |
| the age gate | ❌ `pruneStale.ts:30` filters `entry.isDirectory()` — a file is never a candidate |

**rows 3 and 4 are the exact population `case=12` exists for.** so the guard against a leak
**leaks** — one small file per pre-empted run, forever. it fails the vision's own honest
restatement of the acceptance (*"zero new entries of any kind, once a run's marker is
discharged"*), because a pre-empted run's marker is never discharged.

```
   the age gate today:   readdir → filter isDirectory() → parse → age → rm
   the age gate needed:  readdir → TWO passes
                           ├─ dirs    → parse → age → rm        (extant)
                           └─ MARKERS → age → rm                (new, explicit)
```

the marker sweep is **simpler** than the dir sweep: a marker carries its own run id and timestamp by
construction, so it needs no name parse and cannot hit `case=14`'s hazard. two constraints on it:

- it must **exclude `readme.md` and `.gitignore`**, which the `isDirectory()` filter used to exclude
  for free
- it must be **age-bounded, never state-bounded** — a marker left `open` is the arrears check's only
  evidence, so an eager sweep of open markers would delete the input `case=12` reads. sweep markers
  older than the age window, by which point their arrears have long since been reported

**and no, the marker should not simply be a directory instead.** a dir marker is parsed by
`computeStaleDirs`, fails the parse, and is preserved **forever** as class E — trading a leak that a
five-line sweep fixes for a leak with *no* reclaim at all, plus a line of permanent noise per run in
`case=14`'s report. the defect was never the file; it was the absent sweep.

## what is awkward

honest discomforts, in descending order of how much they bother me:

### 1. the guarantee is not the library's to keep, and the title hides that

the wish's title — *"no temp dir `genTempDir` made survives the test run that made it"* — reads as
an unconditional promise. it is conditional: it holds **if** the consumer wired the hooks into
**every** runner config they own, **and** the run was not `kill -9`'d.

⚠️ r3 sharpened both halves of that condition. *"the test run"* in the title reads at kai's unit
(`npm test`) and holds at ours (one runner invocation) — seven of ours per one of kai's here. and
*"wired the hooks"* is not a one-time act: it is a per-config obligation, re-incurred on every
config a repo adds.

that is not a flaw in the design; probe 1 makes it unavoidable. but it means the library ships a
promise it cannot unilaterally keep, which is an uncomfortable contract to advertise.
[case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md) is my best answer — make the
unkept condition **loud at the moment it matters** — and it is a mitigation, not a cure.

### 2. the design fights the mental model, deliberately, and I chose to keep the fight

kai's model is *"the test helper cleans up after itself."* the reality is *"the test helper cleans
up after itself if you told your test runner to let it."*

every instinct says close that gap — make it automatic. **probe 1 says the gap cannot be closed.**
so the design instead makes the gap *visible*, which is strictly second-best. a reviewer who finds
a way to close it should say so, because I could not.

### 3. the run id in the dir name is real ugliness for a real reason

```
2026-08-31T14-22-01.443Z.r7f3a91c2.my-slug.a1b2c3d4
                        └─────────┘
```

kai reads these paths in failure output. a second opaque hex blob in the middle makes them worse,
and the slug — the one segment a human actually reads — moves further right.

the alternative (a sidecar file that records ownership) is strictly worse: a sidecar can be lost,
half-written, or raced, whereas a name is atomic with the directory it names. **the disk-as-record
property is worth the ugliness**, but the ugliness is real and a human pays it on every failed
test.

### 4. two config keys is one more than it should be

vitest's `globalSetup` exports both `setup` and `teardown` from one module, so vitest needs one
key. jest needs two (`globalSetup` + `globalTeardown`). both verified from installed source, so
this is a fact rather than a guess — the adoption instructions differ per runner for a reason
unrelated to the domain.

**the asymmetry costs more than annoyance.** two keys means a **half-wired** state exists that
vitest cannot reach: a jest consumer who adds `globalSetup` and misses `globalTeardown` mints run
ids, stamps every dir, and never reclaims one — and the arrears check would have blamed a signal
that never landed. **a config surface with two required keys does not merely ask for two lines; it
creates a distinct broken state per absent key, and each needs its own diagnosis.** that state is
the second row of `case=10`'s seven-cause table and `[t4b]` of case=12.

so the honest form of this discomfort: the asymmetry is not cosmetic, and the mitigation is not to
wish it away but to **make the half-wired state legible** — which the marker's `open` state plus a
config read now does.

#### ⚠️ r3 multiplied this discomfort by nine

the section above weighs **two keys**. the real surface is **two keys × every runner config a repo
owns** — ten lines in `test-fns` itself, across nine config files that share no base (see cons).
each of the ten is an independent chance to half-wire, so the distinct broken state the tenth pass
found is not one state; it is **one per config**.

that turns a preset from a nicety into the honest answer. a shipped `test-fns/jest.preset` collapses
two keys into one `extends`, removes the half-wire per config, and survives a config regenerator —
which ten hand-added lines do not. **flagged for execution, not adopted here**, because a preset's
shape (how a consumer merges their own keys into it) is a design question this vision has not
walked.

### 5. I am confident about a chain I did not personally probe

A1 and A2 are the whole foundation, and my evidence for A1 is a probe run by someone else, in a
different repo, on a different day. my evidence for A2 is a documented API and an inference.

that is thin ground for a vision this confident, and it is exactly the ground the wish warned
about — *"a defect there is silent, and it fails toward dirs survive under a green suite."*
**a probe of A1 and A2 should be the first act of execution, before any design is committed.** if
either fails, this vision's shape changes materially.

⚠️ **r3 found the deeper version of this discomfort.** the honest form is not *"I should probe the
chain"* — it is **"I should have asked whether the design needs a chain."** an id both ends can
*derive* has no chain at all. I never asked, because the 🔴 label plus a clamp plus a case demo made
A1 feel handled, and all of that work presumed the chain was necessary. see the derived-id
alternative recorded under A1.

### 6. the tradeoff at case=9 makes me uneasy either way

a reclaim that fails a green run over an un-removable dir may become a flake that trains consumers
to unwire the hooks — which loses the whole behavior to protect against a rare, benign residue. a
reclaim that reports at exit-zero is `failhide` in the specific place this behavior exists to fix.

I chose to fail, and I am not comfortable with it. it is flagged as open question 3 and it is a
clean rework.

## the yield, in one line

> **each run tags the dirs it makes, and the runner's own teardown reclaims exactly those** — so
> the guarantee lives with the allocation, no call site can forget, no peer can be reaped, and
> every failure mode leaks rather than loses.
