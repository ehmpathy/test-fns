# case=2 — the run fails, and still reclaims

> cell 2 · `hooks=jest|vitest` · `termination=fail` · `solo` · `reclaim`
> **feel** happy · **care** critipath — a failed suite is the common dev loop

## the narrative

kai is mid-refactor. the suite is red, and kai runs it again. and again. and again — eleven times
before lunch, each one a failure, each one a little closer.

each of those eleven runs allocated its fixtures. each one gave them back.

this is the cell that carries the **volume**. a green suite runs once at the end; a red suite runs
dozens of times an afternoon, because that is what a red suite *is* — a loop. so if the reclaim
were tied to success, it would skip exactly the runs that make the most dirs.

the failure mode this cell forbids is subtle and very easy to ship: a teardown that only runs on
a clean exit path. kai would see zero residue in CI (green), zero residue on the final local run
(green) — and a `/tmp` that grows only across the afternoons kai is deepest in a hard problem and
least likely to look.

## the shape that earns it

the reclaim hangs off the runner's **global teardown**, which the runner calls after the run
regardless of verdict. it does not read the exit code, and it must not: the fixtures belong to the
run, not to the run's outcome.

## the timeline

```gherkin
given('[case2] an enhooked repo whose suite has a failed test', () => {

  // ⚠️ the cast, declared up front — every demo owes this. an assignment
  //    inside a `then` whose body holds no assertion breaks
  //    rule.forbid.failhide, and leaves `pathPhysical`, the run id,
  //    `exitCode` and `stdout` as free variables.
  const { pathPhysical } = getOneTempDirRoot();
  const countBefore = useThen('the contained dir holds a prior count', () =>
    countTempDirs(pathPhysical),
  );
  const R = useThen('a run starts whose suite will fail', () => mintRun({ willFail: true }));

  when('[t0] the run has not yet begun', () => {
    then('the prior count is a real measurement', () => {
      expect(countBefore).toBeGreaterThanOrEqual(0);
    });
  });

  when('[t1] the suite runs, allocates fixtures, and a test fails', () => {
    then('the run exits non-zero', () => {
      expect(exitCodeOf(R)).not.toEqual(0);
    });

    then('the failure is reported to the human, unchanged', () => {
      expect(stdoutOf(R)).toContain('1 failed');
    });
  });

  when('[t2] the global teardown runs anyway', () => {
    then('the reclaim did not read the exit code', () => {
      // same assertion as case=1 [t3], under the opposite verdict
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(0);
    });

    then('so the contained dir returns to the count it began with', () => {
      // ⚠️ the equality must not stand alone in its own `then`. it is sound as
      //    a CONSEQUENCE of the run-scoped fact above it, and unsound as a
      //    standalone claim over a shared namespace — the shape case=5 [t3]
      //    purges. the run-scoped line is repeated inside this step rather
      //    than left to the step above, so the derivation survives a reorder.
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(0);
      expect(countTempDirs(pathPhysical)).toEqual(countBefore);
    });

    then('the reclaim did not mask or alter the failure', () => {
      expect(exitCodeOf(R)).not.toEqual(0);
    });
  });
});
```

## the edge to press on

`[t2]`'s last `then` is the one a reviewer should press on. a teardown that throws, or that
swallows, could turn a red run green or a green run red. **the reclaim must be transparent to the
run's verdict in both directions** — it may add a failure of its own
([case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)), but it must never
erase the run's.

## a note on the hatch

kai, deep in that refactor, may want the failed run's fixture kept. that is
[case=6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md) — a deliberate,
per-invocation opt-out, never the default.
