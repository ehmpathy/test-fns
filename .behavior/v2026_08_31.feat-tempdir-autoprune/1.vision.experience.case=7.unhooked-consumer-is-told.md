# case=7 — the unhooked consumer is told

> cells 14 + 15 + 16 · one adoption seam, three points of view
> cell 16 — wire the hooks · **feel** happy · **care** critipath — gates every other cell
> cells 14/15 — unhooked · **feel** ⚡ **sharp** · **care** critipath — **the default state on release day**

## why this is a critipath, not a nitpick

**every consumer is unhooked the moment they upgrade.** that is not an edge case — it is the state
of the entire world on release day.

so a version of this behavior that stays silent when unhooked would ship a green changelog, a
green CI, a green test suite, and reclaim exactly zero directories anywhere. the wish would be
"delivered" and the 12,369 dirs would grow unabated. **this cell is where the whole behavior
succeeds or quietly fails to arrive.**

probe 1 in the wish makes the consumer-side hook unavoidable: a library cannot register its own
teardown, because jest kills its workers before any in-process handler fires. so the config cost
is real and permanent. the design question is not how to avoid it — it is **how a consumer finds
out they have not paid it.**

## the narrative — cell 16, the adopter wires it

kai upgrades `test-fns` and runs the suite:

```
$ npm run test:integration

🧹 test-fns: temp dirs made by genTempDir are never reclaimed here.
   ├─ at: ./jest.integration.config.ts
   ├─ cause: this runner config does not wire the autoprune hooks.
   ├─ fix (jest): add both keys —
   │      globalSetup: 'test-fns/autoprune.setup.jest'
   │      globalTeardown: 'test-fns/autoprune.teardown.jest'
   ├─ fix (vitest): add the one key —
   │      globalSetup: ['test-fns/autoprune.setup.vitest']
   └─ quiet: set TEST_FNS_QUIET=1
```

> 🔴 **this block is the SHIPPED render, never a sketch of one.** a sketch of it carries the phrase
> `the runner hooks are absent`, an invented count (`432 dirs`), and the placeholder subpaths
> `test-fns/jest/globalSetup` / `…globalTeardown`. **three drifts, each with its own lesson:**
>
> | the sketch carries | what ships | the lesson |
> |---|---|---|
> | `the runner hooks are absent` | `never reclaimed here`, with a `cause:` line beneath | the render leads with the **consequence** a human cares about and puts the mechanism one line down. the sketch has them the other way round |
> | `432 dirs this run` | **no count at all** | `432` is the **invented** figure the yield's own measured-vs-illustrative note is about. it can reach a demo assertion unchallenged — *a claim inherits the credibility of its neighbours* |
> | `test-fns/jest/globalSetup` | `test-fns/autoprune.setup.jest` | the sketch's own footer calls these *"proposed, to be settled at `2.1.criteria`"*, and they are settled. **a placeholder that names its own expiry still has to be collected**, and prose alone does not collect it |
>
> the last line faces the reader too: `this notice prints once per run` is a statement
> **about us**; `quiet: set TEST_FNS_QUIET=1` is a **move for them**
> (`rule.require.errors-name-the-fix`). the once-per-run guarantee is unchanged — it is clamped at
> `[t0]`'s last assertion rather than announced in the message.

kai adds the pair of keys to that config. the notice stops for the command it runs, and reappears
for the next config that lacks them.

**that is the adoption experience per config: a notice, a pair of keys, and that config is done for
good.** a repo meets the notice once per config it owns — nine times here — and once every config is
wired it does not return.

> ⚠️ **not "two lines per repo" — that is wrong by 5×.** `test-fns` itself holds **nine** config
> files that share no base, so its honest cost is 3 jest × 2 keys + 4 vitest × 1 key = **ten
> lines**. the notice is per-run and per-command, so a repo with nine configs meets it more than
> once — which is the true shape of this experience, and the reason the yield flags a shipped
> **preset** (one `extends` per config) as a repair execution should weigh.
>
> 🟠 **so the sentence above must not read "once, forever"** — that is the exact claim this note
> refutes, two lines apart, on the one quantity an adopter budgets against. **a correction placed
> BELOW the claim it corrects leaves that claim intact**, and a reader who stops at the bold line
> takes away the number the note exists to retract.
>
> the discipline: **a correction must edit the claim, never merely follow it.** `case=9` carries the
> same hazard where it quotes a `case=6` verdict — a stale claim survives beneath a ⚠️ note,
> because the note *looks* like the repair already happened.

### why a notice and not a throw

a throw on upgrade would break every consumer's suite over a cleanup concern. that trades a disk
leak for a broken build — a strictly worse deal, and one no consumer asked for.

the graceful contract:

| unhooked consumer gets | which is |
|---|---|
| exactly today's behavior — dirs survive, age gate reclaims | no regression |
| one actionable notice per run | the discoverability the fix needs |
| a green suite | no forced migration |

this is `rule.require.safe-by-default` read correctly: the safe path is the easy path, and the
easy path here is *do not break people's builds to fix their disks*.

## the narrative — cell 15, unhooked in CI

the same notice lands in a CI log where no human reads it. that is fine, and deliberate:

- CI containers are usually ephemeral, so an unhooked CI leaks into a volume that is discarded
- the notice is still in the log for whoever eventually greps it
- the human who will act on it is the one who runs the suite locally — cell 14 reaches them

so cells 14 and 15 share one mechanism, and cell 14 is the one that carries the fix home.

## the timeline

```gherkin
given('[case7] a repo that upgraded test-fns', () => {

  const { pathPhysical } = getOneTempDirRoot();

  // ⚠️ bound HERE, at the top of the given, because all three assertions below
  //    lean on `countBefore` — and a term no step sets is the same unbound-term
  //    defect case=5's cast guards against. and the count is NOT zero on a
  //    pristine dir: genIsolatedTempInfra writes readme.md and .gitignore on
  //    every run, so it must filter through isTempDir.
  const countBefore = useThen('the contained dir has some prior contents', () =>
    countTempDirs(pathPhysical),
  );

  when('[t0] the runner hooks are ABSENT and the suite runs', () => {
    // ⚠️ RUnhooked is minted here, and every stderr below is read through a
    //    named run. this file holds THREE runs (unhooked, jest-enhooked,
    //    vitest-enhooked); a bare `stderr` shared across all three blocks would
    //    let [t1]'s "the notice is gone" and [t0]'s "a notice names the absent
    //    hooks" assert OPPOSITE facts about one unscoped handle. two of the
    //    three would be wrong, and which two would depend on what a reader
    //    assumed.
    const RUnhooked = useThen('a run with no hooks wired at all', () =>
      mintRun({ wired: 'none' }),
    );

    then('the suite still passes — no forced migration', () => {
      expect(exitCodeOf(RUnhooked)).toEqual(0);
    });

    then('the dirs are NOT reclaimed — today\'s behavior, unchanged', () => {
      // an unhooked run mints no id, so its dirs carry no stamp. that is the
      // population this case is about, and it is named rather than inferred
      // from a whole-dir delta a live peer could also move.
      expect(countTempDirs(pathPhysical, { unstamped: true })).toBeGreaterThan(0);
      expect(countTempDirs(pathPhysical)).toBeGreaterThan(countBefore);
    });

    then('a notice names the CONSEQUENCE first, then the cause', () => {
      // .note = the order is the point. a human meets the fact that bites them
      //         ("never reclaimed here") before the mechanism that caused it
      expect(stderrOf(RUnhooked)).toContain('never reclaimed here');
      expect(stderrOf(RUnhooked)).toContain(
        'this runner config does not wire the autoprune hooks',
      );
    });

    then('the notice names the exact config keys to add, per runner', () => {
      expect(stderrOf(RUnhooked)).toContain('test-fns/autoprune.setup.jest');
      expect(stderrOf(RUnhooked)).toContain('test-fns/autoprune.teardown.jest');
      expect(stderrOf(RUnhooked)).toContain('test-fns/autoprune.setup.vitest');
    });

    then('and it names the way to silence it, for a human who has read it', () => {
      // a notice that repeats with no off switch trains a human to filter the
      // channel — and the channel also carries case=9's residue report
      expect(stderrOf(RUnhooked)).toContain('TEST_FNS_QUIET');
    });

    then('and it names the CONFIG FILE at fault, not merely "your test runner"', () => {
      // the cost is per runner config, not per repo — nine configs here, and
      // they share no base. a notice that names the runner leaves a human to
      // hunt for which of nine is unhooked.
      expect(stderrOf(RUnhooked)).toMatch(/\S+\.config\.ts/);
    });

    then('the notice prints ONCE, not once per test file', () => {
      expect(countOccurrences(stderrOf(RUnhooked), 'never reclaimed here')).toEqual(1);
    });
  });

  when('[t1] the JEST hooks are added and the suite runs', () => {
    const RJest = useThen('the run mints an id', () => getRunId());

    then('the notice is gone', () => {
      expect(stderrOf(RJest)).not.toContain('never reclaimed here');
    });

    then('this run reclaimed its own, and left [t0]\'s unstamped residue', () => {
      expect(countTempDirs(pathPhysical, { run: RJest })).toEqual(0);
      // [t0]'s dirs are unstamped, so no run id claims them. they are the age
      // gate's, not this teardown's — which is why the whole-dir count does
      // NOT return to countBefore here.
      expect(countTempDirs(pathPhysical, { unstamped: true })).toBeGreaterThan(0);
    });
  });

  when('[t2] the VITEST hook is added and the vitest suite runs', () => {
    const RVitest = useThen('the vitest run mints an id', () => getRunId());

    then('the same guarantee holds under vitest', () => {
      expect(countTempDirs(pathPhysical, { run: RVitest })).toEqual(0);
    });

    then('the notice is gone under vitest too', () => {
      expect(stderrOf(RVitest)).not.toContain('never reclaimed here');
    });
  });
});
```

## 🟠 the unbound baseline, and the falser assertion it conceals

all three assertions here lean on `countBefore`, so it must be established — the same unbound-term
defect `case=5`'s cast and `case=12`'s `[t6]` guard against. it is bound at the top of the `given`,
and it filters through `isTempDir` because `genIsolatedTempInfra.ts:61-70` writes `readme.md` and
`.gitignore` into every contained dir, so a raw count reads 2 on a pristine one.

**but the obvious repair — bind it and keep `toEqual(countBefore)` — is wrong**, and
that is the more useful half of this critique. `[t0]` is an **unhooked** run: it mints no id, so
its dirs carry no stamp and **no later teardown can ever claim them.** they are the age gate's, not
`[t1]`'s. so a whole-dir count at `[t1]` does **not** return to `countBefore`, and an assertion
that it does would fail against a correct implementation.

the repair is the one this vision keeps reaching for: **name the population.**

| step | the population it is actually about | how it is asserted |
|---|---|---|
| `[t0]` | dirs an unhooked run made — **unstamped** | `{ unstamped: true }` > 0 |
| `[t1]` | dirs the jest run made — **stamped with `RJest`** | `{ run: RJest }` === 0 |
| `[t1]` | `[t0]`'s residue, which `[t1]` must NOT claim | `{ unstamped: true }` > 0 |
| `[t2]` | dirs the vitest run made | `{ run: RVitest }` === 0 |

**the general shape, and it is why an unbound term matters more than a compile error would:** an
undefined baseline is not merely unverifiable — it **conceals which population the author meant**,
so a reviewer cannot see that the intended one is wrong. a bare `countBefore` reads as *"the dir
returns to its prior state"*, a claim the timeline forbids. once the populations carry names, the
false claim has nowhere left to sit.

## `[t2]` is not optional

collapse 3 in the dimensions asserts that jest and vitest diverge **only** at this seam. `[t2]` is
the clamp on that claim. this repo ships `test-fns/vitest.setup` in `package.json:exports` and
invokes `vitest run` four times across three of its own test scripts (`package.json:54,57,61`) —
a jest-only reclaim would leave the library's own suite as a leaker while it advertises the fix.

note the **key names differ by runner**, verified from installed source: jest takes two keys
(`globalSetup` + `globalTeardown`, `@jest/types@30.2.0/build/index.d.ts:671-672`); vitest takes
one (`globalSetup`, whose module exports both `setup` and `teardown` —
`vitest/dist/chunks/cli-api.BKg19Fvw.js:8480-8497`).

## `[t0]`'s fifth assertion is the one that gets skipped

"prints once, not once per test file" looks cosmetic. it is not. the notice originates in a place
that runs per worker per file; a naive implementation prints it 118 times and trains every
consumer to filter test-fns output — which then hides
[case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)'s real failure.

**noise is not a cosmetic defect when the same channel carries a loud failure.**

> ✅ **SETTLED, and the demo carries the settled form.** the module specifiers are
> `test-fns/autoprune.{setup,teardown}.jest` and `test-fns/autoprune.setup.vitest`, on the extant
> `{feature}.{role}.{runner}` convention (`package.json:21-23`) — never the placeholders
> `test-fns/jest/globalSetup` etc.
>
> **a placeholder that names its own expiry is still a placeholder.** a footer that reads as a plan
> to return lets every later reader take the strings as knowingly-provisional rather than as stale
> — which is exactly how a placeholder survives a settlement that already happened. the clamp
> against a repeat is `autoprune.exports.acceptance.jest.test.ts`, which drives the real `exports`
> map, so a subpath this doc names and the package does not declare is a **red test** rather than a
> footnote (`rule.require.experience-catalog-evolution`).
