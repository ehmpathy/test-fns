# case=1 — the run passes and leaves no residue

> cell 1 · `hooks=jest|vitest` · `termination=pass` · `solo` · `reclaim`
> **feel** happy · **care** critipath — every run, every consumer

## the narrative

kai runs the suite at dawn on a tuesday, the same way as every day.

```
$ npm run test:integration
  PASS  src/domain.operations/genTempDir/genTempDir.integration.jest.test.ts
  Tests: 118 passed, 118 total
```

432 fixture dirs were made and used over those 118 tests. kai never thinks about them, because
kai never had to: they went back the moment the run ended.

> 📏 **`432` and `118` are ILLUSTRATIVE, not measured** — the pair is invented once here and then
> repeated across eleven artifacts, where it can read as an observation. the one measured figure in
> this vision is **12,369** (`tree -a -L 3 -d /tmp/test-fns`, 2026-08-31). every other number is a
> story's scaffold. **execution owes the real per-suite count before any of these figures reaches a
> test.**

the "aha" is **the absence of an event**. before this behavior, kai's `/tmp` grew by 432 dirs
per run and kai learned about it eight months later, at boot, when the disk took four minutes to
unlock. after, there is no growth to notice, so there is no moment to notice it in. the best
outcome of this whole wish is that no consumer ever thinks about it again.

kai's only visible cost was paid **once**, months ago, when kai added one pair of hook keys to each
runner config (see [case=7](./1.vision.experience.case=7.unhooked-consumer-is-told.md)).

> ⚠️ **the cost is not *"two lines in `jest.config.ts`"*.** the honest cost in this repo is **ten
> lines across nine configs that share no base** (3 jest × 2 keys + 4 vitest × 1 key). the claim
> *paid once, then invisible* holds; the **number** is 5× larger than the easy guess. and it is the
> number that matters here — a critipath demo that understates the consumer's cost by 5×
> understates the exact quantity an adopter decides on.

## why kai does not get a report

the reclaim prints no summary on the happy path. a line that says `🧹 reclaimed 432 temp dirs`
every run would be noise that trains kai to skim — and kai would then skim the one run where it
speaks up for a real reason. **silence is the signal that all is well.** the reclaim speaks only
when it cannot do its job
([case=9](./1.vision.experience.case=9.unremovable-residue-fails-loud.md)) or when the hatch is
open ([case=6](./1.vision.experience.case=6.hold-keeps-them-and-says-where.md)).

## the timeline

```gherkin
given('[case1] a repo whose runner hooks are wired, and a suite that calls genTempDir', () => {

  const { pathPhysical } = getOneTempDirRoot();

  // ⚠️ bound here, outside any `then`. a `then` whose whole body is an
  //    assignment to an undeclared `countBefore` verifies not one claim
  //    (rule.forbid.failhide) and leaves the later steps to read the term as a
  //    free variable. every term a step names must be bound where it is read.
  const countBefore = useThen('the contained dir holds a prior count, derived not hardcoded', () =>
    readdirSync(pathPhysical).filter(isTempDirName).length,
  );

  when('[t0] the run has not yet begun', () => {
    // ⚠️ no `+ 2` literal. a step of the form
    //    `readdirSync(pathPhysical).length >= countBefore + 2` — for the
    //    readme.md + .gitignore that genIsolatedTempInfra.ts:61-70 writes —
    //    puts a FABRICATED constant in the very file whose header note says
    //    every figure is measured or tagged illustrative, and "a fabricated
    //    constant in a clamp measures the vision's imagination".
    //    worse, such a constant GOES STALE BY DESIGN: case=12's marker is a
    //    third infra entry in this same dir. the assertion would survive that
    //    change and quietly measure a claim no one meant to make.
    then('that count measures FIXTURES, and it excludes every infra entry', () => {
      // the claim is not "there are exactly N infra files" — it is that the
      // fixture filter takes every entry a fixture filter should take, and no
      // other. stated that way, a third infra entry cannot stale it.
      const entriesRaw = readdirSync(pathPhysical);
      expect(entriesRaw.filter(isTempDirName).length).toEqual(countBefore);
      expect(entriesRaw.filter((e) => !isTempDirName(e)).every(isInfraEntry)).toEqual(true);
    });
  });

  when('[t1] the runner mints the run id, before it forks its workers', () => {
    // ⚠️ a label that says "every worker sees the same run id" over an
    //    assertion that reads the MAIN process's env states two different
    //    facts, and the cross-worker one is A1, the design's largest
    //    unverified risk. a reader who trusts such a label believes the fork
    //    hop is demonstrated when only the parent's half is asserted. so the
    //    two facts get two steps.
    then('the id exists in the MAIN process, before any worker exists', () => {
      expect(process.env.TEST_FNS_RUN).toBeDefined();
      expect(workerCount()).toEqual(0);  // the mint is genuinely pre-fork
    });

    then('and a WORKER, once forked, reads that same id — the A1 hop, observed', () => {
      // this is the assertion the cross-worker claim demands. it is
      // the one link probe 3 covers and probe 1 does not, so it belongs in a
      // suite that actually forks — never in test:acceptance:jest, which runs
      // --runInBand (package.json:59) and would pass while blind.
      expect(readEnvFromInsideAWorker('TEST_FNS_RUN')).toEqual(process.env.TEST_FNS_RUN);
    });
  });

  when('[t2] the suite runs and every test passes', () => {
    then('each genTempDir call yields a dir stamped with this run id', () => {
      const dir = genTempDir({ slug: 'my-test' });
      expect(basename(dir)).toContain(`.r${process.env.TEST_FNS_RUN}.`);
    });

    // ⚠️ `R` names the run this whole walk is about. this file reads the id
    //    straight off the env (correctly: the mint chain is what it
    //    demonstrates), but `exitCode` and `stderr` need a subject. the env is
    //    the id; it is not the run. a handle for the run is what the outcome
    //    assertions read.
    const R = useThen('the run this walk is about', () => process.env.TEST_FNS_RUN);

    then('the run exits zero', () => {
      expect(exitCodeOf(R)).toEqual(0);
    });
  });

  when('[t3] the runner calls its global teardown, once, after all files', () => {
    then('no dir that carries this run id survives', () => {
      // the id the mint wrote is on the main process's env, which is the same
      // source the teardown reads — one hop, not three (see case=10). no free
      // variable stands in for it.
      expect(countTempDirs(pathPhysical, { run: process.env.TEST_FNS_RUN }))
        .toEqual(0);
    });

    then('so the contained dir returns to the count it began with', () => {
      // ⚠️ this whole-dir equality must never stand ALONE in its own `then` —
      //    that is the bare-claim-over-a-shared-namespace shape case=5 [t3]
      //    purges. it is sound here only as a
      //    CONSEQUENCE of the run-scoped fact above it: this run's population
      //    is empty, and no other party wrote to the dir. in a solo scenario
      //    the value is correct by accident, which is precisely why the shape
      //    is dangerous — it teaches a consumer to write the unsound form.
      expect(countTempDirs(pathPhysical, { run: process.env.TEST_FNS_RUN }))
        .toEqual(0);
      expect(readdirSync(pathPhysical).filter(isTempDirName).length)
        .toEqual(countBefore);
    });

    then('the run says no word about it', () => {
      expect(stderrOf(R)).not.toContain('test-fns');
    });
  });
});
```

## what makes it hold

- **`[t1]` before the fork** — probe 2 in the wish settles that a worker-local mint is erased
  between test files. the id must exist before the pool does.

  > 🟠 **ONE assertion under a label that promises TWO is a claim with no clamp.** a label that
  > says *"every worker sees the same run id"* over an assertion that reads the **main** process's
  > env states two different facts, and the absent one is **A1** — the design's largest unverified
  > risk and the whole reason `case=10`'s invariant exists. **a reader who trusts such a label
  > believes the fork hop is demonstrated.**
  >
  > so `[t1]` is two `then`s: the pre-fork mint (with `workerCount() === 0`, so *"before"* is
  > asserted rather than implied) and the hop itself, read from inside a worker. **and the hop's
  > clamp must live in the unit or integration suites** — `test:acceptance:jest` runs `--runInBand`
  > (`package.json:59`), forks no workers, and would pass while blind.
  >
  > **the shape: a label is an assertion the test runner does not check.** every gap between a
  > `then`'s words and its body is a claim with no clamp behind it — and this one sat on the
  > assumption the vision itself grades 🔴.
- **`[t3]` once, in the main process** — a per-file `afterAll` would run N times and race. the
  runner's *global* teardown runs once, after every file, and neither test order nor a partial
  selection can step around it. this is the structural cure the `1,786 orphan` post-mortem
  prescribed.
- **`countBefore` derived, never hardcoded** — see
  [case=8](./1.vision.experience.case=8.clamp-derives-the-path.md).
