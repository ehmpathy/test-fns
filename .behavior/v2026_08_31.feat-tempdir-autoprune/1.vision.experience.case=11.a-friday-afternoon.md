# case=11 — a friday afternoon: five ownership classes in one directory

> the **dense** walk · **9** boundaries in one realistic session · **feel** happy + ⚡ sharp
> **care** critipath — it is the only case that tests the boundaries' **interaction**

> 🟠 **the headline count must match the body**: **five** classes (A–E), **nine** boundary rows.
> cases 12, 13 and 14 each contribute a boundary to this composite, and **a stale headline on the
> densest artifact is the worst place to have one**: a reviewer who trusts it under-scrutinizes
> exactly the rows that arrived last — class **E** and boundaries **7–9**, which are the pre-empted
> teardown, the unreadable name, and the reclaim-of-zero. the catalog (region 5) carries the same
> numbers, and the two must agree.

> the density brief warns: *"a vision of only sterile single-boundary demos is thin."* cases 1–10
> each exercise one or two boundaries in isolation. **not one of them puts the boundaries in the
> same room at the same time** — which is exactly where the density brief says defects cluster.

## why this walk, and not another

the highest-risk state this design can reach is **one contained directory that simultaneously
holds five distinct ownership classes**:

| class | who owns it | must be reclaimed by |
|---|---|---|
| **A** — a dead run's residue | no one (the run was `kill -9`'d) | the age gate, eventually |
| **B** — a held set | a human who will inspect it | the human, or the age gate |
| **C** — a live peer's fixtures | a live process, right now | that peer's own teardown |
| **D** — this run's own | this run | this run's teardown, now |
| **E** — dirs the gate cannot read | an older version, or a foreign tool | **no one — ever** |

every case from 1–10 tests one class against an empty room. **this case tests the run that must
correctly distinguish all five at once** — reclaim exactly D, and leave A, B, C, and E untouched
for four *different* reasons.

> **class E exists because**
> [case=14](./1.vision.experience.case=14.the-stamp-must-not-break-the-age-gate.md) establishes
> that `computeStaleDirs.ts:28-29` **preserves an unparseable name forever, with no signal**. a
> repo with 12,369 dirs of mixed vintage certainly holds some. E is the class whose members are
> **immortal by design and invisible by default**, and the friday afternoon is the only walk that
> puts it beside the four classes that do get reclaimed.

that is a real friday afternoon in a repo with worktrees, and it is the state under which a
plausible implementation quietly gets it wrong.

## the narrative

kai, friday, one repo, two worktrees, three hours.

**already there, since before that friday began** — 30 dirs whose names the age gate cannot parse.
some predate the version that added the stamp; one belongs to a foreign tool that borrowed the
directory. kai has never seen them and never will.
→ **30 dirs (class E)**, immortal, invisible.

**14:05** — kai starts the full suite in `worktree-1`. four minutes, 200 fixture dirs.

**14:07** — it hangs on a deadlock. `ctrl-c` does not take. `kill -9`. gone.
→ **200 dirs (class A)** sit in the contained dir with a dead run id. kai shrugs; kai has a bug to
find.

**14:12** — kai reruns the failed subset with the hatch open, to look at the fixture:
`TEST_FNS_KEEP=true npm test -- --scope 'path://genTempDir'`. it fails, and holds its dirs.
→ **12 dirs (class B)** held, and the run told kai exactly where they are.

**and B's setup speaks the one sentence no run has ever spoken.** A's marker is `open` and A's
process is gone, so B's arrears check names A's 200 dirs — *"a prior run was interrupted"* — then
**stamps the marker reported**. one line, once, from the first run that sees it. see *the arrears
check speaks once*, below.

**14:20** — kai opens one, finds the bug, starts a fix. meanwhile a teammate's CI agent — or kai's
own second worktree — begins a full run in `worktree-2`. after #66 that shares kai's contained dir.
→ **150 dirs (class C)**, live, mid-flight. its setup sees A's marker already stamped, and says no
word.

**14:24** — kai's fix is in; kai runs the suite clean in `worktree-1`.
→ **200 dirs (class D)**, and its teardown fires while C is still live. D's setup, like C's, is
silent about A.

**this is the moment.** kai's teardown must reclaim its own 200 and leave 392 dirs alone —
200 dead, 12 held, 150 live, 30 unreadable — each for a different reason, and it must get all four
right with no notion of which is which beyond the id in the name.

**14:25** — kai's run finishes green and silent. the other four sets are exactly as they were.
kai never thinks about any of it.

**16:38** — the second worktree starts its integration suite, **C2** — the slow one. it will still
be mid-flight a quarter of an hour later.

**16:40** — kai runs the suite once more, on the CI box. it passes, and the job's hard timeout
lands two seconds later — the process takes a `SIGKILL` before its teardown completes.
→ **180 dirs (class D2)** left with an **uncleared marker**, and the run says no word — it cannot;
it is already gone.

**16:52** — kai runs the suite again — **the first run to start since D2 died**. the arrears check
at its setup finds **two** uncleared markers, twelve minutes and fourteen minutes old, and must name
exactly one of them.
→ it names **D2** and spares **C2**. the distinction between *a teardown that failed* and *a run
still at work* is made here or not at all — **and it cannot be made by age**, which is the lesson
this pair of runs exists to force. see *the discriminator*, below.

**17:04** — C2 finishes and its teardown reclaims its own 90, exactly as C's did at 14:25. kai
notices no part of this either. → the contained dir is down to A's 200, B's 12, D2's 180 and E's 30.

**the tuesday after next, 09:02** — the CI command runs again and is pre-empted again.
→ **40 dirs (class G)**, minutes old, marker uncleared.

**the tuesday after next, 09:15** — 11 days on, so the **24-hour** window has elapsed for every dir
made that friday: classes A, B **and D2** are all taken by the gate on the next call to
`genTempDir`. one of A's dirs is a read-only `git init` artifact that will not delete — so that run
reclaims the rest and reports the single residue by name. **class E is spared, because the gate
must never delete what it cannot read — and its 30 are counted aloud rather than skipped in
silence.** and **class G is spared for a third reason: it is not yet aged** — the same reason a
live peer's dirs are spared, which is a coincidence the gate must not try to unpick.

> 🔴 **the clock must be derived, never asserted.** A, B and D2 were **all made on that friday**,
> 2.5 hours apart, so no gate-run moment exists at which A is aged and D2 is not — neither at 3
> days nor at 11. **class G is the honest carrier of the *too young* verdict**: a run pre-empted
> thirteen minutes before the gate fires, rather than a run pre-empted eleven days before it. to
> move the clock without a re-derivation of which populations the move sweeps carries the fault
> forward instead of clears it.

## 🔴 the discriminator — age cannot separate a dead run from a live one

`[t6]` fires the arrears check **twelve minutes** after D2 was pre-empted, while `case=12` defines
that check as *"bounded by a liveness window — the check fires only for markers older than a run
could plausibly still be live."* twelve minutes is inside any such window. so under an age-bounded
mechanism, **D2 would not be named** and `[t6]`'s whole point evaporates.

the contradiction is not local to this file. two of the vision's own claims pull opposite ways:

| the claim | what it demands of the window |
|---|---|
| the yield: *"a pre-empted run in `unit:jest` is reported by `unit:vitest` in the same `npm test`, **seconds later**"* | **short** — shorter than the gap between two invocations |
| `case=12` `[t5]`: a **live peer's** marker must raise no alarm | **long** — longer than the longest suite |

a single age threshold cannot satisfy both, and the gap between them is not a matter of a better
value: a suite that runs 8 minutes and a next invocation that starts 2 seconds later leave **no**
number that is correct.

**the resolution, and it is available only to this check.** the marker records the run's **pid and
its start time**; the arrears check asks whether that process is still alive:

```
   a marker is ARREARS when
     state ∈ { open, partial }        the teardown did not settle it
     AND the process is GONE          pid+startedAt no longer names a live process
```

- **prompt** — a pre-empted run's process is genuinely dead the instant it is torn down, so the
  next invocation names it seconds later
- **safe** — a live peer answers, at any suite duration, so it is never accused
- **and it does not break `case=4`'s rule.** case=4 forbids a reap by liveness guess — *"never
  delete what merely looks abandoned."* **the arrears check never deletes**; `[t6]`'s third `then`
  asserts exactly that. a liveness signal may decide what to *report*; it may never decide what to
  *remove*. the two sweeps have different powers and therefore different licences.

the **age window survives as the fallback**, not the primary: where the liveness question cannot be
answered — a marker from another machine on a shared mount, a platform that will not let us query —
fall back to age and stay silent until it elapses. **fail toward silence, never toward a false
accusation**, since the cost of a wrong name is an adopter who audits a config that was never at
fault (the exact harm cell 25 records).

> the general shape, worth a record: **a mechanism's constraints are set by its powers.** the age
> gate deletes, so it must be conservative and may use only facts it cannot be wrong about. the
> arrears check reports, so it may use a fact that is occasionally unavailable. to apply the gate's
> constraint to the check buys a window that cannot exist.

## 🔴 the arrears check speaks ONCE — and this walk is why

read this composite against `case=12`'s promise that the arrears check names a `kill -9`'d run's
residue *"for free"*, and the two demos assert one mechanism two contrary ways. run **A** is killed
at 14:07 with an `open` marker and a dead process, so it satisfies the arrears predicate — **and it
satisfies it still, eleven days on.** under an unbounded predicate, B, C2, D2 and *every run in
between* name A, and `[t3]`'s *"D said no word"* is red.

**this walk is where that surfaces, and no sterile demo can reach it.** case=12's own timeline runs
a residue for exactly one later run, so a predicate with no bound and a predicate that speaks
once behave identically there. only a walk that carries **one residue across six later runs** tells
them apart — the same reason this composite exists at all.

the settled repair lives in `case=12` (*"conditional is not a bound"*): the marker carries a
nullable **`reportedAt`**, the predicate gains `AND reportedAt is null`, and the check stamps every
marker it names. so the friday reads:

| run | its setup sees A's marker as… | it says |
|---|---|---|
| **B**, 14:12 | open · process gone · **unreported** | ⚡ names A's 200, stamps the marker |
| **C**, 14:20 | open · process gone · **reported** | no word |
| **D**, 14:24 | open · process gone · **reported** | no word — `[t3]`'s silent friday |
| the 16:52 run | A reported; **D2** open, gone, unreported | ⚡ names D2, and only D2 |

**the residue is named when it appears, then it is quiet.** that is the honest sense of
*"one line at the start of a run would have surfaced the 12,369 dirs on day two"* — the value was
always in the **first** line, never in the next four hundred.

boundaries 7–9 come from cases 12, 13 and 14, each of which introduces a boundary this composite
must then carry. **a stale composite is worse than an absent one** — it advertises breadth it no
longer has. the walk below carries all nine.

nine boundaries, one session. and three interactions that **no** sterile case reaches:

> **1 — at 14:24, an implementation that looks correct and filters "dirs older than my run's start"
> reaps all five classes.** it passes case=1 (empty room), passes case=5 (only two classes), and
> destroys 362 dirs here — 150 of them live.

> **2 — at 14:25, run D's own reclaim matches 200 out of `A + B + C + D + E` entries.** `case=10`'s
> invariant asks *an **orphan** exists ∧ matched == 0*; here matched is 200, so it correctly stays
> silent. but an implementation that reasoned *"I matched far fewer than I saw, so we have a
> defect"* would fire on every crowded dir — and a crowded dir is the normal case, not the exotic
> one. **the invariant must never compare against what this run SAW** — the contained dir is a
> shared namespace, so what it saw belongs partly to four other parties.
>
> 🟠 **the figure is a population, never a bare total.** `A + B + C + D` alone silently drops
> **class E's 30**, which sit in the same namespace and predate the whole friday. **a number
> derived from a population goes wrong the moment the population changes** — the exact inverse of
> the other defect in this class, a population that is asserted but never real. stated as
> `A + B + C + D + E`, the next class added to the walk makes the sum visibly incomplete rather
> than quietly wrong.

> **3 — once the window elapses, the age sweep renders THREE verdicts in one pass over one
> directory**: **take** the aged and readable (A, B, D2), **spare-and-count** the unreadable at any
> age (E), **spare-silently** the readable but not yet aged (G). a sweep that treats "cannot read"
> the same as "not mine" loses E's count; one that treats it the same as "stale" deletes a
> stranger's data; and one that takes G reaps by *"looks abandoned"*, which is `case=4`'s forbidden
> liveness probe by another name.
>
> ⚠️ **there is no fourth verdict, and *"spare C, still live"* is the one that tempts.** the gate
> has no notion of liveness — **it spares a live peer's dirs because they are YOUNG, by the
> identical predicate that spares G.** so *spare-because-live* and *spare-because-young* are one
> verdict under two names, and to count them twice is to imply the gate makes a distinction it must
> never attempt. the live-versus-dead distinction belongs to the **arrears check**, one sweep over,
> where it is safe because that check reports rather than deletes. **conflation of the two sweeps'
> powers is the precise error this composite exists to catch.**

each of the three is invisible to every other demo in the set, because each needs the crowd.

## the populations, dated — so every verdict below is derivable

a dated table cannot prevent a wrong assertion, but it makes one **checkable without a re-read of
the narrative**.

| run | made | dirs | at 09:15, day 11 it is… | **settled at** | the gate's verdict | left after |
|---|---|---|---|---|---|---|
| **A** — killed | fri, day 0, 14:07 | 200 | **11 days** old | `[t9]` (the gate) | **take** | **1** ⚠️ |
| **B** — held | fri, day 0, 14:12 | 12 | **11 days** old | `[t9]` (the gate) | **take** | 0 |
| **C** — live peer | fri, day 0, 14:20 | 150 | already reclaimed | **`[t4]`** — C's own teardown | — (gone) | 0 |
| **D** — clean | fri, day 0, 14:24 | 200 | already reclaimed | **`[t3]`** — D's own teardown | — (gone) | 0 |
| **E** — unreadable | before day 0 | 30 | any age, **name unparseable** | never | **spare + count** | **30** |
| **D2** — pre-empted | fri, day 0, 16:40 | 180 | **11 days** old | `[t9]` (the gate) | **take** ⚠️ | 0 |
| **C2** — live peer | fri, day 0, 16:38 | 90 | already reclaimed | **`[t6a]`** — C2's own teardown | — (gone) | 0 |
| **G** — pre-empted | day 11, 09:02 | 40 | **13 minutes** old | not yet | **spare, too young** | **40** |
| **16:52** — observer | fri, day 0, 16:52 | **0** | reported D2, allocates none | its own teardown | — (holds none) | 0 |
| **09:15** — observer | day 11, 09:15 | **0** | **live at `[t9]`**, allocates none | not yet — mid-run | — (holds none) | 0 |
| | | | | | **total left** | **71** |

⚠️ **the `settled at` column ends a whole class of defect: a population pinned at one step and
unaccounted at a later whole-dir count.** a C2 row that says *"reclaimed by C2 itself"* with no step
behind it is a declaration — **and a table entry is a declaration, not a step** — so `[t9]`'s *"and
no other"* would silently require a reclaim the walk never performs. that makes the demo
unsatisfiable in both directions: C2 still live leaves 161 dirs and reddens `[t9]`; a gate that
takes C2's 90 commits `case=5`'s data loss on a live peer. the other columns record what each run's
fate **is**; only this one records **which step delivers it**, so only this one can be checked
against the timeline rather than against intent.

> 🔴 **the two OBSERVER rows are the subtle members of that class.** `[t8]` and `[t9]` are performed
> *by* a run, and a run allocates unless told otherwise, so a bare `mintRun()` observer brings an
> **unstated** population into the same namespace the total counts — and the 09:15 observer is
> **live at `[t9]`**, its teardown not yet fired. `[t9]`'s *"and no other"* would then be
> `71 + whatever the observers made`.
>
> the rule that covers the cast is *"a step has a SUBJECT, and the subject must be a mint"* —
> correct, and incomplete by exactly one step: **a subject is a run, and a run is a population.** to
> add an actor to a walk is to add rows to the ledger that walk reconciles.
>
> both are pinned at `allocates: 0` and asserted in `[t9]` alongside the four empty runs. note
> their zero is a **different kind** from the others': A, B, C, D end at zero because a teardown
> reclaimed them, and the observers hold zero because they never allocated. the `settled at` column
> says so per row, which is the whole reason it exists.

⚠️ **the D2 row.** D2 was made on day 0 and the window is 24 hours, so at 09:15 on day 11 it is
**taken**, never spared as *too young* — and the *too young* verdict needs a population that is
genuinely young, which is **G** (13 minutes old).

⚠️ **the A row.** `pathBad` — the read-only `git init` artifact the gate cannot delete — **is one of
A's own dirs**, so A ends at **1**, not 0. to assert `RA === 0` and, four lines later, assert that
residue survives is a pair **a correct implementation could satisfy neither of**; `case=9`'s settled
contract (reap the rest, name the residue, leave it) is exactly what forbids RA to reach 0.

**one column does the work for the verdict:** *made*. every gate verdict follows from that date and
the 24-hour window alone, with no appeal to whose run it was or whether the process still lives —
which is precisely the discipline the gate must keep. **the `left after` column exists because the
verdict alone is not the population**: *take* is what the gate attempts, and one dir refused.

## the timeline

```gherkin
given('[case11] one contained dir, five ownership classes, one friday', () => {

  // ⚠️ EVERY handle this walk uses is minted here, once, up front. an unbound
  //    handle in a sketch is a CLASS defect of the file, and a per-line fix
  //    guarantees the next reader finds another one a line over. so the whole
  //    cast is declared together, rather than at the line that first needs it.
  const { pathPhysical } = getOneTempDirRoot();

  const RA  = useThen('run A starts in worktree-1, fri 14:05', () => mintRun());
  const RB  = useThen('run B starts with the hatch open, fri 14:12', () => mintRun({ keep: true }));
  const RC  = useThen('run C starts in worktree-2, fri 14:20', () => mintRun());
  const RD  = useThen('run D starts in worktree-1, fri 14:24', () => mintRun());
  // ⚠️ C2 starts BEFORE D2, and that order carries weight. a run's setup fires
  //    the arrears check, so if C2 started after D2 it would name D2 first and
  //    stamp it — and [t6]'s run, two minutes later, would find it reported
  //    and stay silent. C2 is the slow integration suite, still mid-flight at
  //    [t6].
  const RC2 = useThen('run C2 starts in worktree-2, fri 16:38', () => mintRun());
  const RD2 = useThen('run D2 starts and is killed by a signal, fri 16:40', () => mintRun({ preempted: true }));
  const RG  = useThen('run G starts and is killed by a signal, day 11 09:02', () => mintRun({ preempted: true }));

  // ⚠️ a sweep of the identifiers a step READS is right and incomplete. two
  //    more kinds of handle live in prose alone unless the cast declares them:
  //
  //      1. the OBSERVER runs. [t6], [t8] and [t9] are each performed BY a run
  //         ("the first run since D2 died", "that SAME run"). an assertion that
  //         reads a bare `stderr` is bound to no run at all. same class as
  //         case=12 [t6] — "an assertion about a later run needs that later run
  //         to be a STEP".
  //      2. the class-E POPULATION. [t9] asserts 30 unreadable dirs, so a step
  //         must put them on disk. same class as case=14 — "a name is not an
  //         entry" — repaired there by `makeDirAt`.
  //
  //    a step has an ID-SET (what it reads), a SUBJECT (who performs it) and a
  //    WORLD (what is on disk). the cast declares all three.

  // ⚠️ both observers are pinned at `allocates: 0`. a bare `mintRun()` makes an
  //    UNSTATED number of its own dirs — live in the shared namespace at the
  //    moment [t9] counts it — so [t9]'s "and no other" would be `71 + whatever
  //    the observer made`, and a correct implementation that gives R0915 one
  //    fixture dir turns it red. an observer is a run, and a run allocates
  //    unless told otherwise: **to add a subject is to add a population.**
  //
  //    `allocates: 0` is the vocabulary case=10 [t4] already uses. it is not a
  //    convenience: a run whose tests never call genTempDir is the ordinary
  //    case, and it keeps the observers observers rather than participants.
  const R1652 = useThen('the first run to start since D2 died, fri 16:52 — allocates none', () =>
    mintRun({ allocates: 0 }),
  );
  const R0915 = useThen('a run on day 11 at 09:15 — the one [t8]/[t9] observe, allocates none', () =>
    mintRun({ allocates: 0 }),
  );

  // the read-only `git init` artifact the gate will meet at [t9]. it belongs
  // to run A — which is why [t9] asserts RA === 1 rather than 0.
  const pathBad = useThen('one of A\'s dirs is made unremovable', () =>
    makeUnremovable(oneDirOf(RA)),
  );

  // class E — 30 dirs whose names the age gate cannot parse. they predate this
  // friday entirely, so they are written directly rather than by a run: no run
  // in this walk could have made them, which is the whole point of the class.
  const pathsUnreadable = useThen('30 legacy-named dirs already sit in the dir', () =>
    range(30).map((i) =>
      makeDirAt(join(pathPhysical, `legacy-fixture-${i}`), { agedBy: days(30) }),
    ),
  );

  when('[t-1] before the friday begins, class E is already on disk', () => {
    then('they are present, aged past the window, and no name parses', () => {
      expect(pathsUnreadable.length).toEqual(30);
      expect(countTempDirs(pathPhysical, { unreadable: true })).toEqual(30);
      expect(countTempDirs(pathPhysical, { agedBeyondWindow: true })).toEqual(30);
    });

    then('and they belong to no run in this walk — that is what makes them class E', () => {
      // a dir the gate cannot parse cannot be attributed to anyone. so no
      // run-scoped filter reaches them, and only the gate can ever see them.
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(0);  // A has not started
    });
  });

  when('[t0] run A is killed mid-flight and leaves 200 dirs with a dead id', () => {
    then('class A sits in the dir, unowned', () => {
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
    });
  });

  when('[t1] run B finishes with the hatch open, and holds 12', () => {
    then('class B is held, and B said where', () => {
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(12);
      expect(stderrOf(RB)).toContain(getOneTempDirRoot().pathPhysical);
    });

    then('B did NOT touch the dead run\'s residue', () => {
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
    });
  });

  when('[t1a] B\'s SETUP ran the arrears check, before any of the above', () => {
    // ⚠️ A's marker is open and A's process is gone, so A is arrears — and
    //    STAYS arrears for eleven days. a predicate with no `reportedAt` term
    //    makes every run below name A, which turns [t3]'s silent friday red.
    //    this step and [t2]'s last `then` are the pair that pin the bound; see
    //    "the arrears check speaks ONCE", above.
    then('B named A\'s residue — the FIRST run whose setup sees it', () => {
      expect(isProcessAlive(markerOf(RA))).toEqual(false);
      expect(stderrOf(RB)).toContain(RA);
      expect(stderrOf(RB)).toContain(String(200));
    });

    then('it names a CLASS of cause, never one specific cause', () => {
      // an interrupt, a CI timeout and an OOM leave IDENTICAL evidence — an
      // unsettled marker whose process is gone. so the message may name the
      // class and must not pick a member of it: a guess that lands wrong
      // sends a human to audit a mechanism that was never at fault.
      expect(stderrOf(RB)).toMatch(/signal|timeout|OOM|interrupt/i);
      expect(stderrOf(RB)).not.toContain('--forceExit');
    });

    then('and the report STAMPED the marker — reported, still unsettled', () => {
      expect(markerOf(RA).reportedAt).not.toEqual(null);
      expect(markerOf(RA).state).toEqual('open');  // reported ≠ settled
    });

    then('it reaped no dir — A\'s 200 are all still there', () => {
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
    });
  });

  when('[t2] run C starts in the other worktree and is still LIVE', () => {
    then('all three classes coexist in one dir', () => {
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);  // dead
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(12);   // held
      expect(countTempDirs(pathPhysical, { run: RC })).toEqual(150);  // live
    });

    then('C\'s setup said no word about A — already reported at [t1a]', () => {
      // the bound, observed: the SAME marker that made B speak makes C silent
      expect(markerOf(RA).state).toEqual('open');   // still arrears by state
      expect(isProcessAlive(markerOf(RA))).toEqual(false);  // and by process
      expect(stderrOf(RC)).not.toContain(RA);            // and yet: silence
    });
  });

  when('[t3] run D finishes clean and its teardown fires — THE MOMENT', () => {
    then('D reclaimed exactly its own 200', () => {
      expect(countTempDirs(pathPhysical, { run: RD })).toEqual(0);
    });

    then('the broken-chain invariant did NOT fire on a crowded dir', () => {
      // D matched 200 of the entries it SAW — A(200) + B(12) + C(150) + D(200)
      // + E(30), stated as a population so a new class cannot silently shrink
      // it. the guard asks neither "how many did I see"
      // nor "did the dir grow" — both are shared-namespace facts. it asks
      // whether a FRESH, UNSTAMPED entry exists. every entry here is stamped
      // by someone, so the orphan population is empty and the guard is silent.
      expect(countTempDirs(pathPhysical, { orphan: true })).toEqual(0);
      expect(countTempDirs(pathPhysical, { run: RD })).toEqual(0);  // matched, then reclaimed
      expect(errorOf(RD)).toEqual(null);
    });

    then('and class E does NOT make an orphan of itself, though it carries no id', () => {
      // the sharpest test of the predicate's SECOND term, and it is only
      // available because [t-1] puts class E on disk. those 30 dirs carry no
      // run id at all — the first half of "orphan" exactly — and the guard
      // stays silent because they are 30 days old and an orphan must be FRESH.
      // a predicate written on "unstamped" alone would fire on every consumer
      // who has ever had a legacy dir, forever.
      expect(countTempDirs(pathPhysical, { unreadable: true })).toEqual(30);
      expect(countTempDirs(pathPhysical, { orphan: true })).toEqual(0);
    });

    then('the dead run\'s 200 are untouched', () => {
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
    });

    then('the held 12 are untouched', () => {
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(12);
    });

    then('the LIVE peer\'s 150 are untouched, and still readable', () => {
      // ⚠️ a cast that binds every RUN id can still leave the handles DERIVED
      //    from one unbound, which is why `dirsOf(RC)` is spelled from RC here.
      //    the count alone cannot carry this claim either: a dir can be emptied
      //    while its entry survives, so the readability half is what makes this
      //    about a live process's DATA.
      expect(countTempDirs(pathPhysical, { run: RC })).toEqual(150);
      for (const dir of dirsOf(RC)) expect(existsSync(dir)).toEqual(true);
    });

    then('D said no word — a crowded dir is still a silent success', () => {
      // ⚠️ against case=12's arrears mechanism, A is STILL open with a dead
      //    process, so an unbounded predicate names it here. the silence is
      //    legitimate for ONE stated reason — A was reported at [t1a] and its
      //    marker stamped. without that bound this assertion is red against a
      //    correct implementation.
      expect(markerOf(RA).reportedAt).not.toEqual(null);
      expect(stderrOf(RD)).not.toContain('test-fns');
      expect(exitCodeOf(RD)).toEqual(0);
    });
  });

  when('[t4] run C then finishes and reclaims its own', () => {
    then('C took its 150 and left A and B', () => {
      expect(countTempDirs(pathPhysical, { run: RC })).toEqual(0);
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(12);
    });
  });

  when('[t5] run D2 passes and is killed by a signal, which pre-empts its teardown', () => {
    then('D2\'s 180 survive and its marker stays open', () => {
      expect(countTempDirs(pathPhysical, { run: RD2 })).toEqual(180);
      expect(markerOf(RD2).state).toEqual('open');
    });
  });

  when('[t6] at 16:52 — the FIRST run since D2 died — C2 is still mid-flight', () => {
    // BOTH markers are uncleared, and BOTH are minutes old. age cannot
    // separate them — see "the discriminator", above. the arrears check
    // asks whether each marker's process is still alive.
    then('both markers are open, and MINUTES apart — so no age can sort them', () => {
      // ⚠️ no `LIVENESS_WINDOW` constant appears here, because this file rules
      //    that mechanism out four sections above. the ages are measured and
      //    compared to each other; the claim is their PROXIMITY, which is what
      //    defeats a threshold. it needs no threshold to state.
      expect(markerOf(RD2).state).toEqual('open');
      expect(markerOf(RC2).state).toEqual('open');
      expect(ageOfMarker(RD2)).toBeLessThan(minutes(20));   // 12 min
      expect(ageOfMarker(RC2)).toBeLessThan(minutes(20));   // 14 min
      // the claim is their PROXIMITY — no threshold can pass between them
      expect(Math.abs(ageOfMarker(RD2) - ageOfMarker(RC2))).toBeLessThan(minutes(5));
    });

    // ⚠️ the OBSERVER is R1652, and every `then` below reads what THIS run's
    //    setup printed. a bare `stderr`, bound to no run at all, cannot answer
    //    the step's whole question — "which of three markers does this ONE pass
    //    name?"
    then('it names D2 — its process is GONE, so the teardown will never fire', () => {
      expect(isProcessAlive(markerOf(RD2))).toEqual(false);
      expect(markerOf(RD2).reportedAt).toEqual(null);  // unreported: this run is the first since
      expect(stderrOf(R1652)).toContain(RD2);
      expect(stderrOf(R1652)).toMatch(/teardown never ran/);
    });

    then('it does NOT name C2, whose process is still ALIVE', () => {
      // the one assertion that separates "failed" from "still at work".
      // it fails under ANY age-only rule, since both markers are minutes old.
      expect(isProcessAlive(markerOf(RC2))).toEqual(true);
      expect(stderrOf(R1652)).not.toContain(RC2);
    });

    then('and it says no word about A — arrears still, reported four hours ago', () => {
      // three markers, three different reasons for the verdict: D2 named
      // (gone, unreported), C2 spared (alive), A spared (already reported).
      // an implementation with any TWO of the three terms gets one of them wrong.
      expect(markerOf(RA).state).toEqual('open');
      expect(isProcessAlive(markerOf(RA))).toEqual(false);
      expect(stderrOf(R1652)).not.toContain(RA);
    });

    then('and it reaped no dir at all — it reports, never reaps', () => {
      expect(countTempDirs(pathPhysical, { run: RD2 })).toEqual(180);
      expect(countTempDirs(pathPhysical, { run: RC2 })).toEqual(90);
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);
    });
  });

  when('[t6a] at 17:04 C2 finishes, and reclaims its own 90', () => {
    // ⚠️ without this step [t9]'s whole-dir sum is unreachable: C2 is PINNED
    //    live at [t6] with 90 dirs, and the walk jumps straight to day 11. the
    //    dated table says "reclaimed by C2 itself" — but **a table entry is a
    //    declaration, not a step**, and the sum needs the fact, not the claim.
    //
    //    the two ways to close that gap are mutually exclusive, which is what
    //    makes it a blocker rather than a gap: if C2 truly still ran, [t9]'s
    //    count is 161 and red; if the gate took C2's 90, that is case=5's data
    //    loss on a live peer. no implementation could satisfy the demo.
    //
    //    the class is "a population pinned at one step and unaccounted at a
    //    later whole-dir count". a table that records what each run's fate IS
    //    cannot end it; a table that records WHICH STEP delivers that fate can.
    //    hence the `settled at` column.
    then('C2 took its own, and left every other class alone', () => {
      expect(countTempDirs(pathPhysical, { run: RC2 })).toEqual(0);
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(200);   // still dead residue
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(12);    // still held
      expect(countTempDirs(pathPhysical, { run: RD2 })).toEqual(180);  // still pre-empted
    });
  });

  when('[t7] eleven days on, run G is pre-empted at 09:02', () => {
    then('G leaves 40 dirs, minutes old, with an open marker', () => {
      expect(countTempDirs(pathPhysical, { run: RG })).toEqual(40);
      expect(markerOf(RG).state).toEqual('open');
    });
  });

  when('[t8] at 09:15 the next run starts, and its SETUP speaks for G', () => {
    // ⚠️ "the NEXT run's arrears check" dangles unless [t8] and [t9] sit in the
    //    order ONE run executes them: G was pre-empted at 09:02 and the 09:15
    //    run IS the next run, so its setup fires BEFORE its own gate sweep. no
    //    run H exists in this walk.
    // ⚠️ that one run is R0915, minted in the cast. to put two steps in the
    //    order one run executes them, with no such run in the cast, is half a
    //    repair: the observer must be a subject before it can print a word.
    then('G is named — its process is gone and no run has said so yet', () => {
      expect(isProcessAlive(markerOf(RG))).toEqual(false);
      expect(markerOf(RG).reportedAt).toEqual(null);
      expect(stderrOf(R0915)).toContain(RG);
    });

    then('and A, B and D2 raise no word — for two different reasons', () => {
      // A and D2: arrears, but reported on the friday. the bound holds across
      // eleven days, not merely across one afternoon.
      expect(markerOf(RA).reportedAt).not.toEqual(null);
      expect(markerOf(RD2).reportedAt).not.toEqual(null);
      // B: never arrears at all — its teardown fired and CHOSE to hold
      expect(markerOf(RB).state).toEqual('held');
      for (const R of [RA, RB, RD2]) expect(stderrOf(R0915)).not.toContain(R);
    });
  });

  // 🔴 the age gate fires from the SETUP scan, not from a `genTempDir` call.
  //    a trigger on `genTempDir` contradicts R0915's `allocates: 0` pin: a run
  //    that allocates none never calls genTempDir, so the gate could not fire
  //    and the whole sweep below would be unreachable. the setup scan removes
  //    the contradiction AND is the better design — see the yield's "where the
  //    gate fires". the setup already scans this dir for the arrears check, so
  //    the gate rides that scan rather than add a third.
  when('[t9] the SAME setup pass sweeps the age gate', () => {
    // ⚠️ a bare `countTempDirs(pathPhysical)` cannot carry this step, and D2
    //    cannot be held back here as "too young": D2 was made on the same
    //    friday as A and B, so any clock that ages them ages it. class G
    //    carries that verdict.
    then('it TAKES every aged, readable dir it CAN take — D2\'s among them', () => {
      // ⚠️ RA is 1, not 0. pathBad is one of A's OWN dirs (a read-only
      //    `git init` artifact), so A cannot be emptied. to assert RA === 0 in
      //    the same breath as a residue drawn from A that survives is a pair no
      //    correct implementation can satisfy. see the note below the timeline.
      expect(countTempDirs(pathPhysical, { run: RA })).toEqual(1);   // 199 of 200
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(0);   // 12 of 12
      expect(countTempDirs(pathPhysical, { run: RD2 })).toEqual(0);  // 180 of 180
    });

    then('it SPARES class E and COUNTS it — preserve is right, silence is not', () => {
      // ⚠️ these 30 exist because [t-1] WRITES them. a class E that lives in
      //    the narrative and the dated table alone leaves this assertion — the
      //    one that justifies the class at all — to run against an empty
      //    population: red against a correct implementation, or green and
      //    vacuous. "a name is not an entry" (case=14).
      expect(pathsUnreadable.length).toEqual(30);               // the population, cited
      expect(countTempDirs(pathPhysical, { unreadable: true })).toEqual(30);
      expect(stderrOf(R0915)).toMatch(/30 .*could not read/);
    });

    then('and they were aged past the window, so PRESERVE is a real choice', () => {
      // without this the spare is ambiguous: a gate that skipped them merely
      // because they are young would satisfy the count above and prove none of
      // the claim. they are 30 days old — the gate MEANT to keep them.
      expect(countTempDirs(pathPhysical, { unreadable: true, agedBeyondWindow: true }))
        .toEqual(30);
    });

    then('it SPARES class G — not yet aged, and the gate asks no more than that', () => {
      // G is dead and C2 was live, and at this sweep the gate cannot tell them
      // apart — nor may it try. "not yet aged" is one verdict, and a filter
      // that reached past it for "looks abandoned" is case=4's forbidden probe.
      // the window is 24h — shortened from the extant 7d (pruneStale.ts:5),
      // which the marker's pid + startedAt now make safe. G is 13 minutes old,
      // so it is spared under either value; the assertion reads the settled one.
      expect(countTempDirs(pathPhysical, { run: RG })).toEqual(40);
      expect(ageOfDirs(RG)).toBeLessThan(hours(24));
    });

    then('and it names the one dir that would not delete — which BELONGS to A', () => {
      expect(countTempDirs(pathPhysical, { path: pathBad })).toEqual(1);
      expect(isDirOfRun(pathBad, RA)).toEqual(true);  // ties the residue to RA=1 above
      expect(stderrOf(R0915)).toContain(pathBad);
    });

    then('the whole dir sums to its parts — 1 + 30 + 40, and no other', () => {
      // the ONE unfiltered count in this step, placed LAST and reconciled
      // against the named populations above it rather than in place of them.
      //
      // ⚠️ the four EMPTY populations are asserted too. "and no other" is a
      //    claim about every run in this walk, so every run must appear — the
      //    ones that hold zero as loudly as the ones that hold dirs. an absent
      //    C2 row here is exactly what lets its 90 dirs go unaccounted.
      expect(countTempDirs(pathPhysical, { run: RC })).toEqual(0);   // [t4]
      expect(countTempDirs(pathPhysical, { run: RD })).toEqual(0);   // [t3]
      expect(countTempDirs(pathPhysical, { run: RC2 })).toEqual(0);  // [t6a]
      expect(countTempDirs(pathPhysical, { run: RB })).toEqual(0);   // taken above

      // ⚠️ the two OBSERVERS are LIVE at this instant — R0915 is mid-run, its
      //    teardown has not fired — so unlike the four above, their zero is a
      //    property of what they ALLOCATED, never of what was reclaimed. that
      //    is why the cast pins them at `allocates: 0` rather than leave it to
      //    a later sweep.
      expect(countTempDirs(pathPhysical, { run: R1652 })).toEqual(0);
      expect(countTempDirs(pathPhysical, { run: R0915 })).toEqual(0);

      expect(countTempDirs(pathPhysical)).toEqual(1 + 30 + 40);
      //                                          │   │    └─ G, too young
      //                                          │   └─ E, unreadable
      //                                          └─ A's residue, would not delete
    });

    then('and the gate SPARED G that [t8] had just NAMED — one run, two duties', () => {
      // the pair that carries the division of powers. the SAME run, in the SAME
      // invocation, reports G at its setup and then declines to delete G at its
      // gate. that is by design: the sweep that deletes may act only on facts it
      // cannot be wrong about (age); the sweep that reports may use a fact that
      // is sometimes unavailable (liveness).
      expect(countTempDirs(pathPhysical, { run: RG })).toEqual(40);
    });
  });
});
```

## the assertions that carry this case

`[t3]` is the whole point, and within it four `then`s do work no other case does:

1. **"the dead run's 200 are untouched"** — kills the *"reap what looks abandoned"* instinct
2. **"the held 12 are untouched"** — kills *"reap what is not mine"*, since the held dirs are
   genuinely not D's
3. **"the live peer's 150 are untouched, and still readable"** — kills *"reap what is older than
   my start"*, the one that passes every sterile test
4. **"the invariant did not fire on a crowded dir"** — kills *"I matched far fewer than I saw, so
   we have a defect"*. `case=10`'s guard asks for a **fresh, unstamped** entry; every entry here is
   stamped by one of five parties, so the orphan population is empty and the guard is silent. only
   a crowded dir makes *seen* and *ours* differ far enough for a seen-based guard to misfire

then four more, that no sterile case can reach:

5. **`[t6]` "it does NOT name C2, whose process is still alive"** — the single assertion that
   separates *a teardown that failed* from *a run still at work*, **and the only one in the vision
   that an age-only rule fails.** D2's marker is 12 minutes old and C2's is 14 minutes old, so every
   threshold either names both or names neither. case=12's `[t5]` states the rule with a live peer
   and a **stale** dead one, where age happens to work; only here are the two placed minutes apart,
   which is where the stated mechanism breaks and the real discriminator has to appear.
6. **`[t9]` renders the age sweep's THREE verdicts in one pass** — take (A, B, D2 — aged and
   readable), spare-and-count (E — unreadable at any age), spare-silently (G — readable, not yet
   aged). a sweep that collapses any two of them loses E's count, deletes a stranger's data, or
   reaps by *"looks abandoned"*.
7. **`[t8]`/`[t9]` together — one population, two sweeps, opposite duties, ONE RUN.** at 09:15 the
   arrears check **names** G at the setup, and minutes later that same invocation's gate **spares**
   G and says no word. that is not a contradiction but the division of powers: the sweep that
   deletes may act only on facts it cannot be wrong about (age), and the sweep that reports may use
   a fact that is sometimes unavailable (liveness). **no other demo holds one population across
   both sweeps**, so no other demo can show that the two disagree by design.
8. **`[t1a]` / `[t2]` / `[t3]` together — the arrears bound, across one residue and three runs.**
   B names A, then C and D are silent while A's marker stays open and A's process stays dead. no
   sterile demo can catch a predicate with no `reportedAt` term, because a residue that outlives
   exactly one later run behaves the same either way. **this walk carries A across six later
   runs**, which is the only way the absent bound becomes visible.

   > 🔴 **the gate step, `[t9]`, is where three faults converge — and the shape of the three is the
   > lesson.** a bare whole-dir count of `31` cannot stand while D2's **180** dirs sit pinned at
   > `[t6]` with no step that reclaims them. a gate that fires *"next tuesday"* — 3 days — against
   > a **7-day** window never fires at all. and D2 cannot be held back as *too young* on a clock
   > that ages A and B, since the three were made on the same friday 2.5 hours apart.
   >
   > **the first two share one mechanism: the clock moves and the populations it sweeps are not
   > re-derived.** fix a count and the date stays wrong; fix the date and a population lands on the
   > wrong side of it.
   >
   > 🔴 **the third fault sits in the same step:** `RA === 0` cannot hold while `pathBad` — **one of
   > A's own dirs** — survives the sweep. no implementation can deliver both.
   >
   > **a dated table does not catch that third one, and the reason is instructive.** the table
   > records what the gate *decides* (`take`), and A's verdict genuinely is `take`. **a verdict is
   > not a population**: the gate attempts to take all 200 and one refuses. so the table carries a
   > **`left after`** column — what actually survives, which is the quantity the step asserts — and
   > a **total** row that its final `then` must reconcile against (1 + 30 + 40 = 71).
   >
   > **the general lesson:** a derivation table only protects the quantity it actually derives. one
   > built for *dates* proves not one claim about *outcomes*.

each is a different wrong filter, and **each looks correct in isolation.** only the crowded room
tells them apart.

## the guardrail this case respects

per the density brief: *"dense journeys for breadth, focused spotlights for each sharp critipath's
fail-safe."*

this case is the **breadth**. it deliberately does **not** re-prove that the interrupt fails safe,
that the hatch names its fix, or that the residue error teaches the next move — cases 4, 6, and 9
each keep their focused spotlight so those fail-safes stay legible. this walk proves the
boundaries **compose**; the spotlights prove each one is safe.

> across **nine** boundaries is the real claim.
