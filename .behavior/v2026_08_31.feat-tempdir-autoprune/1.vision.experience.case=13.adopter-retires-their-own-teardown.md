# case=13 — the adopter retires the prune machinery they already have

> cell 20 · region 4, the adopter's seam · goal: *"I already hand-rolled a teardown. what now?"*
> **feel** ⚡ **sharp** · **care** critipath — **it is the wish's own acceptance signal for the
> choice of repo**

> ⚠️ the guide's step 1 asks for *every* actor's paths. an actor question settled early — *"one
> actor, two hats"* — leaves the **adopter** hat unwalked. the adopter has four goals, not three,
> and the fourth is the one the wish names in `.why` as the test of whether this fix landed in the
> right repo at all.

## the criterion with no cell

the wish states it as the **acceptance signal for the choice of repo**:

> downstream should end with **no** temp-dir prune, registry, or teardown of its own. if a consumer
> still holds prune machinery once this lands, the fix landed in the wrong repo.

that is a criterion about a **consumer's** end state, and the original grid had no cell for it.
region 4 held three adopter goals — wire the hooks, derive the path, meet a residue — and not the
one the wish uses to judge the whole behavior.

**this is not a hypothetical consumer.** three exist, and one of them is us:

| who | what they hold today | cite |
|---|---|---|
| **`test-fns` itself** | a `createdDirs[]` array + an `afterEach` that `rmSync`s each entry | `genTempDir.acceptance.jest.test.ts:10,16-24` |
| **`nheuron`** | a module-level `DIRS_TEMP` registry + an `afterAll` sweep — the wish's own prior art | wish `.prior art` |
| **any consumer who felt the leak** | whatever they hand-rolled to survive it | — |

the library's own acceptance test is the sharpest evidence. its line 1 declares
`// import from contract layer only (blackbox)`, and line 7 then reaches into internals for
`resetPruneThrottle` precisely because the contract offers no reclaim to reach. **that hand-roll is
a symptom of the defect this behavior repairs, and it must be retired by it** — otherwise we ship
the fix while our own suite still carries the workaround.

## why it is sharp, not merely tidy

a kept hand-roll is not inert. it is the **one shape in the whole design that can reap a peer**.

the wish's prior-art hazard, verbatim:

> **never sweep by a bare prefix glob.** it sweeps only what *this process* made, so a parallel run
> of the same suite cannot reap its peer's live dirs.

a consumer's hand-roll predates our run-id, so it can only filter by what it knew: a prefix, a
path, or a wipe of the whole contained dir. once #66 merges the worktree scopes into one shared
scope, that wipe reaches a **peer's live fixtures** — which is
[case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)'s data loss, reintroduced
by machinery the consumer kept because no one told them to drop it.

so the retire step is not housekeeping. **it removes the last remaining path to loss** in a design
whose whole claim is that every failure mode leaks instead.

## 🔴 the false positive this cell exposes in case=10

here is the finding that makes this cell worth its own file rather than a line in the readme.

a kept hand-roll usually runs **per test file** (`afterEach` / `afterAll`), so it removes our dirs
**before** our `globalTeardown` ever looks. now read
[case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md)'s invariant against that:

```
 dirs made this run   >  0     ← true, the suite made N (N illustrative below)
 dirs matched by id  ==  0     ← true, the hand-roll already deleted them
 ⇒ the chain is broken. fail loud.
```

**both legs hold, and the conclusion is wrong.** the chain is fine. the consumer's own teardown
beat us to the dirs. and the message case=10 prints in that state is actively harmful:

> `this is a test-fns defect against your runner version. please report: …`

so the consumer files an issue about a defect that does not exist, the maintainer burns time on an
unreproducible report, and the actual cause — a hand-roll five lines from the top of their own test
file — goes unnamed. **a guard that misdiagnoses is worse than an absent one, because it sends the
human confidently down the wrong road.**

### the discriminator

the two states are cleanly separable, and the teardown already holds the evidence:

| | dirs the run made are… | means | who fixes |
|---|---|---|---|
| **chain broken** | still **on disk**, with no id in their names | the id never reached the workers | test-fns |
| **hand-roll ran first** | **gone from disk** entirely | another reclaim took them already | the consumer |

so the invariant must ask **what is on disk**, not merely what was counted — and the settled form
asks it in one term rather than two:

```
 an entry exists that is FRESH and carries NO run id   AND   we matched none
 ├─ such an entry EXISTS  ⇒ the chain broke      → MalfunctionError, ours
 └─ no such entry         ⇒ another reclaim ran  → a notice, theirs
```

the **orphan** predicate is what separates the two rows of the table above. a hand-roll that already
deleted our dirs leaves **no entry to find**, so the first term is false and the guard stays silent
— *break vs another-reclaim*, decided by presence rather than by a second lookup.

> ⚠️ **a third conjunct — *do the made paths still exist?* — bolted onto a delta form
> (*made > 0 AND matched == 0*) is NOT the shape**, because a delta over the contained dir counts a
> **live peer's** dirs as ours
> ([case=10](./1.vision.experience.case=10.broken-mint-chain-is-caught.md): the dir is a **shared**
> namespace). conjuncts over a wrong population never converge. the orphan predicate **subsumes**
> the third term rather than sits beside it, and it fires besides on a run that made zero dirs —
> which the delta form cannot detect at all.
>
> **and the current truth must LEAD.** a section that opens with the superseded form and reaches
> the repair only in a footnote hands a reader who stops at the code block the unsound shape, on
> the design's linchpin guard (`rule.forbid.chronological-accretion`).

**a message must be split by cause rather than by symptom, and this is not the only place.**
case=10 already separates *broken chain* from *unhooked* on exactly this principle — same symptom,
opposite cause, opposite fix. this cell adds another member of that family, and the rule
generalizes: **"no dir was reclaimed" is a symptom with at least three causes, and a guard that
names only one of them will confidently misdiagnose the rest.** (case=10's table carries more of
them — among them a peer's dirs, the one cause whose correct verdict is silence, and the
pre-empted-mid-reclaim cause, whose fix is at the filesystem rather than the config.)

> 🟠 **that cross-reference must carry no COUNT.** the family this section describes grows every
> time another cause is found — so a count of it, copied into a neighbour file, is stale on arrival
> and will disagree with the table it names. the family is described by its **rule** rather than by
> its size, and the size is cited only where it lives.

## the narrative

kai maintains a repo that felt the leak last year and hand-rolled a fix for it. kai upgrades
`test-fns`, wires the two config keys, and runs the suite.

```
$ npm run test:integration
  Tests: 118 passed, 118 total

⚠️  test-fns reclaimed 0 of the 432 temp dirs this run made — they were
    already gone when the teardown ran.

    that means another reclaim took them first. the usual cause is a
    hand-rolled teardown from before test-fns did this for you:

      afterAll(() => rmSync(myTempRoot, { recursive: true }))
      afterEach(() => createdDirs.forEach(d => rmSync(d, ...)))

    you can retire it now — the runner hooks you just wired cover it, and
    they cover the cases a hand-roll cannot: a failed run, a scoped run,
    and a parallel run that must not touch its peer's dirs.

    ⚡ that last one matters: a hand-roll that sweeps a path or a prefix
       will delete a PARALLEL run's live fixtures. test-fns filters on
       this run's own id, so it cannot.

    if you have no such teardown, this IS our defect. please report it:
      https://github.com/ehmpathy/test-fns/issues
```

kai deletes eleven lines, re-runs, and the message stops. **kai retired their workaround because
the tool told them it was safe to — rather than kept it forever out of a caution no one ever
addressed.**

## how it fails safe — fast, loud, teaches the fix

| leg | how this case satisfies it |
|---|---|
| **fast** | the very first run after adoption — the exact moment kai is already in the config |
| **loud** | ⚠️ to stderr, with both counts; green exit, because a double-reclaim does no harm today |
| **teaches the fix** | it shows the two hand-roll shapes verbatim, says which cases the hooks cover that a hand-roll cannot, and names the peer-loss hazard as the reason it matters |

**green exit is deliberate here**, and it is the opposite call from case=10's non-zero. a consumer
in this state has a *redundant* reclaim, never a broken one — their dirs are gone, which is the
outcome we wanted. to fail their build over redundancy would punish the consumers who cared enough
to fix the leak themselves. it is `rule.require.status-feedback`, not an error.

## the timeline

```gherkin
given('[case13] an adopter who already hand-rolled a teardown, and now wires the hooks', () => {

  // ⚠️ the cast, declared up front — every demo owes this, so `R` is never a
  //    free variable here.
  const { pathPhysical } = getOneTempDirRoot();
  const R = useThen('the adopter\'s run starts, hooks wired', () => mintRun());

  when('[t0] before adoption — the hand-roll is the ONLY reclaim', () => {
    // ⚠️ this must NOT count `R` — a run minted **hooks wired**. both the
    //    hand-roll AND the hooks' teardown would empty its population, so the
    //    assertion would pass whether or not the hand-roll did any work at
    //    all. the step that establishes the PRE-adoption state needs a run
    //    with no hooks, or it is satisfied by the very mechanism this cell
    //    exists to retire.
    //
    //    the class: **a control needs the condition removed, never merely a
    //    different label.** a block titled "before adoption" over a cast that
    //    says otherwise is no control — a title is not a step.
    const RPre = useThen('a run BEFORE adoption starts — no hooks wired', () =>
      mintRun({ wired: 'none' }),
    );

    then('it works, but only for THIS process and THIS path', () => {
      expect(countTempDirs(pathPhysical, { run: RPre })).toEqual(0);
    });

    then('and the reclaim was genuinely the hand-roll\'s — no hook could have run', () => {
      // the isolation a hooks-wired run cannot give
      expect(hooksWiredFor(RPre)).toEqual(false);
      expect(handRollRanFor(RPre)).toEqual(true);
    });
  });

  when('[t1] the adopter wires the hooks and keeps the hand-roll', () => {
    // ⚠️ the teardown's own report, minted in-body — never a bare
    //    `reclaimAudit` bound nowhere. unbound, the SYMPTOM half of this
    //    discriminator throws rather than evaluates, and a reader cannot tell
    //    the two halves apart at all.
    const auditOfR = useThen('our teardown yields what it matched', () =>
      runTeardownFor(R),
    );

    then('the hand-roll runs first and takes the dirs', () => {
      expect(countTempDirs(pathPhysical, { run: R })).toEqual(0);
    });

    then('our teardown matched none of its own — the symptom', () => {
      // the symptom ALONE is ambiguous: a healthy hand-roll and a broken mint
      // chain produce the identical zero. the discriminator is the NEXT step.
      expect(auditOfR.countMatched).toEqual(0);
    });

    then('but NO orphan exists, so the guard stays silent — the discriminator', () => {
      // the settled invariant needs an entry that is FRESH and carries NO run
      // id. the hand-roll DELETED our dirs, so there is no orphan to find —
      // which is exactly what separates "another reclaim took them first"
      // from "the chain broke and left them unstamped".
      expect(countTempDirs(pathPhysical, { orphan: true })).toEqual(0);
    });

    // ⚠️ every handle below is scoped to R. this file holds FIVE runs by its
    //    end (RPre, R, RBroken, RSelf, RAdopter); a bare `error` / `exitCode` /
    //    `stderr` across three separate blocks — [t3] among them, whose whole
    //    claim is that a DIFFERENT run throws where this one does not — cannot
    //    stand, because two blocks that assert opposite outcomes against one
    //    unscoped handle cannot both hold.
    then('it does NOT throw — the discriminator caught the difference', () => {
      expect(errorOf(R)).toEqual(null);
      expect(exitCodeOf(R)).toEqual(0);
    });

    then('it does NOT blame test-fns for a defect that is not there', () => {
      expect(stderrOf(R)).not.toContain('this IS our defect');
    });

    then('it names the hand-roll as the cause, and says it is safe to retire', () => {
      expect(stderrOf(R)).toContain('afterAll');
      expect(stderrOf(R)).toContain('retire');
    });

    then('it names the peer-loss hazard — the reason retirement matters', () => {
      expect(stderrOf(R)).toContain('PARALLEL');
    });
  });

  when('[t2] the adopter retires the hand-roll and re-runs', () => {
    // a re-run is a NEW invocation with a NEW id. R is the run that STILL had
    // the hand-roll.
    const RRetired = useThen('the adopter re-runs, hand-roll deleted', () =>
      mintRun({ handRoll: 'retired' }),
    );

    then('the dirs are reclaimed by the hooks alone', () => {
      expect(countTempDirs(pathPhysical, { run: RRetired })).toEqual(0);
      expect(handRollRanFor(RRetired)).toEqual(false);  // the hooks did it, and only they
    });

    then('the notice is gone — a settled repo is a silent one', () => {
      expect(stderrOf(RRetired)).not.toContain('test-fns');
    });
  });

  when('[t3] the dirs are unstamped and STILL ON DISK, with no hand-roll — the true break', () => {
    const RBroken = useThen('a run whose chain broke, with no hand-roll to mask it', () =>
      mintRun({ chain: 'broken', handRoll: 'none' }),
    );

    then('the discriminator must not swallow a real defect', () => {
      expect(countTempDirs(pathPhysical, { orphan: true })).toBeGreaterThan(0);  // the premise
      expect(errorOf(RBroken)).toBeInstanceOf(MalfunctionError);
      expect(exitCodeOf(RBroken)).not.toEqual(0);
    });
  });

  // ⚠️ this step must NOT assert on the SOURCE TEXT of a test file —
  //    `readFile(...).not.toContain('createdDirs')` is a grep, not an
  //    experience: the token could vanish for an unrelated reason, or survive
  //    a rename while the behavior is right.
  //    the acceptance signal is a BEHAVIOR, so it is asserted as one.
  when('[t4] test-fns retires its own hand-rolled teardown', () => {
    const suiteOfGenTempDir = 'src/domain.operations/genTempDir/genTempDir.acceptance.jest.test.ts';
    const RSelf = useThen('the library\'s own suite runs, with NO afterEach of its own', () =>
      runSuiteWithoutHandRolledTeardown({ suite: suiteOfGenTempDir }),
    );
    const RAdopter = useThen('and an adopter\'s suite runs, with THEIRS deleted too', () =>
      runAdopterSuiteWithoutHandRolledTeardown(),
    );

    then('the library\'s fixture dirs are reclaimed — by the library, for the library', () => {
      expect(countTempDirs(pathPhysical, { run: RSelf })).toEqual(0);
    });

    // ⚠️ NOT `importsOf(suiteOfGenTempDir).filter(isInternalReach)` — that is
    //    a SOURCE-TEXT assertion too, so one text-check swapped for another is
    //    no repair at all.
    //
    //    it is brittle in both directions: an import can be renamed while the
    //    boundary is still crossed (green, wrong), or vanish for an unrelated
    //    reason while the code is fine (green, meaningless). it tests the
    //    SPELLING of the solution.
    //
    //    the behavior underneath is what "reached past no boundary" MEANS:
    //    the suite still passes when only the published surface is reachable.
    then('and it reached past no blackbox boundary to do it', () => {
      const RBlackbox = runAdopterSuiteAgainst(publishedContractOnly());
      expect(exitCodeOf(RBlackbox)).toEqual(0);
      expect(countTempDirs(pathPhysical, { run: RBlackbox })).toEqual(0);
    });

    then('a consumer who deletes THEIRS gets the same outcome', () => {
      // the wish's acceptance signal, stated as behavior rather than as text:
      // downstream ends with no prune machinery, and still leaks not one dir.
      expect(countTempDirs(pathPhysical, { run: RAdopter })).toEqual(0);
    });
  });
});
```

## `[t3]` is the assertion that keeps the discriminator honest

`[t0]`–`[t2]` all push toward *"be quieter, do not false-alarm"*. taken alone they would tempt an
implementation that simply stops a throw on `matched == 0` — which would **silence case=10
entirely** and hand back the wish's own worst failure mode.

`[t3]` is the counterweight: the real break must still throw. the discriminator has to *separate*
the two causes, never merely soften the alarm. an implementation that passes `[t1]` by a muted
guard fails `[t3]`, and that is exactly the pressure this cell must apply.

## `[t4]` is the wish's acceptance signal, made checkable

the wish says the signal for a right-repo fix is that **downstream ends with no prune machinery of
its own**. `[t4]` applies that test to the one downstream consumer we control, and turns a prose
criterion into an assertion. if `test-fns`'s own suite still carries `createdDirs` when this lands,
we have not met the standard we set for everyone else.

> ⚠️ sketch, not proof. `reclaimAudit`, `hooksWiredFor` and `handRollRanFor` are illustrative
> handles, not proposed exports.
>
> 🟠 **this note must name only handles the walk still carries.** `[t4]` asserts a behavior, never a
> grep-over-source (`readFile(…).not.toContain('createdDirs')`), so a note that points at a
> `readFile` sends a reader after a handle absent from the walk. **an edit that removes a handle
> must sweep the notes that name it** — the note is a copy of the step's surface, and it goes stale
> the instant the step is rewritten. the same class as the count copies, at the granularity of an
> identifier.
