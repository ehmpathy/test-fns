> cell 13 — **feel** ⚡ **sharp** · **care** critipath — a hold with no human, which the behavior
> **tolerates and bounds loudly**
>

## the narrative — cell 9, the hatch in use

kai's test fails, and the assertion message is not enough. kai needs to see what the fixture
actually looked like — the git history in it, the file the clone produced, the symlink that did
not point where kai expected.

before this behavior, kai got that for free: the dirs were never reclaimed. **the reclaim takes
that away, so it must give it back deliberately.**

```
$ TEST_FNS_KEEP=true npm run test:integration -- --scope 'path://genTempDir'

  FAIL  src/domain.operations/genTempDir/genTempDir.integration.jest.test.ts

🧹 test-fns: TEST_FNS_KEEP is set, so this run KEPT ALL of its temp dirs.
   ├─ at: /tmp/test-fns/test-fns/.temp
   ├─ run: r7f3a91c2
   ├─ scope: every dir this run made — a green run holds them too, since a
   │         global teardown is handed no test results to filter by.
   ├─ they are reclaimed by the age gate after 86400000ms (24h) — widen
   │  that window with TEST_FNS_MAX_AGE_MS, in ms.
   └─ done with them? remove this run's, and no peer's:
        rm -rf "/tmp/test-fns/test-fns/.temp"/*.r7f3a91c2.*
```

kai opens the dir, sees the problem in ninety seconds, and moves on.

> 🔴 **this block is the SHIPPED render, never a sketch of one.** a sketch — a `held 12 temp dirs`
> header and a three-line body — disagrees with the snapshot beside it. see *what the drift cost,
> and what it bought* below: the reconcile runs in **both** directions, because one of the sketch's
> claims is a promise the shipped message had quietly dropped.

### why the hatch speaks when the happy path stays silent

[case=1](./1.vision.experience.case=1.run-passes-leaves-no-residue.md) argues that silence is the
signal all is well. the corollary: **a run that deliberately leaves residue owes the human a
sentence.** without it the hatch is a trapdoor — kai sets the flag once, forgets, and leaks for
weeks with no reminder.

the message earns every line against `rule.require.errors-name-the-fix` and
`rule.require.status-feedback`:

| line | what it answers |
|---|---|
| `TEST_FNS_KEEP is set, so this run KEPT ALL ...` | what happened, and which lever caused it |
| `at:` | where to look — the **physical** path, not the symlink, since a human is about to `cd` there |
| `run:` | which subset is this run's, when the dir holds several runs |
| `scope:` | **how many is "ALL"** — every dir this run made, green or red, and *why* |
| `they are reclaimed ... — widen that window with ...` | fix #1, for a human who needs **longer** |
| `done with them? ... rm -rf "<dir>"/*.<run>.*` | fix #2, for a human who is **done** — a copy-paste |

### 🔴 TWO fixes, because a held run leaves its human in one of two states

a message that names one move for a reader who has two is `errors-name-the-fix` half-met — and the
half a widen-only message meets is the rarer one. by the time a human reads this, they far more
often want the dirs **gone** than want them **longer**. so the message names both.

the removal command is **scoped by the run stamp**, never a bare sweep of the dir:

```
   rm -rf "<dir>"/*.r7f3a91c2.*        ✅ this run's, and no peer's
   rm -rf "<dir>"/*                    ⛔ the one command that reaps a live peer
```

that is [case=5](./1.vision.experience.case=5.peer-parallel-run-is-untouched.md)'s guarantee held in
**prose** as well as in code — *a command we print is as much our act as one we execute*, so a
copy-paste we hand a human owes the same peer-safety our own reclaim owes.

### what the drift cost, and what it bought

> a sketch of the demo asserts `toContain('held')`, `toContain(String(N))` and
> `toMatch(/rm -rf .*\.r/)`; the shipped message says `KEPT ALL`, names no count, and carried no
> `rm` at all. **three disagreements, and they do not all settle the same way** — which is the
> point worth the record:

| the sketch claimed | verdict | why |
|---|---|---|
| the word `held` | **sketch stale** — the render says `KEPT ALL`, which answers *how many* in the same breath | a synonym, and the shipped word is the better one |
| a **count** (`held 12`) | **sketch stale, deliberately** — the hold path does no `readdir`, by design | a count would add a scan, and a throw, to the one path whose whole job is to **not** touch the dirs. `scope:` answers the question a count was reaching for |
| an `rm -rf` copy-paste | 🔴 **SHIPPED MESSAGE stale** — the promise was real and had been dropped | restored above, scoped by the run stamp |

**a demo that disagrees with its proof is not automatically the wrong one.** two of these three are
drift in the sketch; the third is a contract the sketch held for us, and a blanket "the snapshot is
reality, update the docs" pass would delete the evidence rather than the defect. *reconcile in the
direction the argument goes, never in the direction the artifact ranks.*

## the narrative — cell 13, the hatch with no human

the grid produced this cell; a free-list would not have.

someone puts `TEST_FNS_KEEP: 'true'` in a CI workflow to debug one flaky job, and leaves it there.
CI runs 200 times a week. no human ever opens a single one of those dirs, and no teardown ever
reclaims them. **the escape hatch silently becomes an unbounded leak in the one environment with
the highest run volume and the least human attention.**

this is not hypothetical drift — it is the exact failure shape of the wish's own headline: a
mechanism that only an absent human would have caught.

### how it fails safe

the behavior must make an unattended hold **loud and bounded**, not merely permitted. the vision
does not settle *which* of these; it settles that the cell must be closed:

- **loud** — `[t2]` below: the hatch reports to `stderr`, which a build log surfaces, and it names
  the key, the scope, and the bound. ⚠️ **it is the SAME notice an attended run gets** — the
  message detects no CI and words nothing for it. that is settled rather than skipped: a hold in
  CI and a hold on a laptop leave identical residue under one environment-blind bound, so a
  CI-only sentence would be a second render to keep in step with the first, bought with a fact the
  reader of a CI log already has. **`[t2]` must not assert a phrase (`no human` / `unattended`) the
  shipped message never carries** — see *what the drift cost*, above
- **bounded** — the age gate is the only reclaim a held dir has, so this cell is the **second**
  reason (with [case=4](./1.vision.experience.case=4.interrupt-falls-to-the-age-gate.md)) the gate
  must stay

✅ **the fulcrum — *warn* vs *refuse to hold* — is SETTLED: warn loudly, proceed, exit 0.**
refusal would kill the one legitimate use the hatch has in CI — a human who
deliberately debugs a CI-only flake, which is exactly when a fixture cannot be reproduced locally —
and the harm it would prevent is already bounded by the age gate. an explicit env var is rung 2 of
`rule.prefer.prevent-over-correct` (*make it hard*), which that ladder accepts where a legitimate
use exists.

## 🔴 the hold is RUN-WIDE — a failed-test-scoped hold is UNIMPLEMENTABLE

the wish's `.acceptance` asks for a hatch to inspect *"**a failed test's dir**"* — singular, scoped
to a failed test. read literally, that rules the run-wide hold an over-wide **issue proposal** and
shrinks cell 13 to unreachable-on-green.

**that narrow scope cannot be built at the hook this design uses, and the reason is structural
rather than a matter of effort:**

```
   a runner's globalTeardown receives         an afterEach receives
   ────────────────────────────────           ─────────────────────
   NO word about test outcomes                the test's own result
   (it is config, run once, after all)        (per file, per worker)
```

the reclaim hangs off `globalTeardown` **precisely because** no test filter can step around it —
that is this vision's central divergence from the issue's `afterAll` proposal, and it is what buys
`case=3` (a scoped run still reclaims) and `case=12` (a marker one process owns). the same property
that makes the teardown unskippable makes it **outcome-blind**. a failed-test-scoped hold would
require the reclaim to move back into `setupFilesAfterEnv`, which forfeits `case=3` outright.

**so the hold is run-wide, and the message says so out loud rather than lets a human discover it:**

```
   ├─ scope: every dir this run made — a green run holds them too, since a
   │         global teardown is handed no test results to filter by.
```

that line carries the load. it names the **scope** and the **cause** in one breath, so a human who
set the flag to inspect one failure is not surprised by four hundred dirs — which is the `case=6`
`forbid.surprises` obligation the narrow scope reached for by a route that does not exist.

### what this restores to cell 13

| | the narrow scope's claim | the shipped truth |
|---|---|---|
| a **green** CI run with the flag left on | holds not one dir — "the cell cannot arise" | **holds every dir of that run** — the cell is live |
| the cell's grade | unreachable-on-green | **demoed, bounded, and loud** — `[t2]`, exit 0 |
| the bound | (none needed) | the age gate, at 24h, **named in the message itself** |

**cell 13 does not disappear; it is bounded.** `[t2]`'s loud notice is therefore load-bearing rather
than a leftover for the red-run case — it is the *only* guard on a green CI run with the flag set.

*a vision may best-guess a narrow scope; execution is where the guess meets the hook, and the
catalog owes the correction the moment it does* (`rule.require.experience-catalog-evolution`).

## ⚠️ the hold must SETTLE its marker

[case=12](./1.vision.experience.case=12.teardown-never-ran-next-run-says-so.md) has each run write a
marker that its teardown settles, so a marker left `open` is a record of a teardown that never
fired.

**a held run's teardown DID fire** — it ran and chose to keep. so it must record `held`, never
leave the marker `open`. otherwise every subsequent run loudly reports *"a prior run's teardown
never ran"* about a hold a human made on purpose, and blames a signal for a deliberate act.

that false positive lands worst exactly where it hurts most: **cell 13** — a hold in CI, which this
case declares bounded-by-nurture — would emit the wrong alarm on **every** subsequent CI run, which
is how a real alarm gets muted.

**the rule: the hatch does not skip the teardown — it changes what the teardown does.** the reclaim
is suppressed; the marker is still settled, as `held`. and the hold's own message is the one a human
should see, never the arrears check's.

## the timeline

```gherkin
given('[case6] an enhooked run with the hold hatch set', () => {

  // ⚠️ the cast, declared up front — every demo owes this, so R, N, stderr and
  //    exitCode are never free variables here.
  //    the three runs also get three ids: "the SAME run" in [t1] is a second
  //    INVOCATION, and one invocation is one run id (see the yield's
  //    "a run is one runner invocation").
  const { pathPhysical } = getOneTempDirRoot();
  const RHeld = useThen('an ATTENDED run finishes with the hatch set', () =>
    mintRun({ keep: true, attended: true }),
  );
  const N = useThen('it made fixture dirs, and held them', () =>
    countTempDirs(pathPhysical, { run: RHeld }),
  );
  const RPlain = useThen('the same suite runs again, WITHOUT the hatch', () => mintRun());
  const RCi = useThen('an UNATTENDED run finishes with the hatch set', () =>
    mintRun({ keep: true, attended: false }),
  );

  when('[t0] an ATTENDED run finishes with TEST_FNS_KEEP set', () => {
    then('the run\'s dirs survive', () => {
      expect(N).toBeGreaterThan(0);
      expect(countTempDirs(pathPhysical, { run: RHeld })).toEqual(N);
    });

    then('the run says it kept them, and names the SCOPE it kept', () => {
      // .note = "KEPT ALL" plus the `scope:` line, never a COUNT. the hold path
      //         does no readdir by design — a count would add a scan, and a
      //         throw, to the one path whose whole job is to leave the dirs alone
      expect(stderrOf(RHeld)).toContain('KEPT ALL');
      expect(stderrOf(RHeld)).toContain('every dir this run made');
    });

    then('it names the PHYSICAL path, since a human will cd there', () => {
      expect(stderrOf(RHeld)).toContain(pathPhysical);
    });

    then('it names the run id, to disambiguate from peer runs', () => {
      expect(stderrOf(RHeld)).toContain(RHeld);
    });

    then('🔴 it names BOTH fixes — longer, AND gone', () => {
      // a human who reads this is in one of two states; a message that names
      // only the rarer one (the widen) is half-met. see "TWO fixes", above
      expect(stderrOf(RHeld)).toContain('TEST_FNS_MAX_AGE_MS');
      expect(stderrOf(RHeld)).toMatch(/rm -rf .*\.r/);
    });

    then('🔴 and the copy-paste it hands over cannot reap a PEER', () => {
      // a command we PRINT is as much our act as one we execute, so it owes
      // case=5's guarantee too — the stamp is in the glob, never a bare `/*`
      expect(stderrOf(RHeld)).toContain(`rm -rf "${pathPhysical}"/*.${RHeld}.*`);
      expect(stderrOf(RHeld)).not.toContain(`rm -rf "${pathPhysical}"/*"`);
    });
  });

  when('[t1] the SAME suite runs again, WITHOUT the hatch', () => {
    then('its dirs are reclaimed, and the run stays silent', () => {
      expect(countTempDirs(pathPhysical, { run: RPlain })).toEqual(0);
      expect(stderrOf(RPlain)).not.toContain('KEPT ALL');
    });

    then('and it did NOT reclaim the held run\'s dirs — they are not its own', () => {
      // the hold survives a peer's reclaim, which is boundary 2 of case=11
      expect(countTempDirs(pathPhysical, { run: RHeld })).toEqual(N);
    });
  });

  when('[t2] an UNATTENDED run (CI=true) finishes with the hatch set', () => {
    then('the hold does not pass silently — cell 13 is BOUNDED, not rejected', () => {
      // 🔴 the notice is the SAME one [t0] gets, and that is the design rather
      //    than a shortfall. the message detects no CI and words nothing for it:
      //    a hold in CI and a hold on a laptop leave identical residue, and the
      //    bound that carries both is the age gate, which is environment-blind.
      //    a CI-only sentence would be a second render to keep in step with the
      //    first, in exchange for a fact the reader of a CI log already knows
      //
      // .note = this assertion must not reach for
      //         `toMatch(/no human|unattended|ci/i)` — a phrase the shipped
      //         message never carries, and a sketch of a branch never built.
      //         the demo and its proof stay in one story
      expect(stderrOf(RCi)).toContain('TEST_FNS_KEEP');
      expect(stderrOf(RCi)).toEqual(stderrOf(RHeld).split(RHeld).join(RCi));
    });

    then('and the notice names the bound that will take them', () => {
      // "we bound it" is a promise about an upper limit, so the demo must show
      // one. without this, the contract is indistinguishable from "we shrugged".
      expect(stderrOf(RCi)).toMatch(/24h|age gate/);
      expect(stderrOf(RCi)).toContain(getOneTempDirRoot().pathPhysical);
    });

    then('the run does not fail the build over it', () => {
      // loud, not fatal: a leak is not worth a broken pipeline. this is the
      // assertion that settles the CONTRACT as "tolerate and say so" rather
      // than "reject" — an inventory grade of `forbidden` ("the behavior must
      // reject it") would sit directly over this exit code and contradict it.
      // the cell's VERDICT is `demoed`; this line is what it demoes.
      expect(exitCodeOf(RCi)).toEqual(0);
    });
  });
});
```

## `[t1]` is the clamp that keeps the hatch honest

it runs the identical suite with the flag cleared and asserts the opposite outcome. without it,
`[t0]` alone would pass under an implementation whose reclaim never worked at all — the dirs would
survive, the message would print, and every assertion would be green.

**a hatch test that omits the closed-hatch case tests only the message.**

> ⚠️ sketch, not proof. `TEST_FNS_KEEP` is the issue's proposed name, carried forward pending
> `2.1.criteria`.
