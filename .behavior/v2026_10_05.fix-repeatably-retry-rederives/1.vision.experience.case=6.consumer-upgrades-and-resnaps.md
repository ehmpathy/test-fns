# case=6 — a consumer upgrades, resnaps once, and the next flake is rescued (B6) — the dense walk

cells: 6, 7, then 1 · feel × care: sharp → happy × criti · boundaries: 5

## .narrative

`rhachet-roles-bhrain` bumps test-fns. its 18 baselines are keyed `attempt 1`. the first ci run is
red. the human who opens the log does not have to guess why: beside jest's own "new snapshot was not
written" text, each failure carries a test-fns hint — the key lost its `, attempt N` ordinal, an
`attempt 1` twin sits in the `.snap`, run the suite once with `-u` (`RESNAP=true`) and commit. they
do. the `.snap` diff reads as a pure rename: `, attempt 1` gone from 18 keys, bytes unchanged, no
`attempt 2`/`attempt 3` copies. ci goes green. a week later a brain flip mismatches attempt 1 of one
case in ci; attempt 2 re-drives, matches the one key, and the run is green. the retry they adopted
months ago now does what it says.

## .bdd timeline

```
given a consumer repo whose .snap holds only "..., attempt 1 ..." keys
  when [t0] ci runs the suite with --ci after the upgrade
    then the case fails                                                    # legacy-key boundary
    then the failure names the rename and the resnap command               # fail-safe: teaches the fix
  when [t1] the human runs the suite once with -u
    then each "attempt 1" key is renamed to its ordinal-free twin          # rename boundary
    then no "attempt [0-9]" key remains in the .snap                       # obsolete-key boundary
  when [t2] ci runs with --ci again
    then exit 0                                                            # ci boundary
  when [t3] a later ci run flips attempt 1 of one case
    then attempt 2 re-drives and matches; exit 0                           # retry boundary
```

the `[t0]` hint is a sharp critipath's fail-safe: fast (at the failed assertion), loud (in the
test's own error), and it names the fix. without it the human meets 18 reds with jest text that
says only "not written in ci".
