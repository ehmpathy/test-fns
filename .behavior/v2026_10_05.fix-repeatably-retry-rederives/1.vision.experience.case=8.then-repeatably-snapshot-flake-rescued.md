# case=8 — a `then.repeatably` snapshot flake is rescued

cells: 18, 33 (`[t4]`) · feel × care: sharp × criti

## .narrative

a consumer skips the `when` wrapper and puts the retry on the assertion itself:
`then.repeatably({ attempts: 3, criteria: 'SOME' })`. on jest that path has its own `try/catch`
(`givenWhenThen.ts:539-545`), separate from the given/when wrapper — so a fix to the given/when
wrapper alone would leave this door open. today a snapshot mismatch on attempt 1 slips past the
catch (jest suppresses, never throws), the attempt is recorded as passed, attempts 2 and 3 skip, and
the file goes red at `test_done` with the retry never run.

after the change the `then.repeatably` path reads the suppressed errors the same way: attempt 1 is
withheld, attempt 2 runs and matches the one baseline, the file is green. the sharp edge this case
guards is a partial fix — two block kinds repaired, the third still blind.

## .bdd timeline

```ts
given('[case8] a guard whose verdict flips once', () => {
  when('[t0] the guard runs', () => {
    then.repeatably({ attempts: 3, criteria: 'SOME' })('the stdout is stable', async () => {
      const result = await runGuard(); // drives on every attempt
      expect(result.stdout).toMatchSnapshot(); // key: "... when: [t0] the guard runs then: the stdout is stable 1"
    });
  });
});
```

- given a `.snap` that holds the ordinal-free key, jest under `--ci`, and an attempt-1 flip
  - when `[t0]` attempt 1 runs
    - then the suppressed mismatch is read and withheld; the attempt is marked failed, not passed
    - then the log carries `🫧 [withheld] attempt 1 failed, a retry follows: Snapshot ... mismatched`
  - when `[t1]` attempt 2 runs
    - then the guard drives again and matches the ordinal-free key; the test is green
  - when `[t2]` attempt 3 runs
    - then it skips; jest exits 0
  - when `[t3]` every attempt mismatches instead
    - then attempts 1 and 2 are withheld, attempt 3's mismatch surfaces with the diff; jest exits non-zero
  - when `[t4]` the check throws on every attempt, on jest or vitest (cell 33)
    - then the body runs exactly `attempts` times — vitest no longer adds a fourth run (F21)
    - then each run reads its own `attempt` number from the runner
    - then the two non-final failures are withheld; the third surfaces; the runner exits non-zero
