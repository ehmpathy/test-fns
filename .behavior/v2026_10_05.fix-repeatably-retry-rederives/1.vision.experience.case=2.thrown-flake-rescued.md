# case=2 — a thrown flake is rescued (B1, B4)

cells: 2 (jest), 11 (vitest), 23 (fail-every) · feel × care: happy × criti

## .narrative

a factory throws on its first call (a timeout) and returns on its second. under `SOME`, attempt 1's
`useThen` throws, the dependent `then` reads an unset proxy, both are swallowed, attempt 2 drives
again and passes. this works **today** on jest — the scratch probe measured the factory at 2
invocations and the block green. on vitest the same case rides the native per-test `retry`, which
re-runs the hooks per try. the change must keep both so; B1 and B4 become committed tests that clamp
them, one per runner.

## .bdd timeline

```ts
when.repeatably({ attempts: 2, criteria: 'SOME' })('[t0] a flaky drive', () => {
  const result = useThen('it drives', async () => {
    counter++;
    if (counter === 1) throw new Error('timeout');
    return { ok: true };
  });
  then('it is ok', () => expect(result.ok).toEqual(true));
});
```

- given a factory that throws on call 1 and returns `{ ok: true }` on call 2
  - when `[t0]` attempt 1 runs
    - then `useThen` throws; the dependent `then` fails; both are swallowed
    - then the log carries `🫧 [withheld] attempt 1 failed, a retry follows: timeout`
  - when `[t1]` attempt 2 runs
    - then the factory runs again (`counter` = 2); `result.ok` is `true`; the block is green (B4)
  - when `[t2]` the factory instead throws on every call (`fail-every`, cell 23)
    - then `counter` reads `N` after the block — one drive per attempt (B1)
    - then the final attempt's `timeout` surfaces; the block is red
  - when `[t3]` the same file runs under vitest (cell 11)
    - then `[t0]`–`[t2]` hold with identical counts and verdicts
