# research: internal test code patterns

## pattern.1 = acceptance test via child process

**source:** `src/domain.operations/slowtestReporter/slowtestReporter.acceptance.jest.test.ts`

**classification:** [REUSE]

**why:** the progress reporter needs the same acceptance test pattern — run jest in child process with custom reporter, verify outputs.

### citations

**[1]** check built reporter exists (lines 17-22):
```ts
/**
 * .what = failfast if built reporter does not exist
 * .why = acceptance tests require `npm run build` to have been run first
 */
if (!fs.existsSync(DIST_REPORTER)) {
  throw new Error(
    `reporter not built at ${DIST_REPORTER}. run \`npm run build\` first.`,
  );
}
```

**[2]** helper to run jest with reporter (lines 28-71):
```ts
const runJestWithReporter = (input: {
  testMatch: string;
  outputPath: string;
  slow?: number;
}): { stdout: string; exitCode: number } => {
  const jestConfig = `
    module.exports = {
      testEnvironment: 'node',
      testMatch: ['${input.testMatch}'],
      transform: { '^.+\\\\.tsx?$': '@swc/jest' },
      reporters: [
        'default',
        [
          '${DIST_REPORTER.replace(/\\/g, '\\\\')}',
          { ${input.slow ? `slow: ${input.slow},` : ''} output: '${input.outputPath.replace(/\\/g, '\\\\')}' }
        ]
      ],
    };
  `;
```

**[3]** execSync to run jest in child process (lines 52-61):
```ts
try {
  const stdout = execSync(
    `npx jest --config "${configPath}" --rootDir "${FIXTURES_DIR}" --passWithNoTests`,
    {
      cwd: process.cwd(),
      encode: 'utf-8', // note: actual code uses encoding, quoted as encode here
      env: { ...process.env, FORCE_COLOR: '0' },
    },
  );
  return { stdout, exitCode: 0 };
```

**[4]** cleanup temp config after test (lines 69-70):
```ts
} finally {
  if (fs.existsSync(configPath)) fs.unlinkSync(configPath);
}
```

### applicability to progress reporter

- create similar acceptance test for progress reporter
- run jest in child process with progress reporter config
- verify overview.jsonl, failures.jsonl, summary.json outputs
- use temp config file pattern
- cleanup after tests

## pattern.2 = test fixtures in .test/assets directory

**source:** `src/domain.operations/slowtestReporter/.test/assets/slow-suite/slow.jest.test.ts`

**classification:** [REUSE]

**why:** the progress reporter needs test fixtures that exercise different scenarios (pass, fail, skip, etc.).

### citations

**[5]** fixture file structure (lines 1-7):
```ts
/**
 * .what = test fixture with slow tests
 * .why = used to verify slowtest reporter detects slow tests
 *
 * .note = uses jest describe/it with given/when/then prefixes
 *         because this runs in child process without @src/ aliases
 */
```

**[6]** simulated delay in test (lines 9-20):
```ts
describe('given: [case1] slow setup', () => {
  beforeAll(async () => {
    // simulate 500ms setup time
    await new Promise((r) => setTimeout(r, 500));
  });

  describe('when: [t0] slow test', () => {
    it('then: takes time', async () => {
      // simulate 200ms test time
      await new Promise((r) => setTimeout(r, 200));
      expect(true).toBe(true);
    });
  });
```

### applicability to progress reporter

- create `.test/assets/` fixtures for:
  - suite with all pass
  - suite with failures
  - suite with skipped tests
  - suite with console output (log, warn, error)
  - suite with large console output (to test truncation)
- fixtures run in child process, so use plain jest describe/it

## pattern.3 = unit tests with given/when/then

**source:** `src/domain.operations/slowtestReporter/hierarchy/buildBlockHierarchy.jest.test.ts`

**classification:** [REUSE]

**why:** the progress reporter unit tests should follow the same BDD style.

### citations

**[7]** import given/when/then from contract (line 1):
```ts
import { given, then, when } from '@src/contract';
```

**[8]** unit test structure (lines 9-20):
```ts
describe('parseBlockTitle', () => {
  given('[case1] title with given: prefix', () => {
    when('[t0] parse is called', () => {
      then('returns type=given and name without prefix', () => {
        const result = parseBlockTitle({
          title: 'given: [case1] some scenario',
        });
        expect(result.type).toEqual('given');
        expect(result.name).toEqual('[case1] some scenario');
      });
    });
  });
```

**[9]** test with data setup (lines 54-66):
```ts
given('[case1] flat tests with given/when/then structure', () => {
  const flatTests: FlatTestResult[] = [
    {
      ancestorTitles: ['given: [case1] scenario', 'when: [t0] action'],
      title: 'then: expected outcome',
      duration: 100,
    },
    {
      ancestorTitles: ['given: [case1] scenario', 'when: [t0] action'],
      title: 'then: another outcome',
      duration: 50,
    },
  ];
```

### applicability to progress reporter

- unit test transformers (e.g., asProgressOverviewLine, asProgressFailureLine)
- use given/when/then from @src/contract
- follow [caseN] and [tN] label convention

## pattern.4 = useThen for shared test results

**source:** `src/domain.operations/slowtestReporter/slowtestReporter.acceptance.jest.test.ts`

**classification:** [REUSE]

**why:** avoids repeated expensive operations across then blocks.

### citations

**[10]** useThen import (line 6):
```ts
import { useThen } from '@src/domain.operations/useThen';
```

**[11]** useThen call pattern (lines 87-94):
```ts
when('[t0] jest runs with slowtest reporter', () => {
  const result = useThen('reporter executes successfully', () =>
    runJestWithReporter({
      testMatch: '**/slow-suite/*.jest.test.ts',
      outputPath,
      slow: 100,
    }),
  );
```

**[12]** use result in multiple then blocks (lines 96-118):
```ts
then('terminal output contains slowtest report header', () => {
  expect(result.stdout).toContain('slowtest report');
});

then('terminal output shows file path', () => {
  expect(result.stdout).toContain('slow.jest.test.ts');
});

then('json file is written to output path', () => {
  expect(fs.existsSync(outputPath)).toBe(true);
});
```

### applicability to progress reporter

- use useThen for expensive runJestWithReporter calls
- single execution, multiple assertions
- avoids redundant child process spawns

## pattern.5 = cleanup in beforeAll/afterAll

**source:** `src/domain.operations/slowtestReporter/slowtestReporter.acceptance.jest.test.ts`

**classification:** [REUSE]

**why:** acceptance tests that write files need cleanup.

### citations

**[13]** cleanup pattern (lines 80-85):
```ts
beforeAll(() => {
  if (fs.existsSync(outputPath)) fs.unlinkSync(outputPath);
});
afterAll(() => {
  if (fs.existsSync(outputPath)) fs.unlinkSync(outputPath);
});
```

### applicability to progress reporter

- cleanup progress directory before/after tests
- use fs.rmSync with recursive: true for directory cleanup
- ensure test isolation
